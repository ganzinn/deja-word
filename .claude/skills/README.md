# スキル記述規約

repo 管理のスキル（このディレクトリ直下に実体があるもの）の SKILL.md と補助ファイル（`templates/` / `references/`）に適用する書き方の規約。symlink で取り込んでいる外部スキルと、実験成果物のディレクトリ（design-session の `evals/` 等。SKILL.md からエージェントが読む導線に無いもの）には適用しない。

目的はスキルの肥大化防止。スキルはセッションごとの知見追記で成長し続けやすく、読むエージェントのコンテキストを毎回消費するため、本文は「現行手順の実行に必要な記述」だけに保つ。

## 記述規約

1. **肯定形の現行手順のみ書く**。やめた方式・過去の失敗・「採用しなかった理由」は書かない。経緯は issue / PR / ADR に置く（本文からは必要なら参照リンク 1 つ）。現行手順内の禁止事項（「〜しない」）は、読み手が自然に踏みやすい誤操作の防止に限り書いてよい。その場合も理由の説明は最小限にし、代わりの正しい手順とセットで書く。
2. **実体は一次置き場、スキルは参照**。設定・スクリプト・雛形は repo 管理ファイル（`.claude/settings.json` / `scripts/` / スキルの `templates/`）に置き、スキル本文には場所と役割の参照だけを書く。スニペットの複製転記をしない。
3. **証跡を書かない**。検証で確定した仕様は断定形で書く。日付・実測メモ・出典 URL の羅列を本文に残さない（証跡は PR / issue に残る）。
4. **追記より置き換え**。セッション知見を反映するときは、まず既存記述の置き換え・削除を検討する（append-only にしない）。
5. **外部ツール仕様の転記は操作に必須な最小限**。返却形式・制限値などはスキルの手順の実行に必要な分だけ書き、汎用知識は当該ツール側のスキル・ドキュメントに寄せる。
6. **構造で分離**。SKILL.md は主フローのエントリポイント。詳細手順・トラブルシュートが嵩む場合は `templates/` / `references/` の補助ファイルへ切り出し、本文からリンクする。

## 運用

- スキルを変更する PR のセルフレビューに「この変更で削れる既存記述はないか」を含める。
