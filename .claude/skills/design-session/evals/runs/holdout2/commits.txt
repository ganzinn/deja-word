+# 01. 要求・ユースケース
+
+状態: **確定**（2026-07-08）
+
+## 前提（確定事項の再掲）
+
+このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。
+
+- 機能名は word-goal（UI 日本語は「学習目標」）。継続を後押しする補助機能で、単語データそのものには手を入れない。
+- アプリのコンセプトは「一度忘れた単語との再会」による定着支援。学習目標はその継続を後押しする補助機能。
+- 解答履歴は `QuizAnswer`（1 解答 = 1 行）に永続化され、通常テスト・定着モードとも同テーブルに `mode`（TEST / DRILL / DRILL_RETRY）で区別して入る。フィールドは `ownerId` / `wordId` / `mode` / `format` / `result` / `createdAt`（`@default(now())` = UTC 保存）。→ word-quiz 設計。
+- アプリ内に「今日」「今週」等の日付境界・タイムゾーンを扱う既存コードは無い（学習目標で新規に設計する）。
+
+## 検討事項リスト
+
+- [x] 学習目標で解決したいユーザーの課題は何か（コンセプト「再会」との関係）
+- [x] 目標は何を単位に、いくつ持てるか
+- [x] 「復習した」を何でカウントするか（対象 mode・正誤・ユニークの粒度）
+- [x] 「週」をどう定義するか（週の開始曜日・タイムゾーン・達成の保持有無）
+- [x] 目標値の範囲・未設定時の扱い・設定/変更/解除のユースケース
+- [x] 進捗をどこで・どう見せるか（達成時の扱い）
+- [x] 認可・プライバシー（誰の進捗・目標が見えるか）
+- [x] スコープ外とするもの
+
+## 議論・決定
+
+### 決定 1: 核となる体験 — 週次の復習量目標で継続を後押しする
+
+「1 週間にこれだけ復習する」という量の目標をユーザー自身が決め、今週どこまで進んだかをアプリ内で確認できるようにする。目標はあくまで自己設定の努力目標で、アプリが強制・催促するものではない。
+
+- **却下案（アプリ主導の復習ノルマ / SRS 連動）**: アプリが「今日復習すべき単語数」を算出して提示する方式。word-quiz が「任意起動の腕試し」で SRS をスコープ外にしているため、目標側だけ SRS 前提にはできない。ユーザーの意図も「自分で決めた量をこなす継続支援」であり、任意起動の学習量を可視化するだけで足りる。
+
+### 決定 2: 目標はユーザーごとに 1 つ・種類は週あたりの復習単語数のみ
+
+- ユーザーは学習目標を**ちょうど 1 つ**持てる（未設定 or 1 つ設定済みの二状態）。複数目標を並行して持つ機能は持たない。
+- 目標の種類は「**週あたりに復習する単語数**」のみ。1 日あたり・1 か月あたり等の期間違い、正答数・学習時間などの語数以外の指標はスコープ外。
+
+- **却下案（複数目標・期間の使い分け）**: 「週 50 語」「日 10 語」を同時に持つ等。MVP の目的（継続の後押し）には単一の週次目標で足り、UI・集計・データモデルが複雑化するため見送る。
+
+### 決定 3: 「復習した」= 週内に解答した単語のユニーク数（全 mode・正誤問わず）
+
+進捗の分子（達成数）は、**その週に解答された `QuizAnswer` 行の `wordId` を distinct した件数**とする。
+
+- **対象 mode は全て**（TEST / DRILL / DRILL_RETRY）。通常テストでもドリルでも「その単語に取り組んだ」ことに変わりはないため区別しない。
+- **正誤（`result`）は問わない**。CORRECT / INCORRECT / GAVE_UP / TIMEOUT のいずれでもカウントする。目的が「定着度」ではなく「継続的に単語に触れた量」の可視化であるため、取り組んだ事実をカウントする。
+- **ユニークの粒度は「週内で」distinct**。同じ単語を同じ週に何回解いても 1 とカウントする（延べ解答数ではない ―「単語数」という語義に合わせ、1 単語連打での水増しを防ぐ）。週が変われば同じ単語が翌週に再びカウントされうる（毎週の復習量を測る主旨に合う）。
+
+- **却下案（正解のみカウント / DRILL 系のみカウント / 延べ解答数）**: 正解のみは「定着度目標」に寄りコンセプトが変わる。DRILL 系のみは通常テストでの復習を取りこぼす。延べ解答数は「単語数」の語義と乖離し水増し可能。いずれも決定 1 の「量の継続」という主旨から外れるため却下。
+
+### 決定 4: 「週」は JST 固定・月曜始まり・進捗は都度算出（履歴を持たない）
+
+- **タイムゾーンは JST（Asia/Tokyo）固定**。日本語話者向けのアプリで、ユーザーの生活時間に合う。ブラウザのタイムゾーンやサーバーの UTC には依存しない。
+- **週は月曜 00:00 JST 始まり**（月曜 00:00:00 から翌月曜 00:00:00 の直前まで）。学習習慣として「今週の計画」は月曜起点が自然。
+- **進捗は永続化せず、都度 `QuizAnswer.createdAt` から算出する**。達成数を別カウンタや達成履歴テーブルに持たない。`createdAt` は UTC 保存なので、集計時に「今週」の JST 範囲を UTC の開始/終了時刻に変換して範囲クエリする（成立性: 週境界は現在時刻から一意に導出でき、`createdAt` から distinct 集計できる。別カウンタを持たないため二重定義・食い違いも生じない）。
+- 週をまたぐと進捗は自動的に新しい週の集計に切り替わる（前週の達成有無・達成回数は残さない）。「今週」以外の週の進捗は表示しない。
+
+- **却下案（日曜始まり / UTC 基準 / ローリング直近 7 日 / 達成カウンタを別途永続化）**: 日曜始まりはロケール差、UTC 基準は日本時間と最大 9 時間ずれて「今日解いたのに来週分に入る」等の直感外れを生む。ローリング 7 日は境界がユーザーごとにばらけ「今週」という共通感覚と合わず実装も複雑。達成カウンタの別途永続化は `QuizAnswer` から導出可能な値の二重管理となり、解答削除時の整合など複雑さを持ち込むため MVP では持たない（将来、達成履歴の蓄積を入れる段で再検討）。
+
+### 決定 5: 目標の設定・変更・解除（1 つの上書き）と目標値の範囲
+
+ユースケースは以下の 4 つ:
+
+- **UC1 目標を設定する**: 未設定のユーザーが週あたりの復習単語数を入力して保存する。
+- **UC2 目標を変更する**: 設定済みの値を上書きする（目標は 1 つなので新規と変更は同じ「上書き保存」）。変更は即時反映され、今週の進捗の分母（目標数）がすぐ切り替わる（分子＝達成数は集計値なので変わらない）。
+- **UC3 目標を解除する**: 設定を消して未設定状態に戻す。以後、進捗表示は出さない。
+- **UC4 今週の進捗を確認する**: ログイン後トップで今週の達成数/目標数を見る。
+
+目標値の制約:
+
+- **正の整数のみ**。単位は「語/週」。
+- **範囲は 1〜999**（固定）。上限は「現実的な週次の復習量」に十分な固定値とし、登録単語総数には連動させない（連動させると登録の増減で有効範囲が動き、実装も複雑になるため）。
+- **デフォルトは未設定**（オプトイン）。未設定のユーザーには進捗を表示せず、設定への導線のみ出す（決定 6）。
+
+- **却下案（上限を登録単語数に動的連動）**: 「登録より多い目標は無意味」に見えるが、同じ単語を複数週にわたり復習する使い方では登録数超えの週次目標も成立しうる。動的上限は登録の増減で有効値が揺れ、バリデーションが複雑化するため固定範囲を採る。
+
+### 決定 6: 進捗表示はログイン後トップ `/menu`・達成後は満了表示のみ
+
+- **表示場所はログイン後トップ `/menu`**（現状アプリで唯一の post-login landing）。目標未設定時は「学習目標を設定する」導線を、設定済み時は「今週の進捗」を表示する。ダッシュボードの新設や単語テスト画面への埋め込みはしない。
+- **表示内容は「今週 X / Y 語」＋達成率の視覚表示（バー等）**。X = 今週の復習ユニーク単語数（決定 3）、Y = 目標値（決定 5）。
+- **達成時（X ≥ Y）は進捗表示が満了になるだけ**。通知・お祝い演出・バッジ等は行わない。達成後も今週の集計は継続し、満了状態を保つ（超過分の見せ方など細部は 04 で詰める）。
+
+- **却下案（専用 `/dashboard` 新設 / 単語テスト開始画面に埋め込み）**: `/menu` が既存の唯一のログイン後トップで、そこに置くのが最も自然に「アプリ内で確認できる」を満たす。専用ダッシュボードは MVP には過剰、テスト画面埋め込みはテストを起動しないと目標が見えず「継続の後押し」に弱い。具体的なカードのレイアウト・導線は [04-ui.md](04-ui.md) で詰める（本トピックでは置き場所と達成時の扱いのみ確定）。
+
+### 決定 7: 認可・プライバシー — 目標も進捗もユーザー本人専有
+
+- 学習目標も今週の進捗も、**設定・閲覧できるのは本人のみ**。他ユーザーの目標・進捗は一切見えない（他ユーザーとの比較はスコープ外）。
+- 進捗集計は本人の解答のみを対象とする（`scopedOwnerIds` 準拠。`QuizAnswer.ownerId` は解答者本人しか作らないため実質本人行のみだが、読み取り規約に沿う）。目標設定は本人行のみを upsert する。物理的な保存先・認可の実装規約は [05-architecture.md](05-architecture.md) で確定する。
+
+### スコープ外（MVP でやらないこと）
+
+- 達成履歴の蓄積・過去週の進捗表示（今週のみ表示）
+- 進捗のグラフ・可視化（達成率バー以外の統計表示）
+- 他ユーザーとの比較・ランキング・共有
+- 目標達成時の通知・お祝い演出・バッジ・リマインド
+- 複数目標・期間違いの目標（日次・月次）・語数以外の指標（正答数・学習時間など）
+- 目標値の上限を登録単語数に連動させる動的制御

+# word-goal 設計ドキュメント（ハブ）
+
+1 週間あたりに復習する単語数の目標を設定し、今週の進捗（達成数/目標数）をアプリ内で確認できる「学習目標」機能の設計ドキュメント群の入口。
+**word-goal（学習目標）の設計に関わるセッションは、必ずこのファイルから読み始めること。**
+
+## 目的・スコープ
+
+ユーザーが「1 週間にこれだけ復習する」という量の目標を持ち、今週どこまで達成したかを一目で確認できるようにする。
+アプリのコンセプト「一度忘れた単語との再会」による定着支援の**継続を後押しする補助機能**。単語データそのものには手を入れず、既存の解答履歴（`QuizAnswer`）を集計して進捗を出す。
+
+スコープの詳細（何をやる / やらない）は [01-requirements.md](01-requirements.md) で定義する。
+
+## 確定事項サマリ
+
+結論のみを記載する。採用理由・却下した代替案は各トピックファイルを参照。
+
+- **機能名は word-goal（UI 日本語は「学習目標」）**。継続を後押しする補助機能で、単語データには手を入れない。→ [01](01-requirements.md)
+- **目標はユーザーごとに 1 つ**。種類は「週あたりの復習単語数」のみ（複数目標・期間の使い分け・語数以外の目標種類はスコープ外）。→ [01](01-requirements.md)
+- **「復習した」= 週内に解答した単語のユニーク数**。`QuizAnswer` 全 mode（TEST / DRILL / DRILL_RETRY）・正誤問わず、週内 distinct `wordId` を数える。同じ単語を週内で何回解いても 1。→ [01](01-requirements.md)
+- **「週」は JST（Asia/Tokyo）固定・月曜 00:00 始まり**。進捗は保存せず `QuizAnswer.createdAt` から都度算出する（達成履歴・カウンタは持たない）。週が変わると自動的に新しい週の集計に切り替わる。→ [01](01-requirements.md)
+- **目標値は正の整数（1〜999 語/週）**。デフォルトなし。未設定なら進捗を表示せず設定導線を出す（オプトイン）。設定画面で変更・解除できる。→ [01](01-requirements.md)
+- **進捗表示はログイン後トップ `/menu`**。「今週 X / Y 語」＋達成率バー。達成後は満了表示のみで通知・お祝い演出はしない。→ [01](01-requirements.md)
+- **進捗・目標はユーザー本人専有**。進捗集計は `scopedOwnerIds`、目標設定は本人行のみ upsert（他ユーザーの目標・進捗は見えない）。→ [01](01-requirements.md)
