+### 決定 1: トグル操作は星アイコンで、各単語行と単語詳細画面から行う
+
+単語一覧の各行（`WordRow`。単語単位ビュー・掲載箇所ビュー共通）と単語詳細画面のアクション領域に星アイコンを置き、クリックで付け外しする。
+
+- 星の状態表示: 塗りつぶし = ブックマーク済み / 輪郭のみ = 未。アイコンは lucide の `Star`（既存の他アイコンと同じ `lucide-react`）。
+- 行内の星ボタンは行の `<Link>` ナビゲーションを発火させない。既存の行内発音ボタン `RowAudioButton`（行の Link 内に置かれるがクリックで遷移しないボタン）と同じ扱いに揃える。
+
+採用理由: 一覧・詳細のどちらからでも 1 タップで付け外しでき、既存の行内ボタン（発音）と操作感が揃う。
+
+却下した代替案:
+- 詳細画面のみにトグルを置く。一覧から直接付け外せず反復操作が面倒なため却下。
+- メニュー（`…`）内に隠す。1 タップで済まず発見性が低いため却下。
+
+### 決定 2: ブックマーク絞り込みは単語単位ビューのツールバーに URL クエリで持たせる
+
+`/words` の単語単位ビューのツールバー（`word-list-toolbar`）に「ブックマークのみ表示」のトグルを追加し、状態を URL クエリ（例: `bookmarked`）で保持する。既存フィルタ（`q` / `sort` / `match` / `view`）と同じ「client が `router.replace` で URL を書き換え → server component が `searchParams` を再読込」方式に揃える。
+
+- 掲載箇所ビューにはこの絞り込みを出さない（掲載箇所ビューは特定掲載箇所の連続閲覧が目的で、ブックマーク横断の絞り込みとは目的が異なるため）。ただし星トグル自体は掲載箇所ビューの行にも表示する（付け外しはどの行からでも可能）。
+
+採用理由: 既存のフィルタ機構をそのまま踏襲でき、URL 共有・ブラウザの戻る操作とも整合する。
+
+却下した代替案:
+- 専用ページ（01 決定 2 で覆済）。
+- client state のみで保持。URL 共有ができずリロードで状態が消え、既存フィルタと不整合なため却下。
+
+### 決定 3: フィルタ適用時の表示項目は通常の単語一覧と同一とする
+
+「ブックマークのみ表示」にした場合も、行の表示項目・レイアウトは通常の単語一覧と同じにする。ブックマーク専用の表示・追加情報（付与日時など）は設けない。
+
+- 星は全ての行に表示されるため、フィルタ適用中でもその場で外せる。外した後に一覧へ反映する（再取得）の扱いは 04 で扱う。
+
+採用理由: 表示を一本化して実装・認知コストを抑える。専用表示の需要が出たら別途検討する。
+
+却下した代替案: ブックマーク用の簡略/拡張表示。MVP には過剰なため却下。
+
