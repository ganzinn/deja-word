# implement-agent-prompt（サブエージェント委譲プロンプト雛形）

プレースホルダ: `{機能名}` `{NN}` `{チケット名}` `{worktree絶対パス}`

---

あなたは {機能名} のチケット {NN}（{チケット名}）の実装担当です。作業場所は `{worktree絶対パス}`（git worktree）。**この外のファイルは読み書きしないこと**。

## 必読（この 2 ファイルで実装が自己完結する）

1. `{worktree絶対パス}/docs/plan/{機能名}/README.md`（plan ハブ。共通規約・共有物・競合点）
2. `{worktree絶対パス}/docs/plan/{機能名}/{NN}-{チケット名}.md`（対象チケット）

設計ドキュメント（docs/design/）は、チケットの再掲の出典参照を深掘りする必要がある場合のみ読む。

## 守ること

- チケットの「実装内容」に従い、スコープ外に手を出さない。plan ハブの「チケット横断の共通事項」（共有物・競合点、共通規約）を守る
- テストは AGENTS.md の規約に従う（`*.unit.test.ts` / `*.integration.test.ts`、SUT の隣にコロケート）
- `docs/plan/` 配下は**編集しない**（ステータス・実装メモはオーケストレーターが更新する）
- **コミット前に必ず整形する**: `pnpm format` で整形 → `pnpm format:check` がクリーン → `pnpm lint` / `pnpm typecheck` / `pnpm test:unit` を通すこと（この順）。整形差分は実装コミットに含める（別コミットにしない）。**`pnpm test:integration` は実行しない**（共有 DB を使うためオーケストレーター側で直列実行される。integration テストファイルの新規作成・変更自体はチケットに従い行う）
  - 任意: devman が導入済みの環境では、これらのコマンドを `devman run <worktreeディレクトリ名> <タスク>` 経由で実行してもよい（cd 不要で worktree を名前指定でき、mise 経由のツールチェーンが保証される）
- worktree 内でコミットすること。メッセージは `{機能名}: {NN} {チケット名}`（複数コミット可。後で squash される）
- 設計・計画と実装が矛盾する、またはチケットに書かれていない判断が必要になったら、**勝手に補完せず**矛盾・不明点を報告して終了すること

## 報告フォーマット（最終メッセージ。これがオーケストレーターへの返却値になる）

- 変更ファイル一覧（**integration テストファイルの有無を明記** — マージ後検証の判定材料になる）
- 実行した検証コマンドと結果（整形 `pnpm format` / `pnpm format:check` を含む）
- チケットの完了条件（DoD）のチェック結果（手動確認項目は「未実施」と明記）
- 計画との差分・後続チケットへの申し送り（「実装メモ」転記用。なければ「なし」）
- 未解決事項（あれば）
