# ADR-0008: スキーマ進化は side table 加算（テーブル分離・enum scope・RLS を却下）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

共有マスタとユーザーデータが同居する Word 系テーブルに対し、将来の要求（検索強化、quiz、進捗管理、共有行の非表示、お気に入り等）へどう備えるかの長期方針が必要だった。当初は「テーブル分離」が将来方向とされていたが、明示的に書き換えられた。

## 決定内容

**既存テーブルは変更せず、side table（横付けの子テーブル）の加算で拡張する。** 将来要求は core テーブルに触れずに side table 追加で満たす。

## 採らなかった代替案

`docs/refactor/word-registration.md` に却下案が表形式で記録されている:

- **テーブル分離（system 用とユーザー用を分ける）**: 検索が UNION を強いられ、コピー行の陳腐化問題も生じ、総コストが現状維持を上回るため却下
- **enum の scope カラム追加**: 却下（同表参照）
- **Postgres RLS（行レベルセキュリティ）**: 却下（同表参照）
- **headword のグローバル一意化**: 却下（同表参照）

## 影響

- quiz 機能は QuizAnswer / Drill / DrillWord の side table 加算のみで実装され、既存テーブル無変更が守られた（`docs/design/word-quiz/README.md` が本方針の踏襲を明記）
- ノート複数行化も `*Note` 子テーブル加算で対応（[ADR-0012](0012-note-child-tables.md)）
- 本方針は `prisma/CLAUDE.md` に恒久規約として記載されている
