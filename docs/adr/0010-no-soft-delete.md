# ADR-0010: ソフトデリート不採用（物理削除のみ）

- ステータス: 提案
- 確信度: 低
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

削除操作（単語・掲載箇所・drill・ユーザー）の実装方式として、論理削除（deletedAt / isDeleted フラグ）と物理削除のどちらを採るかは横断的な設計判断になる。

## 決定内容

全テーブルで**物理削除のみ**を使う。schema に `deletedAt` / `isDeleted` に類するカラムは存在せず、削除は `onDelete: Cascade`（[ADR-0009](0009-cascade-default-setnull-exceptions.md)）と ops の purge / TRUNCATE に委ねる。

## 採らなかった代替案

- ソフトデリート — 採られていないが、**検討した記録自体が無い**。（推定）個人学習アプリで削除の取り消し・監査要求が無く、全クエリに `deletedAt IS NULL` を書く複雑さに見合わないため、と考えられる

## 影響

- 削除は復旧不能。誤削除の保険は DB バックアップのみ
- クエリに削除フラグの条件が不要で、`scopedOwnerIds` 等の where 注入がシンプルに保たれている
- 将来「削除の取り消し」要求が出た場合は side table 加算（[ADR-0008](0008-side-table-addition.md)）では対応しにくく、方針の再検討が必要

## 根拠（コード・コミット・文書参照）

- `prisma/schema.prisma` — 削除フラグ系カラムの不在（全モデル）
- `scripts/purge-occurrence.ts` / `scripts/reset-prod-db.ts` — 物理削除・TRUNCATE ベースの運用
- ※「不採用の決定」を記録した文書・コミットは見つかっていない（不在の証跡のみ）
