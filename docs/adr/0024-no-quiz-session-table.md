# ADR-0024: テストセッションテーブル非採用（QuizAnswer は append-only）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

「1 回のテスト実施」をエンティティとして持つか（セッションテーブル + 明細）、解答行だけを持つかの選択があった。

## 決定内容

- **テストセッション（1 回のテスト実施）テーブルは持たない**。過去テストの結果一覧を見る要求がないため
- 履歴は **QuizAnswer（1 解答 = 1 行、append-only）**のみ。単語（Word）に紐づけ、Meaning には紐づけない（出題・正誤の単位が単語のため）
- TEST / DRILL / DRILL_RETRY の区別は `mode` カラムで持つ

## 採らなかった代替案

- セッションテーブル + 解答明細の 2 テーブル構成 — 結果一覧要求が無い以上、テーブルと整合性管理が増えるだけとして不採用（02 の設計判断の記録から）

## 影響

- 「ラウンド」や「テスト実施」の単位で集計したい要求が将来出た場合、`createdAt` 近接などの推定に頼るか、side table 加算での対応になる
- TEST の再送信で同じ解答が二重に入り得ることは MVP の許容事項とされた（[ADR-0032](0032-history-submit-single-flight.md)）— idempotency key を置く場所（セッション）が無いことと表裏
- 用語として drill の 1 回分は「ラウンド」と呼び、「セッション」は認証 Session と衝突するため使わない（naming-book）

## 根拠（コード・コミット・文書参照）

- 「テストセッションテーブルは持たない」と理由（元 design ドキュメントは実装完了に伴い削除。本 ADR が一次情報）
- `prisma/schema.prisma` — QuizAnswer モデル（wordId / ownerId / mode / result）
- `docs/reference/naming-book.md` — ラウンド vs セッションの用語規約
