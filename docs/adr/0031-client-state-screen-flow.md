# ADR-0031: /quiz 内のクライアント状態遷移（画面ごとの URL を持たない）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

quiz の画面フロー（開始 → カウントダウン → 出題 → 結果）を URL ルーティングで分けるか、単一ルート内のクライアント状態で遷移させるかの選択があった。

## 決定内容

`/quiz` の**単一ルート内でクライアント状態により遷移**する（start → countdown → play → result）。画面ごとの URL は持たない。

## 採らなかった代替案

- **画面ごとのルート分割** — 却下（進行中の状態はサーバに無く URL 直叩きで再現できないため）

## 影響

- ブラウザバックで進行中テストが壊れる問題への対処が必要になり、離脱ガード + 「層数同期方式」のバックガードが実装された（commit `00960c2`、ログイン画面が back で再表示される問題の修正）
- 進行状態はすべてクライアントメモリ上にあり、リロード = 中断（破棄、[ADR-0023](0023-batch-submit-discard-on-abort.md)）となる

## 根拠（コード・コミット・文書参照）

- 画面フローの決定と却下案（元 design ドキュメントは実装完了に伴い削除。本 ADR が一次情報）
- `src/app/quiz/_components/quiz-flow.tsx` — 状態遷移の実装
- commit `00960c2`（PR #22）— バックガードの層数同期方式
