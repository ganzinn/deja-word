# ADR-0036: drill は残数モデル（積み上げ式カウントを却下）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

定着モード（drill）で「単語ごとにあと何回正解すれば定着か」をどうモデル化するか。誤答した単語ほど多く反復させたい。

## 決定内容

**残数（remaining）モデル**を採る:

- 元テストで誤答だった単語は残数 3、正解だった単語は残数 1 から開始（値は後に設定可能化）
- 正解で残数 −1、誤答で残数リセット（初期値に戻る）、うろ覚え（VAGUE）は専用の初期残数
- 残数 0 = 定着。全単語定着で drill 完了（`completedAt`）
- ラウンド制で、日をまたいで再開できる

## 採らなかった代替案

- **積み上げ式カウント（N 回正解で定着）** — 元テスト正解組の開始値の説明（1 回しか正解していないのに 2 から開始）が複雑になるため却下し、残数方式を採用（ユーザー提案。quiz-06 決定 1 に明記）

## 影響

- DrillWord（複合 PK `[drillId, wordId]`）が単語ごとの `remaining` を持ち、残数遷移は `next-remaining.ts` の純関数で定義される
- 残数の初期値は「定着までの回数」設定として後にユーザー設定可能になった（`resetRemaining` / `vagueRemaining` / `initialCorrectRemaining`、PR #79/#80）
- 「残数」は naming-book の確定用語であり、UI・コードで積み上げ式の語彙（累計正解数等）を使わない
