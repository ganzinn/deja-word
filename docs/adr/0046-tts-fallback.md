# ADR-0046: 発音音源未登録時は Web Speech API で TTS フォールバック（mp3 優先）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

発音音源（mp3）は手動アップロードでしか登録できず、入手が難しい。音源未登録の単語では発音を確認できなかった。

## 決定内容

- 音源未登録時は **Web Speech API（ブラウザ内蔵 TTS）で発音を合成**するフォールバックを設ける（理由「mp3 は手動アップロードでしか登録できず入手が難しいため」がコミットに明記）
- **登録済み mp3 が常に優先**。TTS はあくまで代替
- ユーザー設定 `UserPreference.ttsFallback`（null = 既定 ON）で無効化できる
- 合成失敗時は 1 回だけトーストで通知する（サイレント故障が「壊れている」ように見えるのを防ぐ。quiz 自動再生時は通知しない）
- **Android Chrome で無音になる問題への対処は、一度修正を入れたが実機で解消せず revert し、「原因（端末側の TTS / 英語ボイス有無等）を特定してから改めて対応する」として保留**（推測ベースの修正を重ねない判断が記録されている）

## 採らなかった代替案

- サーバ側 TTS（外部 TTS API での mp3 自動生成）—（推定）外部 SaaS 依存（[ADR-0043](0043-blob-di-driver-switching.md) の方針と衝突）とコストを避けたと考えられる。比較の記録は無い

## 影響

- 発音再生の入口は「mp3 → TTS」の 2 段構えが前提になり、再生 UI はソースの区別を持つ
- Android の無音問題は未解決の既知課題として残っている（revert コミットが記録）
