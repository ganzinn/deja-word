# ADR-0048: 本番セルフサインアップ無効 + 管理者招待（リセット機構転用、メール送信なし）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

本番は身内向け運用であり、不特定多数のサインアップを受け付けない。一方でメール送信基盤が無いため、一般的な「招待メール送信」フローは使えないという制約があった。

## 決定内容

- **本番のセルフサインアップを `DISABLE_SIGNUP="true"` で無効化**する。判定ロジックは `signup-policy.ts` に集約
- ユーザー追加は**管理者招待フロー**で行う:
  1. 管理者（= system ユーザー、[ADR-0007](0007-system-user-as-admin.md)）がメールアドレスだけでユーザー登録
  2. Better Auth の**パスワードリセット機構を転用**して set-password リンクを発行（トークンは `AsyncLocalStorage` で捕捉）
  3. **メールは送らず、URL を管理画面に表示**して管理者が本人へ手渡す
  4. 本人がパスワードを設定する（**パスワードは管理者が設定しない** — 本人だけが知る状態を保つ、と理由明記）
- set-password 完了時に `emailVerified` を立てる。パスワード未設定ユーザーはメール変更不可（レビュー指摘対応、commit `ffb2a68`）

## 採らなかった代替案

- 管理者による初期パスワード設定 — 「パスワードは管理者が設定せず、本人だけが知る」として却下（ops 文書に明記）
- メール送信基盤の導入 — 現時点では導入せず、リンク手渡しで代替（基盤が無いことは制約として明記。導入自体の可否判断の記録は無い）

## 影響

- 招待・パスワード設定・メール変更のすべてが「メール基盤なし」を前提に組まれている。基盤を導入する場合はこの一連のフローの見直しになる
- Better Auth の標準機構に乗ったため、独自のトークンテーブルは持たない
