# ADR-0049: メール変更はステージング型 JWT。検証リンクのリスク許容 + requireEmailVerification 有効化禁止

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

管理者がユーザーのメールアドレスを変更したい。しかしメール送信基盤が無く（[ADR-0048](0048-admin-invite-without-email.md)）、誤ったアドレスへ即時変更すると本人がログイン不能になる。

## 決定内容

- **ステージング型**を採る: 管理者の変更操作では DB を書き換えず、ステートレスな change-email **JWT** を発行して検証リンクを管理画面に表示。**本人（新アドレスの受信者）がリンクを踏んだ時点で初めてメールアドレスが切り替わる**。DB に保留行を持たないため migration 不要
- **既知の制限を明示的に許容**: 検証リンクはログイン不要で確定でき、踏むと自動ログインされる。つまりリンク保持者は本人でなくても変更 + ログインできてしまう。「ログイン中セッションでのみ変更可」への厳格化は**後日の課題として明示的に先送り**
- **Better Auth の `requireEmailVerification` は有効化しない**こと。既存ユーザーは全員 `emailVerified=false` のため、有効化すると一斉にログイン不能になる（運用上の禁止事項として明記）

## 採らなかった代替案

- 管理者による即時変更 — 誤アドレスで本人がログイン不能になるため、受信確認後の切替（ステージング型）を採用（コミットに理由明記）
- DB に保留中アドレスの行を持つ方式 — ステートレス JWT なら migration 不要のため採らず（コミットに記載）

## 影響

- 「許容したリスク」と「禁止事項（requireEmailVerification）」が明文化されており、セキュリティ強化の際はこの ADR / ops 文書を起点に再検討する
- メール変更リンクも招待リンクと同じ「管理者による手渡し」運用
