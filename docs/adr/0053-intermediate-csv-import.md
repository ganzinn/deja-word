# ADR-0053: 複雑な元データはレビュー可能な中間 CSV へ分解してから取り込む

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-07-04

> **注意**: 本 ADR はコード・コミット履歴からの事後的な推定であり、当時の意思決定の記録ではない。
> 当時を知るメンバーのレビューを経てステータスを更新すること。

## 背景

ターゲット1900 の元データには関連語（≒/⇔）の埋め込み記法が含まれ、取り込みツールが直接パースすると、パース誤りの検出が取り込み後の DB 確認まで遅れる。

## 決定内容

- **取り込みツールは埋め込み記法を解釈しない**。`import-words` は meaning_text をそのまま登録する
- 複雑な元データは**使い捨ての分解ジェネレータでレビュー可能な中間 CSV（words.csv / related.csv）へ分解**し、人間がレビューしてから**単純な取り込みツールで投入**する（split → import-words → import-related-words の 3 段パイプライン）
- 割り切りも明文化されている: 関連語インポートは**マージ・重複排除をしない**（再実行すると同じ関連語をもう一度作る）。単語ループは **1 件ずつコミットで非原子的**（途中失敗時の復旧手順を文書化）

## 採らなかった代替案

- **取り込み時のインラインパース** — パース結果を投入前にレビューできないため不採用（naming-book / ops 文書に方針として明記）
- 冪等な upsert 型インポート —（推定）dry-run + 実行前レビューで重複投入を防ぐ運用で足りるため、ツールを単純に保つ側に倒したと考えられる（「しない」ことは文書に明記、理由の記述は簡素）

## 影響

- 新しい教材データの取り込みも「分解ジェネレータ + 中間 CSV + 単純ツール」の形を踏襲する
- 関連語インポートの再実行は重複を作るため、実行管理（dry-run 確認 → 1 回だけ --execute）が運用上の前提になる
