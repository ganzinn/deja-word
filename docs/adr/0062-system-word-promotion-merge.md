## 背景

system ユーザー（管理者）が単語を新規作成するとき、一般ユーザーが既に同じ見出し語の私有単語を持っているケースがある。system 単語を素朴に併存させると、共有マスタと私有単語が一覧に二重表示され、各ユーザーの意味・メモ・掲載が私有側に取り残される。

## 決定内容

system principal での単語作成（`createWordAsSystem`）は次を行う:

- 同一 headword の system 単語が既にあれば `DuplicateHeadwordError`
- 同一 headword の**非 system 単語**が存在する場合、`createdAt` 昇順で最古の 1 件を残し、他を `mergeWordInto` で統合（子エンティティごと付け替え）
- 最後に残した単語の `ownerId` を `SYSTEM_USER_ID` へ更新（**所有権の system への移譲**）し、その上にフォーム入力の子行を書き込む

つまりユーザーの私有単語は、同名の system 単語が作られた時点で**暗黙に共有マスタへ昇格・統合**される。ユーザーへの通知は行わない。この挙動には確立した呼び名が無い（本 ADR では「昇格マージ」と仮称。naming-book 未収録）。

## 採らなかった代替案

- **重複エラーにして手動統合させる**（推定） — 管理者のバルク登録（1900 語規模）が既存私有単語のたびに止まる
- **system 単語を併存させる**（推定） — 一覧・検索・出題で同 headword が二重に現れ、`ownerId_headword` のユニーク制約とスコープ設計の前提が崩れる

## 影響

- ユーザーは自分の単語が「いつの間にか system 所有になる」体験をする（自分の子行は pass-through 編集で維持される）
- 統合は最古優先のため、複数ユーザーが同名単語を持つ場合はどのユーザーの単語 id が生き残るかがデータ依存で決まる
- 用語が未定義のため「merge / 昇格 / 統合」と呼び方が揺れる。naming-book への「昇格マージ」エントリ追加を推奨
