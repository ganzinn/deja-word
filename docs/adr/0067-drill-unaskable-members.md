# ADR-0067: 投入後に出題不能化した DrillWord メンバーの扱い

- ステータス: 提案
- 確信度: 低
- 起票日: 2026-07-11

> **注意**: 本 ADR は issue #106 手順 3 の**設計判断の起票**であり、実装済みの決定の事後推定ではない。
> 候補の比較のみ記載し、決定はしていない。レビューを経て決定し、ステータスを更新すること。

## 背景

drill の完了判定は「全 DrillWord 行の `remaining === 0`」（`src/lib/quiz/handlers/drill-round-handler.ts` の `remaining.every(w => w.remaining === 0)`）。一方ラウンド生成の出題対象は取得クエリの適格述語（対象 Occurrence への番号付きリンク ∧ 形式適格）を満たすメンバーに限られるため、投入後の通常編集でメンバーが出題不能になると `remaining > 0` のまま二度と出題されず、**drill が恒久に完了不能**になる（issue #106）。

issue #106 手順 1〜2（本ブランチ、マージ済み緩和策）で経路の大半は塞いだ:

- 手順 1（`src/lib/drill-create.ts`）: 作成時に番号付きリンクの無い単語を DrillWord に投入しない（混入防止）
- 手順 2（`src/lib/quiz/queries/quiz-source.ts` の `ensureTargetWordIds`）: 番号が範囲外へ移動したメンバーも範囲と独立に出題する（範囲外化の救済）

それでも残る出題不能化の経路は**投入後の通常編集**によるもの:

- **意味の全削除**: 可視 MeaningText が 0 件になると非 TG 形式の形式適格（`eligibleWord`）を満たさない（TG 例文形式では「使える TG 例文」の全削除が同型）
- **番号付きリンクの喪失**: WordOccurrence のリンク解除、または occurrenceNumber の null 化

単語自体の削除は `onDelete: Cascade` で DrillWord ごと消えるため問題にならない。現状、上記の経路で完了不能化した drill からユーザーが脱出する手段は **drill の削除のみ**。

## 決定内容（候補）

未決定。候補は次の 3 案:

### (a) 完了判定から出題不能メンバーを除外する

完了判定（`remaining.every(...)`）の分母を「出題可能なメンバー」に絞る。出題不能行は残るが完了を妨げない。

- 利点: データを変更せず、編集を戻せば（意味の再登録・番号の再付与）そのメンバーは自然に drill へ復帰する
- 欠点: 完了判定のたびに適格判定クエリが要る。「完了したのに remaining > 0 の行が残る」状態の説明が要る（進捗表示・再テスト対象との整合）

### (b) ラウンド生成時に出題不能 DrillWord 行を自動削除する

ラウンド生成で適格を失ったメンバーの DrillWord 行を物理削除し、不変条件「DrillWord のメンバー = 出題可能」をデータ側で回復する。

- 利点: 完了判定・進捗表示は現行ロジックのまま正しくなる
- 欠点: 編集を戻してもメンバーは復帰しない（学習対象が黙って消える）。読み取り経路であるラウンド生成が書き込みを持つ

### (c) UI 通知のみ（データ不変）

完了判定・DrillWord は変更せず、出題不能メンバーがいる drill に「出題できない単語が N 件あります（意味未登録・掲載番号なし）」等の表示を出し、対処（編集で戻す / drill を削除する）をユーザーに委ねる。

- 利点: データ・判定ロジック不変で最も安全。原因（どの単語がなぜ）をユーザーに可視化できる
- 欠点: 完了不能状態そのものは解消しない（脱出手段は依然 drill 削除のみ）

## 影響

- (a)(b) は完了判定・ラウンド生成の意味論が変わるため、`drill-round-handler.ts` の CAS 送信（ADR-0033）・進捗表示・再テスト（ADR-0041）との整合確認が必要
- (c) は drill 一覧・ラウンド画面への表示追加のみだが、issue #106 の完了条件「投入後に意味削除しても完了可能」は満たさない
- いずれの案でも、手順 1〜2 により対象は「投入後に意味を全削除 / リンクを失った」稀なケースに限定される
