# ADR-0074: 出題数の指定（範囲からのランダム抽選）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-02

## 背景

quiz の出題対象は指定範囲（掲載箇所＋掲載番号範囲、またはブックマーク全件。[ADR-0022](0022-quiz-source-occurrence-range.md) / [ADR-0070](0070-bookmark-all-scope-quiz.md)）の**全問**だった。範囲は広く取りつつ「そのうち N 問だけ」テストしたい使い方（広い範囲からの抜き打ち確認、隙間時間の短いテスト）ができない。範囲を狭めれば問題数は減らせるが、それでは「どこが出るか分からない」抜き打ち性が失われる。

実装上の論点は 3 つあった。

1. **抽選をどこで行うか**: 出題順の決定は `buildQuiz` に集約する規約がある（[ADR-0072](0072-quiz-order-by-occurrence-number.md)。ビルダーへ分岐を入れると RNG の消費列が設定依存になり [ADR-0028](0028-rng-injected-pure-generation.md) のシード付きテストが崩れる）。
2. **抽選外になった範囲内の単語の扱い**: 四択のダミー候補は「同一 Occurrence → 他 Occurrence」の優先順（[ADR-0030](0030-dummy-pool-bounded-fetch.md)）で、出題対象はダミーにならない前提がある。
3. **再テスト（「同じ範囲でもう一度テストする」[ADR-0042](0042-retest-same-range.md)）との整合**: 抽選結果（出題した単語集合）はどこにも永続化されない設計（テスト自体を DB に保存しない）のため、「同じ問題の再現」には新たな永続化が要る。

## 決定内容

**開始画面に「出題数」`questionCount` を追加する**。未指定（空欄）= 従来どおり全問出題。

- **抽選は UseCase（`quiz-generate.ts`）で行う**。`partitionMaterial` の後に `pickN`（Fisher–Yates）で対象からランダムに N 語を選び、`retargetMaterial` で素材を再分割する。抽選は「出題対象集合の決定」であり出題順ではないため、出題順を `buildQuiz` に集約する規約（ADR-0072）は崩れない。形式ビルダー・既存 unit テストは無変更。
- **抽選外になった範囲内の単語はダミー候補プール（同一 Occurrence 側）へ回す**。`retargetMaterial` の既存流儀（drill ラウンド生成・再テスト生成と同型）で、ダミー候補は減らない（増える方向にだけ働く）。
- **対象数 ≤ 指定数は全問出題（min 挙動）**。エラーにしない。開始画面のプレビューに実効出題数（`min(指定数, 対象数)`）を併記する。スキーマ（zod）でも対象数との大小は検証しない（対象数は保存後のデータ変化で変わるため。デフォルト設定を保存時検証しない既存方針と同根）。
- **形式の成立可否（`checkFormatAvailability`）は抽選後の対象で判定する**。実際に出題する集合で判定するのが正であり、抽選はダミー候補を増やす方向にしか働かないため従来より不成立になりやすくなることはない。
- **掲載箇所に従属しない**: ブックマーク全件モード（掲載箇所未指定）でも指定できる。範囲入力（掲載箇所必須）とは違い、クロスフィールド検証の対象にしない。
- **再テストは同じ出題数で「再抽選」する**。`Drill.sourceQuestionCount` に元テストの指定を保存し（`sourceRangeFrom/To` と同役割）、「同じ範囲でもう一度テストする」は同じ出題数で範囲から選び直す。同じ単語集合は再現しない（下記代替案）。
- **定着モード（drill）のラウンド出題には適用しない**。ラウンドは残単語全部を出題する（定着の完了条件が「全単語の残数 0」である以上、間引くと完了できない）。出題数が効くのは元テストと再テストだけ。
- 設定の持ち方は「ブックマークのみ」（ADR-0070）と同型: 開始画面の入力 ＋ `QuizDefaultSetting.questionCount`（null = アプリ既定＝全問）＋ 設定画面。開始画面の「この設定をデフォルト設定とする」で保存される。上限は解答系配列と同じ `QUIZ_ANSWERS_MAX_COUNT`（5000、issue #107）。

## 採らなかった代替案

- **再テストで同じ単語集合を再現する（同じ問題でもう一度）** — テストは DB に保存されない設計のため、抽選済み wordIds を `Drill` へ永続化（最大 5000 件の配列カラム）し、「指定 ID 集合でテスト開始」の生成経路と入力面（クライアント申告 wordIds の検証）を新設する必要がある。さらに「再テストは今の状態で再評価する」という ADR-0042 の思想（ブックマーク再評価）と衝突し、削除・ブックマーク変更時の挙動の決定も増える。実装規模が 1.5〜2 倍になる割に、再抽選には「回すたびに別のミックスに当たる」学習上の利点もあるため却下（2026-08-02 ユーザー確認）。
- **抽選を SQL（`ORDER BY random() LIMIT N`）で行う** — 抽選外の範囲内単語が取得されずダミー候補プールから消え、ダミー確保の成立性が下がる。また抽選が RNG 注入の外（DB 側）に出てテストで決定化できない。取得は従来どおり全対象＋有界プール（ADR-0030）とし、JS 側で抽選する方が既存構造に沿う。
- **抽選を `buildQuiz`（generation 層）で行う** — `buildQuiz` は「取得済み素材から問題を作る」純関数で、素材の再分割（ダミー候補への回し込み）は `retargetMaterial` を使う UseCase 層の責務として既に確立している（drill ラウンド・再テスト生成）。集約規約（ADR-0072）が守っているのは出題順の RNG 消費列であり、対象集合の決定はもともと UseCase 側にある。
- **範囲を狭める運用で代替（機能を追加しない）** — 「どこが出るか分からない」抜き打ち性が失われ、ユーザーが手で範囲を刻む手間も残るため却下。

## 影響

- `Drill.sourceQuestionCount`（null = 指定なし）と `QuizDefaultSetting.questionCount`（null = 未設定＝全問）を追加（migration `20260802034440_add_quiz_question_count`。nullable 追加のみで backfill 不要）。
- 進行中 drill 一覧・完了画面の範囲表示は変更しない（出題数は表示に含めない。再テスト開始時に効くだけ）。
- 出題形式の追加時に増える手当てはない（抽選は形式非依存）。
- プレビュー（`quiz-preview.ts`）はサーバー変更なし（件数のみの軽量経路のまま。実効出題数はクライアントの min 計算）。
