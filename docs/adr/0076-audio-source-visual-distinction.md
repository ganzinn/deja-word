# ADR-0076: 発音ボタンは登録済み音源と自動音声を「アイコン＋濃淡」で区別する（ラベル文字は変えない）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-03

## 背景

発音音源が未登録のときは端末内蔵の自動音声（TTS）で代用する（[ADR-0046](0046-tts-fallback.md)）。ただし再生ボタンの見た目は音源・自動音声とも同一（`▶ 発音`）で、**ユーザーはいま聞いた発音が信頼できるもの（登録済み音源）なのか、端末合成の代用なのかを区別できなかった**。学習用途では「正しい発音として覚えてよいか」が判断できる必要がある。

## 決定内容

`AudioPlayButton`（`src/components/audio-play-button.tsx`）で、音源あり／自動音声を**形（アイコン）と濃淡の両方**で描き分ける。ラベル文字列は両方「発音」のまま変えない。

- 音源あり: マイクアイコン ＋ 通常コントラストの枠線（`border-foreground/30`）
- 自動音声: 再生（▶）アイコン ＋ muted な文字色（`text-muted-foreground`）
- `aria-label` を出し分け（`発音を再生` / `発音を自動音声で再生`）、`title` で根拠を補足する

制約と理由:

- **ラベル文字数を変えない**。発音ボタンは単語一覧・単語テストの密なレイアウトに並ぶため、文字数が変わると行内の並びが崩れる。
- **色相を使わない**。テーマは完全モノクロ（`--primary` 含め全トークンが彩度 0、例外は `--destructive` のみ）で、アクセント色という概念が無い。差は濃淡で付ける。
- **濃淡だけにしない**。モノクロで付けられる濃淡差は弱く、色覚特性・低コントラスト環境で伝わらない可能性がある。形（アイコン）でも冗長に区別する。

## 採らなかった代替案

- **ラベルを出し分ける（`発音` / `自動音声`）** — 意味は最も明快だが、一覧行・テスト画面でボタン幅が変わりレイアウトに影響する。ユーザーの明示的な要件（文字数を増やさない）と衝突するため却下。
- **音源ありにバッジ（✓ 等）を足す** — 幅が増えるうえ、マークの意味が初見で伝わらず凡例が要る。
- **色相（緑・青など）で区別** — モノクロのデザインシステムに新しい色相を持ち込むことになり、既存の配色規約（`destructive` 以外は無彩色）から外れる。
- **アイコンだけ／濃淡だけ** — どちらか一方では小サイズ（`size="xs"`、アイコン 12px）で気づきにくい。

## 影響

- 発音ボタンが出る全画面（単語一覧・単語詳細・単語テストの出題／選択肢／結果一覧・音源管理の「試聴」）で見た目が変わる。`docs/features/` のスクリーンショットは再撮影が必要。
- 音源管理画面の「試聴」ボタンは常に音源ありのため、常にマイク表示になる。
- ユーザーが「マイク = 登録済み音源」を学習できるよう、設定画面（単語全般）の自動音声の説明文と `docs/features/` に見分け方を明記した。
