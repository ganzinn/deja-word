# ADR-0077: 文章系フィールドの装飾は Markdown 風の記法で入力し、生テキストのまま保存する

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-03

## 背景

学習コンテンツ（意味・補足説明・例文・メモ等）では「この語法が要点」「ここは対義に注意」といった強調をユーザー自身が付けたい。これまで装飾できたのは TG 例文（`Example.kind=TARGET`）の**自動着色だけ**で（`src/components/tg-example-text.tsx`）、ユーザーが任意の箇所を強調する手段は無かった。

必要な装飾は 4 種（太字・斜体・赤文字・青下線）。入力欄はプレーンな `<input>` / `<textarea>` で、リッチテキストエディタは持っていない。

## 決定内容

### 記法

対称の囲み記号による Markdown 風の記法を採用する。解釈は `src/lib/rich-text.ts` の `parseRichText` に集約する。

| 記法 | 表示 |
| --- | --- |
| `**太字**` | 太字（`font-bold`） |
| `*斜体*` | 斜体（`italic`） |
| `***太字の斜体***` | 太字＋斜体（Markdown と同じく 1 記号として扱う） |
| `==赤==` | 赤文字（`text-red-500`） |
| `__下線__` | 青の下線（`underline decoration-blue-500`。**青いのは線だけで文字色は変えない**。文字も色付けたいなら `==` と重ねる） |

- 入れ子を許す（`**==赤い太字==**`）。マークは集合として重なる。
- **長い記号から先に照合する**（`***` → `**` → `==` → `__` → `*`）。先に `*` を見ると太字が斜体に食われる。
- `***` を `**` と `*` の入れ子として解かず専用の記号にしているのは、`***太字斜体***` と書いたときに内側の `*` が閉じられず崩れるため（同じ結果は `**太字*斜体*太字**` の形でも書けるが、Markdown 慣れした書き方を通す方を優先した）。
- **閉じ記号が無い記号・中身が空の記号は装飾にしない**（`2 * 3 = 6` はそのまま表示される）。
- **エスケープ記法を持たない**。記号そのものを表示したい場合は、対になる記号を書かないことで回避する。

### 保存形式

**打った文字列をそのまま保存する**。HTML へ変換して保存しない。スキーマ変更・マイグレーションは無い（対象カラムはいずれも `String`）。

装飾は描画のたびに `parseRichText` で解釈し、`<span>` + Tailwind クラスとして組み立てる（`src/components/rich-text.tsx`）。

### 対象フィールド

**文章系フィールドのみ**を対象とする。

対象: `MeaningText.text` / `MeaningNote.text` / `Example.text` / `Example.meaning` / `ExampleNote.text` / `RelatedWord.meaning` / `RelatedWordNote.text` / `WordMemo.text` / `WordOccurrenceDetail.detail`

対象外: `Word.headword` / `RelatedWord.term` / `Meaning.pronunciation` / `Occurrence.location` / `Meaning.partOfSpeech`

対象外の理由は、これらが**表示以外の用途で生の文字列として比較・利用される**ため。

- `headword` — スペル確認（SPELLING）の正誤判定、単語検索（`contains`）、重複見出し語チェック
- `RelatedWord.term` / `headword` — 発音の読み上げ（TTS フォールバック）、発音音源ファイルとの突合
- `Occurrence.location` — 掲載箇所の一意判定・範囲ラベル

これらにも記法を通すと、判定・突合のすべての経路に記号除去を挟む必要があり、漏れると「スペルは合っているのに不正解」のような静かな不具合になる。

### TG 例文の自動着色との重ね方

TG 例文の自動着色（英文＝青太字、意味＝赤、`A`/`B`/`do`/`doing` 等のプレースホルダの体裁）は**ベースの体裁**、ユーザーの装飾記法は**その上に重ねる**。競合するプロパティは `cn`（tailwind-merge）の後勝ちでユーザー記法を優先する。

アプリが訳語へ付ける強調（先頭の訳語の赤字。[ADR-0100](0100-first-meaning-only-question-side.md) 決定 2）も同じ扱いで、ベース体裁として置いた上にユーザー記法を後勝ちで重ねる。自動の赤は記法の赤マークと同じ `text-red-500` にしてあるため、重なっても見た目は変わらない。

### 選択肢の重複排除

四択・多義語選択のダミー選択肢の重複排除キーは、装飾記号を除いてから比較する（`src/lib/quiz/generation/dummy-pool.ts` の `dedupeKey`）。除かないと「片方だけ装飾された同じ訳語」が別物と判定され、画面上は同一文言の選択肢が並ぶ。

### 入力支援

記法は手打ちのみとし、装飾ボタン・ライブプレビューは作らない。単語フォーム上部に折りたたみの凡例（`RichTextHelp`）を置き、記号と表示結果の対応を確認できるようにする。凡例の見本は `RichText` を通して描画し、実際の体裁とのドリフトを防ぐ。

## 採らなかった代替案

- **HTML（またはリッチテキストの JSON）で保存する** — 描画は速くなるが、保存物のサニタイズ責務が生まれ（XSS）、記法や体裁を変えたくなったときに保存済みデータの一括変換が必要になる。生テキスト保存なら元の入力が常に無傷で残る。
- **タグ風の記法（`{b:太字}` / `{r:赤}`）** — 装飾種別を増やすときは素直だが、`**` が Markdown と同じ意味で使えるという学習コストの低さを優先した。既存データとの衝突可能性はどちらも同程度に低い（target1900 の 1900 行で `*` `{` `}` `==` は 0 件）。
- **1 文字の対称記号（`*太字*` / `^赤^` / `_下線_`）** — 打鍵は最小だが、本文に出る記号（特に `_` を含む固有名詞や `*`）との誤爆が最も起きやすい。
- **全フィールドで記法を有効にする** — 見出し語・関連語の見出しにも装飾を許すと、スペル判定・検索・TTS・音源突合のすべてに記号除去が必要になり、漏れが静かな不具合になる。装飾したいのは説明文であって見出し語ではない、という実際の用途とも合わない。
- **装飾ボタンとライブプレビューを付ける** — スマホでの入力は楽になるが、選択範囲の取得・カーソル位置の復元など `textarea` 制御の実装量が大きい。まず記法だけを入れて使用感を見る。
- **エスケープ記法（`\*` 等）を用意する** — 記号を literal で書きたい要求は現データに見当たらず（`*` `==` は 0 件）、記法の複雑さに見合わない。閉じ記号が無ければ装飾されない仕様で実用上は足りる。

## 影響

- 対象フィールドを表示する全画面で装飾が効く: 単語詳細（ページ・クイズ内ダイアログ）、単語一覧の意味、クイズの問題文・選択肢・自己判定の解答表示・結果一覧。
- 単語登録・編集フォームの先頭に凡例（折りたたみ）が増える。`docs/features/` のスクリーンショットは単語フォームのみ再撮影が必要。
- 既存データは無変更で、表示も変わらない（既存 1900 件に記法と衝突する記号がほぼ無いことを確認済み。`_` を含む 1 行も単独のアンダースコアのため装飾にならない）。
- テーマは無彩色を原則とする（[ADR-0076](0076-audio-source-visual-distinction.md)）が、それは UI クローム（ボタン・バッジ等）の規約であり、**学習コンテンツ本文の色は既に例外**（TG 例文の青・赤、意味テキストの赤）。本 ADR の赤・青はその延長で、UI クロームには色相を持ち込まない。
- **読み上げ（TTS）は記法を落として読む**（[ADR-0078](0078-speech-text-normalization.md)）。読み上げの一本道 `speakEnglish` で正規化するため、例文の読み上げを足しても記号が読まれることはない。
- 装飾を描画しない他の経路（CSV 取り込み・AI 下書き・音源突合・ops スクリプト）では記号がそのまま見える。必要になったら `stripRichTextMarkup` を通す。
