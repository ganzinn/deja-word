# ADR-0078: 自動音声は表示用の記号を落として読む（読み上げ直前に一箇所で正規化）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-03

## 背景

発音音源が未登録のときは端末内蔵の自動音声（TTS）で読み上げる（[ADR-0046](0046-tts-fallback.md)）。`speakEnglish` は受け取った文字列をそのままネイティブ TextToSpeech / `SpeechSynthesisUtterance` へ渡していたため、**本文に含まれる表示用の記号もそのまま合成に入っていた**。

記号を読むか黙って飛ばすかは合成エンジンの実装依存で、ネイティブ TextToSpeech とブラウザ speechSynthesis で揃う保証がない。実際に見出し語のチルダが読み上げられる事象が確認されている。

本番データで読み上げに関係する記号は次の 3 種類（2026-08-03 時点）:

| 出どころ | 値 | 記号の意味 |
| --- | --- | --- |
| 見出し語 | `so that ~` / `such a ~` | 「ここに語が入る」プレースホルダ |
| 関連語の見出し | `【米】check` `【米】garbage` `【米】lumber` `【米】major` `【英】socket` | 地域ラベル（米式・英式） |
| TG 例文の英文 | `be certain that ...` / `mean that ...` / `realize that ...` / `suggest (to 〜) that ...` | 「ここに節が入る」プレースホルダ |

見出し語と関連語の見出しは**現に読み上げられている**。TG 例文の英文は現時点では読み上げ対象ではないが、例文の読み上げ（#170）を足した時点で同じ問題を踏む。

加えて [ADR-0077](0077-rich-text-markup.md) で文章系フィールドに装飾記法（`**太字**` 等）が入った。

## 決定内容

**読み上げの一本道である `speakEnglish`（`src/lib/speech.ts`）で、渡された文字列を読み上げ用に正規化してから合成へ渡す**。正規化は `toSpokenText` に切り出す。

落とすもの:

1. **装飾記法**（`stripRichTextMarkup`。ADR-0077 の `**` `*` `==` `__`）
2. **注記** `【…】` — 中身ごと落とす（`【米】check` → `check`）。地域ラベルは表示の情報であって、読み上げる語ではない
3. **プレースホルダ** — チルダ `~` `〜` `～`（3 つの字形すべて）と省略記号 `...`（連続ピリオド 3 つ以上）・`…`。入力元により字形が揺れるため、いずれの字形も対象にする

**追補: 括弧（[ADR-0081](0081-speech-bracket-normalization.md)）** — 例文の読み上げ（[ADR-0079](0079-example-pronunciation-audio.md)）に伴い、括弧を意味で出し分ける規則を `toSpokenText` に追加した（`(…)` は記号だけ落として中身を読む／`[…]` は中身ごと落とす）。落とすものは本 ADR の 3 種＋括弧になる。

落としたあとは連続空白を 1 つに畳んで trim する。**文末のピリオドは残す**（落とすのは連続ピリオド＝省略記号だけ）。**正規化の結果が空になったら合成へ渡さず `onEnd` を呼んで完了扱いにする**（無音の発話を投げてハンドラが呼ばれないのを防ぐ）。

## 採らなかった代替案

- **呼び出し側（`ttsText` を渡す各コンポーネント）で正規化する** — 読み上げ経路は発音ボタンだけでも単語一覧・単語詳細・クイズの出題／選択肢／結果一覧に散在する。新しい呼び出し元が増えるたびに正規化を思い出す必要があり、漏れは「記号が読まれる」という静かな劣化になる。一本道での正規化なら構造的に漏れない。
- **DB のデータ側から記号を消す** — `so that ~` の `~` は表示としては必要な情報（後ろに語が続くことを示す）。表示と読み上げで要求が違うだけなので、保存物は変えない。
- **記号を読み替える（`~` を "something" と読ませる等）** — 原文に無い語を足すことになり、聞き手に誤った情報を与える。プレースホルダは読まないのが素直。
- **記号を一律に除去する（英数字以外を全部落とす）** — `don't` のアポストロフィや複合語のハイフンまで壊れる。落とすのは意味の分かっている記号だけに限る。

## 影響

- 発音ボタンの自動音声が「`so that ~`」→「so that」、「`【米】check`」→「check」と読むようになる。**登録済み音源（mp3）の再生には影響しない**（正規化は TTS 経路だけ）。
- 例文の読み上げ（#170）を足したとき、`be certain that ...` は「be certain that」と読まれる。
- 表示は一切変わらない（正規化するのは合成へ渡す文字列だけ）。
- 例文の読み上げを追加したとき、装飾記法の記号は自動的に落ちる。
- 新しく「読み上げたくない記号」が見つかったら `toSpokenText` に足す（1 箇所）。
