# ADR-0083: `do` / `doing` の斜体は訳語・TG 例文で共通ルール、色と `A` / `B` の斜体は TG 例文限定

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-06

## 背景

語法を表すプレースホルダ `do` / `doing` は、単語帳の紙面と同じく斜体で組みたい。これまで自動で斜体になるのは **TG 例文の英文だけ**だった（`TgExampleText`）。同じ記号を含んでいても、

- TG 例文の和訳（`TgExampleMeaning`）: 体裁を変えるのは `...` / `A` / `B` / `〜` の 4 種で、変えるのは色（青）だけ。`do` / `doing` は素通り。
- 訳語（`MeaningText`）: 自動の体裁は一切なし。`RichText` を通すだけ。

という状態で、`（to do）` を斜体にしたければユーザーが `（*to do*）` と装飾記法（[ADR-0077](0077-rich-text-markup.md)）で手打ちするしかなかった。訳語には TG 例文の英文と同じ記号が同じ意味で使われている（`（...する）根拠（to do）` など）。

「欄ごとに体裁ルールを持つ」構造そのものが、同じ記号の見え方が場所によって変わる原因になっていた。

## 決定内容

**プレースホルダの体裁ルールを「共通部分」と「欄固有部分」に分け、`do` / `doing` の斜体を共通側に置く**。

- **共通の斜体対象は `do` / `doing`**（`ITALIC_PLACEHOLDER_SOURCE`）。TG 例文の英文・TG 例文の和訳・訳語のどこに現れても斜体にする。判定は `isItalicPlaceholder` の 1 箇所。
- **`A` / `B` の斜体は TG 例文の英文だけ**（`AB_PLACEHOLDER_SOURCE`）。和訳・訳語では色（TG 和訳なら青）を変えるだけで斜体にしない。英文の `A` / `B` は語法の骨組みとして英文の一部を成すが、和訳・訳語の `A` / `B` は日本語の中に置かれた記号で、斜体にすると日本語の字面から浮く（2026-08-06 ユーザー確認）。
- **色（青）は TG 例文に限る**。訳語には色を付けない。TG 和訳の色対象は従来どおり `...` / `A` / `B` / `〜` で、新たに斜体対象へ加わった `do` / `doing` は**斜体だけで色は変えない**。
- **非太字（`font-normal`）も TG 例文の英文に限る**。青太字というベースを打ち消すための体裁であって、プレースホルダ一般の性質ではない。
- **トークン集合そのものは統一しない**。TG 英文は括弧・`〜` も体裁対象、TG 和訳は `...`・`〜` も色対象、訳語は `do` / `doing` のみ、と欄ごとに違ってよい。統一すると TG 和訳の括弧が青くなる・訳語の先頭行（太字赤）の括弧が非太字になるといった、誰も要求していない既存表示の変化を伴う。
- 実装は共通モジュール `src/components/placeholder-text.tsx`（`renderPlaceholders` と共通の斜体トークン）に置き、`tg-example-text.tsx` と新設の `meaning-text.tsx` がこれを使う。訳語の描画を `TgExampleText` の隣に置かないのは、訳語は TG とは無関係な欄で、TG モジュールへ依存させると「TG の一部」に見えるため。
- 適用欄は**訳語と TG 例文の和訳まで**。非 TG 例文の和訳・関連語の意味・補足説明・メモは対象外（同じ記号を使う欄が出てきたら、そのとき広げる）。
- 訳語の描画は `MeaningText` に集約し、訳語が出る全画面（単語詳細・単語一覧・単語テストの問題文／選択肢／解答／結果一覧）で同じ体裁になるようにする。
- 保存データは変えない。DB には入力どおりの文字列が入り、体裁は描画時にだけ付く（[ADR-0077](0077-rich-text-markup.md) と同じ方針）。ユーザーが `*to do*` と手打ちした既存データは、装飾記法の斜体と自動の斜体が重なるだけで見た目は変わらない。

## 採らなかった代替案

- **`A` / `B` も全欄で斜体にする**（最初の実装案） — ルール表は一番小さくなるが、和訳・訳語の日本語（`〔A ～ Bで〕A対B` など）の中で `A` / `B` だけが傾き、記号が浮いて読みにくい。共通化の目的は見え方を揃えることであって、ルールの行数を減らすことではない。
- **トークン集合まで完全に共通化する** — 「欄ごとのルール」を無くせるが、TG 和訳の括弧が赤→青に変わる・訳語の強調行で括弧が非太字になるなど、既存表示のリグレッションが出る。今回直したいのは斜体の有無だけ。
- **訳語だけに斜体を足し、TG 和訳は据え置く** — 依頼された箇所は直るが、「英文だけ斜体」という非対称が「英文と訳語だけ斜体」に置き換わるだけで、同じ記号が欄によって違う見え方をする問題は残る。
- **ユーザーが装飾記法で `*to do*` と書く運用を続ける** — 実装ゼロだが、1900 語規模の既存データに一括で入れる手間と打ち漏れが避けられず、入力者ごとに揺れる。
- **保存時に `*` を自動挿入する（データ側で解決）** — 表示ルールを変えるたびに保存物の書き換えが必要になり、入力どおりに保存する原則（ADR-0077）を崩す。
- **`renderPlaceholders` を `tg-example-text.tsx` に置いたまま訳語から import する** — ファイルは増えないが、TG と無関係な欄が TG モジュールに依存する。共通部分だけを別モジュールへ出す方が依存の向きとして素直。
- **前置詞（`(to)` `(for)` `(with)` 等）も斜体にする** — 訳語には括弧付きの前置詞が多数あり紙面では斜体だが、今回の依頼の範囲外。対象を広げると既存表示の変化が大きく、別途判断する。

## 影響

- 訳語に `do` / `doing` が含まれる行は、訳語が出る全画面で斜体になる。
- TG 例文の和訳に `do` / `doing` が含まれる行は斜体になる（色は変わらない）。
- TG 例文の英文の表示・TG 和訳の `A` / `B`（青のまま）・訳語の `A` / `B`（無装飾のまま）は変わらない。
- 読み上げ（`toSpokenText`）には影響しない。斜体は表示だけの体裁で、`A` / `B` / `do` / `doing` は読み上げ対象として残す方針（[ADR-0081](0081-speech-bracket-normalization.md)）も変わらない。
- 今後「このトークンも全欄で斜体にしたい」となったら `ITALIC_PLACEHOLDER_SOURCE` の 1 箇所を足せば 3 欄すべてに効く。「この欄だけ体裁を変えたい」は各欄の `classFor` に足す（`A` / `B` の斜体がその形）。
