# ADR-0085: 前後ナビの横フリックは window の touch イベントで判定する（左＝次 / 右＝前、画面端は除外）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-06

## 背景

単語詳細には、掲載箇所の並び（掲載番号順）を前後に移動する前後ナビが 2 箇所ある。

- 単語詳細ページ `/words/[id]`（掲載箇所コンテキスト付きで開いたとき） — `AdjacentWordNav` が `<Link>` で遷移する。
- 単語テストの結果一覧から開く単語詳細ダイアログ（ルート単語のみ） — `WordDetailDialog` が `onNavigate` で表示単語を差し替える。

どちらもボタン押下でしか移動できず、単語帳を順に読み進める使い方（掲載番号順に何十語も送る）ではボタンの位置まで指を運ぶ操作が毎回入る。スマートフォンの読み物 UI では横フリックで送るのが一般的で、ユーザーからも同じ操作を求められた（2026-08-06）。

## 決定内容

**前後ナビを出しているときに限り、画面全体の横フリックで前後の単語へ移動できるようにする**。判定は共通フック `useSwipeNav`（`src/components/use-swipe-nav.ts`）に置き、ページとダイアログの両方が使う。

- **方向**: 指を左へ動かす（左フリック）＝次へ、右へ動かす＝前へ。紙面をめくる向き・ボタンの左右配置と一致する。
- **リスナは window に張る**。前後移動は画面単位の操作であり、対象領域（ページ本文 / `DialogContent`）でスクロール容器が違うため、要素を包むラッパを 2 種類作るより窓側で受ける方が実装も DOM も薄い。すべて `passive: true` で登録し `preventDefault` はしない（縦スクロールを一切妨げない）。
- **有効化の条件は「移動先があること」**。`onPrev` / `onNext` が両方 null（前後ナビ非表示・関連語をたどった先・両端）ならリスナを張らない。端では無反応（巻き戻し・ラップアラウンドはしない）＝ボタンの `disabled` と同じ挙動。
- **判定閾値**: 横移動 60px 以上、かつ横移動が縦移動の 2 倍以上。タップのブレと縦スクロール中の斜めブレを弾く。時間の上限は設けない（ゆっくりした横ドラッグでも送れてよい）。
- **画面左右端 24px から始まったタッチは無視する**。iOS Safari / Android の「戻る」エッジジェスチャと二重に反応し、戻ると同時に前の単語へ移動する事故を避ける。
- **マルチタッチ（ピンチズーム等）は対象外**。触れている指が 1 本のときだけ開始位置を記録する。
- **視覚的なページめくりアニメーションは付けない**。ボタン押下と同じ遷移をするだけ。
- 判定そのものは純関数 `resolveSwipeNavDirection(dx, dy)` に切り出し、unit テストで閾値を固定する（イベント配線側は `.tsx` を含まないためテスト対象外）。

## 採らなかった代替案

- **子要素を包む `SwipeArea` コンポーネントを作り、そこに React の `onTouch*` を張る** — 対象範囲が明示的になるが、ページ（server component の `<main>` 配下）とダイアログ（`DialogContent` 配下）で挿入位置と flex レイアウトの調整が別々に必要になり、ラッパ div の分だけレイアウト崩れのリスクが増える。得られるのは「ヘッダ上のフリックが効かない」という差だけで、望ましさが不明。
- **`touchmove` で追従アニメーション（指に付いて紙面が動く）を付ける** — 気持ちよさは上がるが、`preventDefault` で縦スクロールとの取り合いを自前調停する必要があり、詳細画面（縦に長い）でスクロールを壊すリスクが大きい。まず移動できることを優先する。
- **Pointer Events で実装しマウスドラッグにも対応する** — PC でも同じ操作ができるが、本文のテキスト選択（ドラッグ）と競合する。PC にはキーボードとボタンがあり、要求はスマートフォンの操作。
- **スワイプライブラリ（react-swipeable 等）を入れる** — 判定は数十行で足り、依存を増やす利得が小さい。
- **エッジ除外を設けない** — 実装は単純だが、OS の戻るジェスチャと同時発火して「一覧に戻りつつ前の単語へ進む」ような不可解な遷移になり得る。
- **端でラップアラウンドする（最後の次＝最初）** — 送り続けられるが、ボタンが `disabled` になる挙動と食い違い、意図しない先頭戻りを生む。

## 影響

- 掲載箇所コンテキストで開いた単語詳細ページと、単語テスト結果からのルート単語ダイアログで、横フリック移動ができる。前後ナビを出していない画面（掲載箇所コンテキストなしの詳細、関連語をたどった先のダイアログ）は従来どおり無反応。
- `AdjacentWordNav` が client component になる（`useRouter` を使うため）。受け取る props は文字列のみで、ページ側の呼び出しは変わらない。
- ページ側の遷移は `router.push`。同じ href の `<Link>` が prefetch 済みのため、ボタン押下と同じ速さで表示される。
- 縦スクロール・ピンチズーム・OS の戻るジェスチャの挙動は変えない（`passive` リスナのみ、エッジ除外あり）。
