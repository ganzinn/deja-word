# ADR-0087: 掲載番号は見出し語の右に `#N` で出し、前後ナビは 2 ボタンを右詰めにする

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-06

## 背景

前後ナビ（ADR-0085 / ADR-0086）は導入時、単語詳細ページ・単語詳細ダイアログのどちらもコンテンツ上部に「前へ / 中央ラベル `No.N` / 次へ」の 1 行として置いていた。

中央ラベルの `No.N` は「今どの掲載番号を見ているか」の情報でしかなく、操作行に置く必然性がない。同じ情報を「掲載箇所」セクションのカードは `#N` として見出しの横に出しており、表記も置き場も二重になっていた（2026-08-06 ユーザー依頼）。

## 決定内容

1. **中央ラベル `No.N` は廃止し、掲載番号は本文の見出し語の右に `#N` として出す**（`WordDetailView`）。表記は「掲載箇所」セクションのカードに合わせる。掲載番号が無い単語では何も出さない（従来の `—` プレースホルダは持たない）。**文字サイズは `text-xl`**（見出し語 `text-2xl` の約 0.85 倍＝「掲載箇所」カードの本文 `text-sm` : 番号 `text-xs` と同じ比率）。カードの `text-xs` をそのまま持ち込むと 24px の見出し語に対して小さすぎ、並びとして釣り合わない。
2. **`#N` は「今表示している単語」の掲載番号を出す**。ダイアログは前後移動中も前の単語を残して待つ（ADR-0086）ため、番号は要求中の単語ではなく表示中の単語 ID を鍵に隣接応答から引く。番号だけ先に次の単語へ進むのを防ぐため。
3. **前後ナビ行はコンテンツ上部のまま**（ページ・ダイアログ共通）。位置・高さは 0085/0086 当時から変えない。
4. **ナビ行の 2 ボタンは右詰め**（`justify-end`）。中央ラベルが無くなり `justify-between` のままでは「前へ」が左端に孤立して 1 行が間延びするため、操作を画面右側にまとめる。

## 採らなかった代替案

- **ナビ行をコンテンツ末尾へ移す** — 1 語を読み終えた位置でそのまま次へ進めるが、実装して確認した結果ユーザー判断で不採用（2026-08-06。上部固定を維持する）。
- **ナビ行を画面下部に固定（sticky / fixed）** — 常に押せる反面、本文の可視領域を常時削る。単語詳細は 1 画面に収まらないことが多く、読む面積を優先した。
- **中央ラベルをナビ行に残したまま `#N` を見出し語の右にも出す** — 同じ情報の二重表示になる。
- **`#N` を `ScreenHeader` のタイトル横に出す（ページ）** — ダイアログには `ScreenHeader` が無く、ページとダイアログで置き場が分かれる。加えてヘッダは遷移中フィードバックの対象外（ADR-0086 影響節）なので、番号だけ先に切り替わる。

## 影響

- 掲載箇所コンテキストで開いた詳細のみ `#N` が出る（単語ビューから開いた詳細・関連語をたどった先には出ない）。単語がどの掲載箇所に何番で載っているかは従来どおり「掲載箇所」セクションで確認できる。
- ダイアログでは、詳細が先に届き隣接応答が未着の瞬間に `#N` が一拍遅れて現れうる（先読みが効いていれば起きない）。誤った番号を出さないことを優先した許容。
- `NavView` から `centerLabel` が消える（`word-detail-dialog-state.ts`）。ナビ行の表示可否・disabled 判定だけを担う。
- ダイアログのナビ行は本文と同じ `px-4`（右端が本文と揃う）。`✕`（`absolute top-2 right-2`）との衝突は、上段のブックマーク行に `min-h-7` を入れて高さを常に確保することで防ぐ。従来はブックマーク行を「詳細取得後のみ描画」していたため、詳細より隣接応答が先に届いた瞬間にナビ行が最上段へせり上がり ✕ と重なりえた（ナビ行の `pr-14` で避けていたが、右詰めにすると本文の右端と揃わなくなる）。副次的に、詳細到着時にブックマーク行が現れてナビ行が押し下げられるレイアウトシフトも無くなる。
- docs/features の該当記述を更新済み。前後ナビが写るスクリーンショットは無い（`word-detail.png` は掲載箇所コンテキスト無しで撮っており、詳細ダイアログの撮影対象も無い）ため再撮影は不要。
