# ADR-0088: テスト結果ダイアログの前後ナビを結果一覧順のクライアント配列に変更する

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-07

## 背景

テスト結果一覧から開く単語詳細ダイアログの前後ナビは、掲載箇所全体を掲載番号昇順で辿るサーバ隣接取得（`getAdjacentWordsForDialog` → `findAdjacentWordsByOccurrenceNumber`）だった。この方式には次の問題があった。

- ナビの順序が「結果一覧に見えている順（= 出題順、絞り込み中はその表示順）」と食い違う
- 全件ブックマークモード（掲載箇所なし）のテストでは `occurrenceId` が無くナビ自体が出ない
- 削除済み単語に到達すると隣接応答が null になり、ナビごと消えて先へ進めないデッドエンドがある

word-view-nav 設計（`docs/design/word-view-nav/03-quiz-result-dialog-nav.md`。実装完了に伴い削除済みのため、決定は本 ADR に転記してある）で置き換えを確定した。

## 決定内容

1. **順序ソースはクライアントスナップショット**: 前後ナビの順序は、結果一覧でダイアログを開いた時点の表示行（`wrongOnly` フィルタ適用後の `visibleRows`）の wordId 配列（navOrder）とする。隣接判定はすべてクライアント側の配列 index で行い、サーバへの隣接取得は行わない。ダイアログ表示中はフィルタを操作できない（モーダル）ため順序は陳腐化せず、閉じて開き直せば再スナップショットされる。サーバは出題順を復元できず（ADR-0024）、順序の真実は `rows` 配列にしかない。
2. **受け渡しは開くイベントの引数**: `ResultList` の `onOpenDialog(wordId, navOrder)` で渡し、`quiz-flow.tsx` が `dialogNavOrder: string[] | null` state に保持する。`dialogStack` が空になったとき（閉じるボタン・ブラウザバックの pop のいずれでも）null に戻す。出題中の詳細ボタン経由は順序なし（null）。`WordDetailDialog` へはスタック深さ 1 のときのみ渡す（関連語スタック先はナビ非表示を維持）。現在位置は `navOrder.indexOf(表示中 wordId)`（1 語 1 問で wordId は一覧内一意）、端は disabled。ナビの表示条件は「navOrder が非 null」のみで `occurrenceId` に依存しない → 全件ブックマークモードでもナビが出る。隣接が同期的に決まるため応答待ちのナビ状態（初回非描画・移動中 disabled）は廃止し、ナビ行は開いた瞬間から確定表示する。
3. **サーバ隣接経路の廃止**: `getAdjacentWordsForDialog` action・`adjacentWordsInputSchema`・`findAdjacentWordsByOccurrenceNumber` を削除する（順序ソースが二重になる余地を構造的に排除）。詳細ページ用の `findAdjacentWordsByOccurrence` は別物であり存続する。
4. **#N は詳細応答から導出**: 見出し語右の掲載番号は、表示中の詳細データ（`WordDetail`）の掲載箇所一覧から基準掲載箇所（`dialogOccurrenceId`）に一致する行の `occurrenceNumber` を引いて表示する。`dialogOccurrenceId` が null（全件ブックマークモード）・一致なし・番号なしでは #N を出さない（ナビは出る）。詳細と同じ応答由来のため「前の単語を残して淡色化中に番号だけ先に進む」事象が構造的に起きない。
5. **削除済み単語の行はスキップしない**: 到達時は既存のエラービュー（「対象の単語が見つかりません。」）を表示し、前後ナビはそのまま操作できる（隣接が配列 index で決まるため、詳細取得の成否とナビの可用性が独立する）。一覧に見えている行を黙って飛ばさない。
6. **先読みは前後 1 件の詳細のみ**: `resolvePrefetchTargets` は navOrder 上の前後 1 件の未キャッシュ詳細のみを対象とし、隣接応答の先読み（`kind: "adjacent"`）は廃止する。発火条件は「表示中単語の詳細が settle した後」に簡素化し、`occurrenceId` への依存を外して navOrder がある間は先読みする（全件ブックマークモードでも有効）。エラー応答をキャッシュしない方針は維持する。

**ADR-0086 決定 3 のうち「ダイアログは詳細＋隣接ナビの Server Action を前後 1 件先読みする」の隣接先読み部分は、本 ADR の決定 6 で置き換える**（詳細の前後 1 件先読み・開いている間だけの Map キャッシュ・鮮度照合と干渉させない方針は変わらない）。

## 採らなかった代替案

- **順序（wordId 配列）をサーバへ渡して隣接をサーバ計算** — 順序の正はどのみちクライアントにあり、ラウンドトリップと入力検証を増やすだけで得る情報が無い。
- **`wrongOnly` を quiz-flow へリフトして親で順序を導出** — `ResultList` の表示専用の関心が親へ漏れる。開いた時点のスナップショット受け渡しで足りる。
- **`dialogStack` を `{ wordId, index }` 等に変える** — 関連語 push には index が無く型が歪む。順序はスタックと独立した 1 本の配列で十分。
- **隣接 action を残して全件ブックマークモード等の補完に併用** — 順序ソースの二重定義そのもの。掲載番号昇順ナビは廃止確定済みで残す用途が無い。
- **`ResultRow` に `occurrenceNumber` を追加して一覧から供給** — quiz 生成データ〜結果行まで伝搬範囲が広く、詳細応答から引けば足りる。
- **削除済み行をナビからスキップ** — 見えている行を黙って飛ばすと一覧とナビが不一致になる。削除判定源が送信応答にありモードごとに分かれるため、順序リスト構築が複雑化する割に得る体験が小さい。
- **前後 2 件以上の先読みへ拡張** — ADR-0086 で前後 1 件・追い越し許容と確定済みで、覆す動機が無い。

## 影響

- 全件ブックマークモードのテストでも結果ダイアログに前後ナビが出るようになる（従来は非表示）。
- 「間違えた問題だけ表示」で絞り込み中は表示行だけを辿る（従来は絞り込みと無関係に掲載番号順）。
- テスト後に削除された単語の行へ移動してもナビが継続操作できる（従来はデッドエンド）。
- 単語詳細 1 表示あたりのサーバ往復が減る（隣接取得・隣接先読みの廃止。詳細先読みは従来どおり前後 1 件）。
