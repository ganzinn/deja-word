# ADR-0092: 単語詳細のカードは全体がタップで発音を鳴らす（右上のアイコンバッジは音源の有無を示す印。ADR-0076 追補）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-07

## 背景

発音の再生ボタン（`AudioPlayButton`）は `size="xs"` ＝ **高さ 24px** で、iOS HIG の 44pt・Android の 48dp というタップ領域の推奨値を大きく下回る。単語詳細ではこれが本文の上に小さく置かれており、**スマホで押しづらい**という指摘があった。

単語詳細は `src/components/word-detail-view.tsx` 1 つを、詳細ページ（`/words/[id]`）と単語テストの詳細ダイアログ（`src/app/quiz/_components/word-detail-dialog.tsx`）が共有している。詳細の表示単位は「カード」（意味・例文・関連語・掲載箇所）で、**発音を持つカードでは「カード 1 枚 ＝ 発音 1 つ」が既に成り立っている**。押しづらさの本質は、その 1 対 1 対応があるのに操作点だけが 24px の的に絞られていたことにある。

## 決定内容

1. **詳細カード（意味・例文・関連語）はカード全体をタップ領域にする**。カード内のどこを押しても、そのカードの発音が鳴る（再押下で停止）。新設の `PronunciationCard`（`src/components/pronunciation-card.tsx`）が担う。
2. **カード右上にアイコンのみのバッジを置く**。ADR-0076 の描き分け（音源あり＝マイクアイコン＋通常コントラストの枠線 / 自動音声＝再生アイコン＋muted な文字色、`aria-label` と `title` での区別）は**そのまま維持し、ラベル文字「発音」だけを落とす**（`size="icon-xs"`、従来と同じ 24px 角）。ADR-0076 が「ラベル文字を変えない」とした理由は一覧行・テスト画面でボタン幅が変わりレイアウトが崩れることであり、詳細カードは幅の制約を受けないため矛盾しない。
3. **バッジは品詞・発音記号のメタ行に流し込まず、カード右上へ絶対配置する**（`absolute top-3 right-3` ＋ カード側 `relative pr-10`）。メタ行に入れると、メタを持たない例文カード（TG・成句・熟語・MP・例文）で**バッジだけの行が縦 1 行分を占め、左側に空白の帯ができる**ため。絶対配置なら例文カードはメタ行ごと畳まれ（`empty:hidden`）、本文がカード上端から始まる。DOM 上はバッジをカードの先頭に置き、支援技術が本文より先に操作点を読み上げるようにする。
4. **バッジの有無が、そのまま「鳴るかどうか」の目印になる**。再生手段がまったく無いカード（音源なし・自動音声も使えない）はバッジを出さず、タップにも反応しない。とくに 2 個目以降の意味は自動音声フォールバックの対象外（ADR-0082）のため、音源が無ければバッジ無し＝タップ不応となる。
5. **カード自体は `role="button"` にしない**。関連語カードはリンク（`<Link>` / `onSelectRelated` の `<button>`）を内包しており button の入れ子は不正になること、カード本文まるごとがボタンの読み上げ名になってしまうことによる。カードの `onClick` は**ポインタ操作の近道**と位置づけ、キーボード・支援技術からの操作は右上バッジ（本物の `<button>`、`aria-label` / `aria-pressed` 付き）が担う。
6. **カード内の操作要素はカードのタップより優先する**。`onClick` の中で `e.target.closest("a,button")` を見て、一致すれば何もしない。これで右上バッジの二重トグル（バッジ自身の再生とカードの再生が打ち消し合って即停止する）と、関連語リンクの誤発火をまとめて防ぐ。呼び出し側（`word-detail-view.tsx`）に伝播停止を書かせないため、判定は `PronunciationCard` の内側に閉じる。
7. **本文を選択している最中のクリックでは鳴らさない**。`window.getSelection()` が非 collapsed なら `toggle` しない。例文・意味のコピーをカード全体タップ化で潰さないため。
8. **一覧行・単語テスト・音源管理の「試聴」は従来どおり**行内の `AudioPlayButton` を使う。一覧行はタップが詳細への遷移・展開に割り当て済みで、カード全体タップと衝突するため。
9. **再生制御を `usePronunciationPlayback`（`src/components/use-pronunciation-playback.ts`）へ切り出す**。「音源を常に優先し、無いときだけ（設定 ON・読み上げ語あり・ブラウザ対応）自動音声」という判定は、行内ボタンとカード全体タップで完全に同一のため。見た目の描き分けは `PronunciationToggle`（`src/components/pronunciation-toggle.tsx`）に集約し、ADR-0076 の規則が 2 箇所へ分裂しないようにする。`AudioPlayButton` の外部 API（`src` / `label` / `ttsText` / `reserveSpaceWhenEmpty`）は変えない。

## 採らなかった代替案

- **擬似要素で当たり判定だけ広げる**（`after:absolute after:-inset-*`。`src/components/ui/checkbox.tsx` に前例あり） — 見た目を変えずレイアウトも動かない最小の手だが、「小さな的を狙う」操作自体は残る（広がるのは数 px 単位で、44px には届かせにくい）。また「カード 1 枚 ＝ 発音 1 つ」という既にある対応関係を視覚的に伝えられない。
- **ボタン自体を拡大する**（`size` を `sm`=28px / `default`=32px へ） — それでも 44px に届かないうえ、メタ行の高さが変わりカードの縦寸が動く。得られる改善に対して見た目の変更が大きい。
- **カードを `role="button"` にする／カード全面に透明な `<button>` を重ねる** — 関連語カードのリンクが button の入れ子になり a11y 上不正。全面オーバーレイは本文のテキスト選択も塞ぐ。決定 5 の「近道としての `onClick` ＋ 操作点はバッジ」はこの両方を避けるための形。
- **バッジに「発音」の文字を残す** — カード全体が押せる以上、文字は操作の誘導としては冗長になり、右上の印としては大きい。ADR-0076 の文字数制約は一覧行の都合であり詳細カードには効かない（決定 2）。
- **一覧行にもカード全体タップを広げる** — 行タップは詳細への遷移・展開に割り当て済みで衝突する（`RowAudioButton` が伝播を止めている構造がまさにその衝突の管理）。
- **掲載箇所カード・メモカードも同じ扱いにする** — 発音を持たないため対象にならない。見た目の枠（`detailCardClassName`）だけ共有し、挙動は変えない。

## 影響

- **詳細ページと単語テストの詳細ダイアログの見た目が変わる**（行内の `🎤 発音` ボタン → 右上のアイコンのみバッジ）。`docs/features/` の該当記述とスクリーンショット（`word-detail.png`）は更新・再撮影が必要。
- 例文系カード（TG・成句・熟語・MP・例文）はメタ行が畳まれ、1 行分（約 32px）縦に詰まる（決定 3）。意味・関連語カードの縦寸は変わらない。バッジのぶんカード本文の右余白が広がる（`pr-10`）。
- **誤タップで音が鳴る頻度は上がる**。横フリックの前後ナビ（ADR-0085）は最低 60px の横移動を要求するため判定は分かれるが、本文を読みながらの意図しないタップは従来より鳴りやすくなる。これは押しやすさと引き換えに受け入れる。
- キーボード操作・スクリーンリーダーからの操作性は変わらない（右上バッジが従来のボタンと同じ役割・同じ `aria-label` を持つ）。
- `AudioPlayButton` は内部が `usePronunciationPlayback` ＋ `PronunciationToggle` に分解されたが、呼び出し側（一覧・単語テスト・音源管理、計 6 箇所）の記述と挙動は変わらない。
