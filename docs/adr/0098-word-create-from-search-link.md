# ADR-0098: 検索結果からの単語登録導線（完全一致は検索と同じ照合規則・受け渡しは一覧コンテキストのみ）

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-15

## 背景

単語ビュー（`/words` の単語一覧）で検索して目当ての単語が見つからなかったとき、登録への導線はヘッダの常設リンクと検索語なし時の空状態ボタンしか無く、どちらも検索語を登録フォームへ引き継げなかった。ユーザーは `/words/new` で綴りを打ち直す必要があり、「検索して無ければ自分で登録する」という基本ループが 1 動線で完結していなかった。

word-create-from-search 設計（`docs/design/word-create-from-search/` 01〜03。実装完了に伴い削除済みのため、恒久的な判断は本 ADR に転記してある）で、件数行の直下に「「{語}」を登録」の導線を出し、検索語をプリフィルした `/words/new` へ進める仕様を確定した。実装は PR #260。

本 ADR が引き継ぐのは次の 2 つの判断で、いずれも「なぜその代替案を採らなかったか」がコードからは復元できない。

- **導線を出すかどうかを決める「完全一致」の定義**（照合規則・比較対象の集合）
- **導線リンクが `/words/new` へ何を渡すかの契約**（プリフィル値・戻り先の受け渡し方式）

表示語・プリフィル値に正規化後キーワードを用いる判断は [ADR-0084](0084-search-keyword-accent-normalization.md) の例外節が受け皿になっている（本 ADR では前提として参照する）。

## 決定内容

1. **発動条件は「有効な検索語あり ∧ 登録可能な長さ ∧ 可視範囲に完全一致 headword なし」**: 「有効な検索語」は `normalizeSearchKeyword`（ADR-0084）を通した結果が空でないこと（正規化後が空になる入力では一覧が「キーワード指定なし」に倒れる既存挙動に合わせ、導線も出さない）。「登録可能な長さ」は正規化後キーワードが見出し語の最大長（`SHORT_TEXT_MAX_LENGTH` = 100、[ADR-0068](0068-content-input-max-limits.md)）以内であること。条件を満たすとき、**検索結果の件数と一致方法（から始まる / を含む / で終わる）にかかわらず**導線を表示する。部分一致のヒットがあっても表示する（「runner」だけがヒットしても「run」は登録できる）。

2. **完全一致は検索と同じ照合規則（大文字小文字を区別しない等値比較）で判定する**: 検索の部分一致照合（キーワード側のみ正規化・`mode: "insensitive"`。ADR-0084）を等値比較に置き換えたもので、照合規則を検索と一貫させる。書き込みガードの `src/lib/words-duplicate.ts` が区別する equals を使うのは一意制約 `@@unique([ownerId, headword])` と挙動を揃えるためであり、**目的が違うので規則も分ける**（あちらは書き込みの可否、こちらは検索の見え方に合わせた表示判定）。この使い分けは判定関数の JSDoc にも残す。アクセント付き headword が正規化後キーワードと等値にならない非対称は、検索で見つからないのと同じ帰結として許容する。

3. **比較対象は可視範囲（system＋自分）の全体で、表示上の絞り込みに依存しない**: 判定は `src/lib/words-list.ts` の専用関数 `hasExactHeadwordForUser(userId, keyword)`（`ownerId: { in: scopedOwnerIds(userId) }`、[ADR-0018](0018-scoped-owner-ids-read-scope.md)）で行い、ブックマーク絞り込み・ページングを**入力に持たない**（定義を構造で担保する）。呼び出し側（`WordView`）は正規化を 1 回だけ行い、決定 1 の前 2 条件を満たすときのみ判定関数を呼んで `listWordsForUser` と `Promise.all` で並列実行する。

4. **導線リンクは一覧コンテキストだけを渡し、プリフィル値と戻り先 URL はサーバ側で導出・再構築する**: リンク先は `/words/new?<一覧コンテキスト>` で、一覧コンテキストは単語ビューの検索条件 `q` / `sort` / `match` / `bookmarked` / `page` をそのまま渡したもの（省略規則は一覧 URL と同じ）。`q` に載せるのは URL・件数行と同じ trim 済み入力値で、導線の表示語（正規化後キーワード）とは別値になりうる（正規化後を載せると、アクセント付き入力時に戻り先が元の一覧と別の検索になる）。`/words/new` 側では、プリフィル値を `q` から導出し（正規化 → `headwordSchema` の safeParse に通った場合のみ採用。手打ち URL への防御）、戻り先は `q` の trim 後が非空なら一覧 URL を再構築して `returnHref` に渡す。**プリフィル専用パラメータ（`headword=` 等）と生の戻り先 URL（`return=/words?...`）は受けない**。これは詳細・編集画面と同じ流儀（コンテキストを受けてサーバ側で内部相対パスを組み立てる。[ADR-0089](0089-word-detail-nav-list-context.md) 決定 6）で、オープンリダイレクトを構造的に排除する。導線経由の「戻る」は元の検索条件の一覧へ戻り、送信成功後の遷移は既存どおり登録した単語の詳細のまま変えない。

5. **プリフィル値に対するフォーム初期表示時の重複チェックは追加しない**: 既存の blur 発火のままとする。決定 1・2 により「可視範囲に大文字小文字を区別しない完全一致なし」が導線の前提であり、重複警告・一意制約が見る「区別する完全一致」はその部分集合なので、プリフィル値のまま登録して重複になる通常経路が無い。まれな競合（導線表示後に別タブで同語を登録）や手打ち URL は、blur 時の既存チェックと送信時の `duplicate` エラー表示で拾える。

## 採らなかった代替案

- **ゼロ件時のみ導線を出す** — 部分一致だけがヒットするケース（「runner」があり「run」が無い）で登録に進めず、要望を満たさない。
- **現在の絞り込み結果（ブックマーク絞り込み・表示中ページ）を判定対象にする** — ブックマーク絞り込み中は既存の完全一致単語が結果に現れないだけで導線が出てしまい、一意制約エラーになる登録へ誘導する。
- **`listWordsForUser` の戻り値に `hasExactMatch` を足す** — 一覧取得は `bookmarkedOnly` / `skip` / `take` を受けるため、絞り込み非依存の判定と関心が混ざる。掲載箇所ビュー等、既存の全呼び出し箇所にも波及する。
- **取得済みの一覧結果から完全一致を導出する** — 手元にあるのは 1 ページ分だけで、2 ページ目以降やブックマーク絞り込みで決定 3 の定義とずれる。
- **system 単語に完全一致があっても導線を出す（私有コピー登録の導線を兼ねる）** — system 単語との共存登録は許容仕様（[ADR-0065](0065-system-word-coexistence.md)）だが、完全一致がある時点で「見つからなかった」という前提が崩れる。私有コピーの作成は `/words/new` の手動フローで足りる。
- **完全一致判定を重複警告・一意制約と同じ「大文字小文字を区別する」に揃える** — 導線の目的は「検索で見つからなかった」ことの判定なので、検索の照合規則から外れるほうが不自然。逆に重複警告側を区別しないへ統一する改修は、一意制約の挙動に合わせるという別の関心の変更でスコープ肥大になる（必要が出たら issue 化する）。
- **プリフィル値を専用パラメータ `headword=` で別途渡す** — 一覧コンテキストの `q` と同じ情報の二重受け渡しになり、手打ち URL で食い違わせる余地が生まれる。
- **生の戻り先 URL を searchParams で渡す** — 内部パス限定の検証を新設する必要があり、既存流儀（コンテキスト渡し＋再構築）から外れる。
- **戻り先を既存のまま固定 `/words` にする** — 実装は最小だが、導線の起点である検索結果へ戻れず、検索のやり直しの手間が導線の価値を削る。
- **プリフィル時に重複チェックを 1 回発火する** — 通常経路では警告が出ることがなく、フォーム挙動の追加に見合わない。
- **プリフィル値に trim 済み入力値をそのまま使う** — 判定値との乖離が生じる。詳細は ADR-0084 の例外節を参照。

## 影響

- 部分一致だけがヒットする検索・2 ページ目以降・ブックマーク絞り込み中でも、可視範囲に完全一致が無ければ導線が出る。逆に、絞り込みで完全一致が画面に見えていなくても導線は出ない。
- 自分が「Run」を持つ状態で「run」を検索すると、登録自体は可能なのに導線は出ない（決定 2 のズレ）。導線が出ないだけで `/words/new` の手動登録は残るため許容する。
- 「を含む」「で終わる」でのブラウズ用途の検索でもヒット多数のまま導線が出続け、押せば「ing」のような断片語も登録できる。登録には明示的な操作が要り削除で回復できるため許容し、表示は控えめなテキストリンク（件数行直下）に留めて緩和する。
- `/words/new` が searchParams を解釈するようになり、create モードの戻り先が可変になった（従来は固定 `/words`）。一覧 URL のパラメータ語彙を増やすときは、一覧側のパーサ・ビルダだけでなく `/words/new` 用のヘルパも追随させる必要がある。
- 検索の照合規則（ADR-0084 の正規化・`mode: "insensitive"`）を変えると、この導線の発動条件も同じ規則で動くため両方の見え方が変わる。
