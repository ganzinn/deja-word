# ADR-0100: 訳語の「先頭のみ表示」は出題側にだけ効かせ、解答側は先頭訳語の赤字で補う

- ステータス: 提案
- 確信度: 高
- 起票日: 2026-08-15

## 背景

単語テストには「選択肢に最初の訳語だけを表示する」設定があり、四択（英語→日本語）の選択肢だけに効いていた（`choiceFirstMeaningTextOnly`）。一方、日本語→英語の 3 形式（四択・自己判定・スペル確認）の問題文は常に最初の Meaning の訳語を「; 」で連結して出しており、訳語を複数持つ単語では手がかりが多すぎて答えが透けるという要望が出た。

quiz-first-meaning-only の設計（要求・適用範囲／設定モデルと移行／UI・文言とテスト戦略の 3 トピック。実装完了に伴い設計文書は削除済みで、恒久的な判断は本 ADR に転記してある）で、この設定を形式横断の**共通設定**へ広げ、コード名・DB 列名を `firstMeaningTextOnly` / `first_meaning_text_only` へ改名することを確定した。

本 ADR が引き継ぐのは、いずれもコードからは「なぜ他案を採らなかったか」が復元できない次の 4 つの判断である。

- **設定を効かせる範囲を出題側に限り、解答側は情報を減らさず強調で補うこと**（表示ごとの目的の違いをどう扱うか）
- **先頭の訳語だけでは答えが一意に定まらない問題文を許容すること**（許容の範囲と、例外的に打つ緩和策の線引き）
- **設定の適用範囲を広げても、進行中の drill に保存済みの値を移行しないこと**
- **設定の既定値を層ごとに揃えないこと**

改名そのもの・表示切替ヘルパの置き場・トグルの表示条件や文言・赤字の実装経路は、読めば分かる／覆すコストが低い判断としてコード（＋コメント・テスト）に委ねる。四択（日本語→英語）のダミー選定に入れた緩和策は、既存の受け皿である [ADR-0026](0026-dummy-choices-same-occurrence-first.md) へ追記した。

## 決定内容

### 1. 共通設定は「手がかりを出す側」にだけ効かせる

設定が効くのは次の 2 つで、いずれも**出題データの生成時**に反映する。

- 四択（英語→日本語）の選択肢（従来の適用先。挙動は変えない）
- 日本語→英語 3 形式（四択・自己判定・スペル確認）の問題文（今回の追加分）

ON は「最初の Meaning の先頭 MeaningText 1 つ」、OFF は「最初の Meaning の MeaningText を『; 』連結」。この定義は全適用先で共通とする。

効かせないのは、多義語選択（英語→日本語）の選択肢、自己判定（英語→日本語）の解答表示、TG 例文形式 4 種、訳語が出る他の画面（単語詳細ダイアログ・単語詳細ページ・単語一覧）。

設定の目的は「答えを思い出す手がかりを 1 つに絞る」ことであり、手がかりを出す側（問題文・選択肢）と、答え合わせで覚える材料を出す側（解答表示）は目的が逆になる。後者は情報を減らさないほうがよい。多義語選択は「最初の Meaning の訳語をすべて選ぶ」が正解条件なので、先頭の訳語だけにすると選ぶべき正解が常に 1 つになり、形式の眼目が失われる。TG 例文形式は問題文・解答の素材が TG 例文の英文と意味で、訳語を表示しない。

**結果一覧には専用の分岐を作らない**。結果一覧は生成済みデータの再表示なので、上記 2 つの適用先はそのまま結果一覧の該当列（四択（英語→日本語）の正解列と「自分の回答」列、日本語→英語 3 形式の問題文列）にも同じ内容で出る。

### 2. 解答側は、設定に連動しない常時の赤字で補う

自己判定（英語→日本語）の解答表示（全 Meaning を品詞ごとに並べるブロック）と、結果一覧のその形式の正解列で、**先頭 Meaning の先頭 MeaningText 1 つ**をアプリが常時赤字にする。共通設定の ON / OFF には連動させない。

- 体裁は `text-red-500`・太字なし・`dark:` なし。単語一覧および装飾記法（[ADR-0077](0077-rich-text-markup.md)）の赤マークと同じ値。
- 装飾記法との重ね方は既存方針（[ADR-0077](0077-rich-text-markup.md) / [ADR-0083](0083-placeholder-italic-shared.md)）に従い、自動の赤字をベース体裁として置き、ユーザー記法を後勝ちで重ねる。呼び出し側でラッパー要素を足す形は採らない（記法で色を上書きできる経路を保つため）。
- 対象外は、多義語選択の選択肢・正解列、四択（英語→日本語）の選択肢と結果一覧の正解列・「自分の回答」列（決定 1 で設定により内容が変わる列であり、強調を重ねると設定の効果が読み取りにくくなる）、日本語→英語の問題文（設定 ON なら表示自体が先頭の訳語 1 つになる）、TG 例文形式。

自己判定（英語→日本語）の解答表示は全 Meaning を並べるため、どれが代表的な訳語かが一目で分からない。表示を減らさずに視点を誘導できる強調が要求に合う。設定と連動させないのは、設定 OFF（全訳語表示）のときこそ強調の必要が大きいためで、連動させると必要な場面で効かない逆の挙動になる。

この決定は [ADR-0083](0083-placeholder-italic-shared.md) を覆さない。同 ADR の「訳語には色を付けない」「訳語が出る全画面で同じ体裁」は `MeaningText` が**自動で付ける体裁**についての記述であり、画面側が先頭の訳語を強調することを禁じていない。実際、単語一覧と単語詳細は既に先頭の訳語を赤字にしており、今回はその既存慣行を単語テストの解答側へ広げるものである。「訳語の描画は `MeaningText` に集約する」も、赤字を同じ描画経路（ベース体裁）に載せるため壊れない。

**単語詳細（`font-bold text-red-400`）とは体裁がずれたまま残る**。単語一覧・単語詳細・単語テストの 3 画面の統一と、訳語まわりの赤・TG 例文の意味の赤がいずれもダークモード未対応な件は、本機能と無関係な既存画面の見た目を変えることになるため別 issue（[#269](https://github.com/ganzinn/deja-word/issues/269)）に切り出す。

### 3. 先頭の訳語だけでは答えが一意に定まらない問題文は許容する

設定 ON では、先頭の訳語が同じ別単語が同じテストに含まれると、四択（日本語→英語）で正解と等価に見える選択肢が並ぶ・スペル確認で別解を入力して不正解になる、といったことが起こりうる（自己判定（日本語→英語）は自己申告採点のため採点上の影響はない）。これを設定の性質として許容し、避けたいユーザーは開始フォームで OFF にする。

訳語は本来 1 対 1 対応ではなく、「; 」連結の現状でも同じ訳語群を持つ単語では起こりうる（ON で頻度が上がるだけ）。設定の目的（手がかりを絞る）と両立する完全な一意性保証は、出題対象の除外や訳語の付け替えを伴い、機能の規模に見合わない。

**緩和策を打つのは四択（日本語→英語）のダミー選定だけ**とする。四択は選択肢を生成側で選べるため、「同じ問題文に対して正解と等価な選択肢が並ぶ」事態だけは低コストで避けられる。実装（候補キーを「正解一致判定用」と「重複排除用」に分ける形）と、その帰結として不成立条件が広がることは [ADR-0026](0026-dummy-choices-same-occurrence-first.md) に追記した。自己判定・スペル確認には選択肢が無く、同じ緩和は適用できない。

### 4. 進行中の drill に保存済みの値は移行しない

既存の `Drill` 行（日本語→英語形式を含む）の値は書き換えない。実装後は、保存値が ON の日本語→英語 drill の問題文が次ラウンドから先頭の訳語 1 つになる。「同じ範囲でもう一度テストする」へ値が伝播する既存経路もそのまま使う。

日本語→英語 drill に保存されている値は、開始フォームのトグルが四択（英語→日本語）選択時しか表示されない一方で値は形式によらず送られていたため、ほとんどの場合デフォルト設定の値（未設定なら ON）がそのまま流れたものになる。いずれもそのユーザーが選んだ／受け入れた値であり、共通設定として読み替えても設定の意図と食い違わない。drill は短命なデータで、形式で絞った backfill を書くと、その SQL 自体が「日本語→英語だけ OFF」という説明の付かない状態を作る。

### 5. 既定値の非対称は層ごとの意味の違いとして残す

既定を持つ層は 4 つあり、いずれも従来の値を維持する。

| 層 | 未設定・未指定のときの値 |
| --- | --- |
| デフォルト設定（`QuizDefaultSetting`、nullable） | null = ON（アプリ既定） |
| 画面の初期値・「デフォルト設定に戻す」の推奨値 | true（明示値として保存されうる） |
| `Drill` 列（`NOT NULL @default(false)`） | false（既存行の backfill 値。作成時は常に明示値が入る） |
| 生成オプション（`BuildQuizOptions`、optional） | false（従来どおりの「; 」連結） |

「未設定」の意味が層ごとに違う。ユーザーが設定していないことを表す設定側は機能としての推奨値（ON）へ倒すのが自然で、画面の初期値もそれに合わせる。一方、生成側の未指定は入力の取りこぼしであり、表示を減らす側へ倒すと問題文が黙って短くなるため OFF へ倒す。本番の呼び出し経路では必ず値が渡るが、生成関数のデフォルト引数自体は残るため、テストや将来追加する呼び出しでは未指定に到達しうる。適用先が 4 形式へ広がった分、取りこぼし時の影響範囲も広がる点は許容する。

## 採らなかった代替案

- **訳語が表示される全箇所に一律で効かせる**（決定 1） — 設定 1 つで全体を説明できるが、多義語選択の形式が変質し、解答表示まで先頭 1 つに減って復習の材料を失う。
- **多義語選択だけ別扱いの例外フラグを設ける**（決定 1） — 設定を 1 つに統合する方針に反し、成立しない組み合わせを設定で作れてしまう。
- **結果一覧だけ常に全訳語を出す**（決定 1） — 出題時と結果一覧で同じ問題の見え方が変わり、見直しの手がかりにならない。表示側に生成データと別経路の分岐を増やすことにもなる。
- **ON でも全 Meaning の先頭訳語を品詞ごとに並べる**（決定 1） — 手がかりを 1 つに絞る目的を満たさず、既存の四択（英語→日本語）の挙動とも食い違う。
- **既定を「未設定＝OFF」に変える**（決定 1） — 適用範囲が広がることに合わせて安全側へ倒せるが、既存の四択（英語→日本語）の既定挙動が黙って変わる。
- **赤字を共通設定と連動させる（ON のときだけ赤字）**（決定 2） — 設定の説明は単純になるが、ON では出題側が先頭 1 つしか出ないため、強調が最も要る OFF のときに効かない逆の挙動になる。
- **装飾記法（`==…==`）をデータに書いて表現する**（決定 2） — 実装ゼロで実現できるが、全単語のデータへ手を入れる必要があり、訳語を並べ替えると赤字の位置がずれる。
- **多義語選択の選択肢も赤字にする**（決定 2） — 選択肢のうち先頭訳語だけが赤いと正解のヒントになり、形式の難度を変えてしまう。
- **赤字を `font-bold text-red-400`（単語詳細と同じ）にする**（決定 2） — 単語詳細と揃うが、装飾記法の赤（500）と重なると後勝ちで 500 になり、「自動の赤字と記法の赤が重なっても見た目は変わらない」という前提が崩れる。単語一覧（500）とは今度こちらがずれる。
- **ダークモード対応の色トークンを新設する**（決定 2） — ダークモードでの見え方は改善するが、既存の赤 4 系統（単語一覧・単語詳細・装飾記法の赤マーク・TG 例文の意味）を巻き込むか、単語テストだけ色が違う状態を作るかの二択になる。
- **3 画面の体裁統一を今回のスコープに入れる**（決定 2） — 一貫性は上がるが、本機能と無関係な単語一覧・単語詳細の見た目が変わり、変更対象とレビュー範囲が広がる。
- **先頭の訳語が衝突する単語を出題対象から外す**（決定 3） — 一意性は上がるが、出題数が設定によって暗黙に減り、範囲指定の意味が崩れる。
- **緩和策をまったく入れない**（決定 3） — 実装は減るが、四択で「どちらも正しいのに一方だけ正解」という体験が残る。設定 ON が既定である以上、既定の体験の質に直結する。
- **既存の日本語→英語 drill 行だけ false へ backfill する**（決定 4） — 進行中の見え方は変わらないが、その drill は以後「共通設定 OFF」として振る舞い、ユーザーのデフォルト設定と食い違う。
- **4 層すべて「未指定＝ON」に揃える**（決定 5） — `Drill` 列の default 変更にマイグレーションが必要で、生成側の取りこぼしが表示の縮小として現れるようになる。揃うのは字面だけで、役割の違いは消えない。
- **生成オプションを必須フィールドにして既定を無くす**（決定 5） — 取りこぼしを型で防げるが、生成オプションは出題順の指定と同じ optional な袋で、1 項目だけ必須にすると呼び出し側（テストを含む）すべてに影響する。

## 影響

- 日本語→英語 3 形式の問題文が既定（未設定＝ON）で先頭の訳語 1 つになる。全訳語を見たいユーザーは開始フォームまたはデフォルト設定で OFF にする。
- 進行中の日本語→英語 drill も、次ラウンドから保存値に従って見え方が変わる（決定 4）。
- 自己判定（英語→日本語）の解答表示と結果一覧の正解列に、設定と無関係な赤字が常時入る。
- **設定が効く形式の集合は、生成側（生成の網羅 switch の case）と UI 側（開始フォームのトグル表示条件に使う述語）に独立して存在する**。出題形式を増やすときは両方を更新する必要があり、片方だけだと「トグルは出るのに効かない／効くのに出ない」になる（形式拡張の網羅 switch 方針は [ADR-0029](0029-format-extension-exhaustive-switch.md)）。
- 設定の DB 列名が `first_meaning_text_only` に変わり、旧コードとの後方互換は無い（マイグレーション適用から新コード配備までの間に旧コードが動くとテスト開始・drill 生成が落ちる）。個人利用規模の短時間の不整合として許容する。
- 四択（日本語→英語）で設定 ON のとき、ダミー候補が尽きて生成に失敗しうる経路が広がる（詳細と条件は [ADR-0026](0026-dummy-choices-same-occurrence-first.md)）。
- 先頭訳語の赤字の体裁が 3 画面で揃っていない状態が残る（[#269](https://github.com/ganzinn/deja-word/issues/269)）。
