# 01. 要求

状態: **確定**（2026-07-13）

## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

（依存する決定が確定したら、ここに 1 行ずつ再掲する。形式: 「- {依存する決定の要約}（{NN} 確定）。」）

ユーザー要望（初期指示、2026-07-13）:

- 苦手な英単語にブックマークを付けられる
- quiz で「掲載箇所内のブックマークのみ」を対象にテストできる（開始フォームに「ブックマークのみ」チェックボックス）
- 掲載箇所を指定せずブックマークだけ指定した場合はブックマーク全件を出題する
- 単語一覧・テスト結果一覧などの一覧画面にブックマークボタンを付け、簡単に付け外しできる（詳細画面でも可能）

## 議論・決定

### 決定 1: 用語は bookmark（日本語名「ブックマーク」）

コード名は `bookmark`（モデル名は 02 で決定）、日本語名は「ブックマーク」とし、naming-book に登録する。

- 採用理由: ユーザー要望の語をそのまま採用。既存用語と衝突せず、翻訳の揺れも生じない。
- 却下した代替案: `favorite` / `star` — 「お気に入り」は苦手マークという意味論と合わず、bookmark に対する積極的な採用理由がない。

### 決定 2: 1 ユーザー × 1 単語の ON/OFF、1 種類のみ

ブックマークは 1 ユーザー × 1 単語につき 1 個の ON/OFF で、種別・タグ・フォルダ分類・メモは持たない。

- 採用理由: 要望は「苦手単語のマーク」であり単一種別で満たせる。分類が必要になっても side table 加算方針（ADR-0008）で後から拡張できる。
- 却下した代替案: タグ・フォルダによる複数分類 — 現時点の要望になく、UI・データモデル双方が複雑化する。

### 決定 3: 共有マスタ単語にも本人のブックマークを付けられる

ブックマークの対象は自分に可視な単語すべて（本人所有＋共有マスタ ownerId=system）。ブックマーク自体は常に本人だけのデータで、他ユーザーには見えない。

- 採用理由: 教材単語（ターゲット1900 等）は system 所有であり、これを対象にできないと機能が成り立たない。純 per-user 設定（手本: OccurrencePresetSetting）として対象を scopedOwnerIds で検証するパターンが既存規約（ADR-0018/0019）に沿う。
- 却下した代替案: 本人所有単語のみ対象 — 主要ユースケース（教材単語の苦手マーク）を満たせない。

### 決定 4: 付け外し導線は「単語一覧・テスト結果一覧・単語詳細・quiz の単語詳細ダイアログ」

ブックマークトグルボタンを次の 4 箇所に置く: 単語一覧の行（WordView / OccurrenceView 両モード）、テスト結果一覧の行、単語詳細画面、テスト結果一覧から開く単語詳細ダイアログ。ボタン自体が ON/OFF 状態を表示し、一覧上でブックマーク済みかが一目でわかるようにする。

- 採用理由: 初期指示（一覧＋詳細）に加え、単語詳細ダイアログは共有部品（word-detail-view）のため追加コストが小さく、結果確認中に付け外しする自然な導線になる。一覧上の可視化はユーザー指示（2026-07-13）。
- 却下した代替案: 解答直後の正誤表示画面にも置く — 解答フローへの UI 追加が必要で、結果一覧・ダイアログで代替できるため今回は見送り（必要になれば issue 化）。

### 決定 5: 単語一覧に「ブックマークのみ」フィルタを追加（専用一覧画面は作らない）

ブックマークした単語を見る手段は、既存の単語一覧への「ブックマークのみ」フィルタ追加で提供する。

- 採用理由: 新規画面が不要で、URL searchParams ベースの既存フィルタパターンに乗る。一覧で確認・解除できないと「何をブックマークしたか」を把握できない。ユーザー指示（2026-07-13）。
- 却下した代替案: 専用のブックマーク一覧画面 — 実装量が最も大きく、単語一覧フィルタで同じ目的を果たせる。/ スコープ外（issue 化）— 付けたブックマークを確認・解除する導線が不足する。

### 決定 6: quiz は「ブックマークのみ」チェックボックスで絞り込む（要求レベル）

quiz 開始フォームに「ブックマークのみ」チェックボックスを追加する。既存の掲載箇所 Select＋掲載番号範囲 Input は残し、チェック ON で範囲内をブックマーク済み単語に絞る（AND）。掲載箇所未選択＋チェック ON の場合はブックマーク済み単語全件を出題する。仕様の詳細（入力スキーマ・範囲解決・drill / 再テスト / デフォルト設定への波及）は 03 で決める。

- 採用理由: ユーザー指示（2026-07-13）。既存の範囲指定 UI を保ったまま最小の操作で絞り込みを足せる。
- 却下した代替案: 出題スコープ切替 UI（掲載箇所 / ブックマークの排他選択）— 「掲載箇所×ブックマークの AND」ができなくなり、要望（掲載箇所内のブックマークのみ）を満たせない。

### 決定 7: スコープ外の明示

以下は今回のスコープ外とする（必要になったら GitHub issue に起票して着手判断する）:

- 誤答からの自動ブックマーク付与
- ブックマークの種別・タグ・フォルダ分類、メモ
- 解答直後の正誤表示画面での付け外し
- ブックマークの共有・エクスポート

- 採用理由: いずれも初期要望になく、コア価値（付ける・見る・quiz で絞る）に不要。スコープ肥大を防ぐ。
- 却下した代替案: なし（上記を含める案を個別検討していない）。
