## 議論・決定

### 決定 1: トグルは共有部品 BookmarkButton ＋行内用 RowBookmarkButton

`src/components/bookmark-button.tsx` に `BookmarkButton` を新設し、4 導線すべてで使い回す。一覧の行内（行全体が Link / role="button" の中）に置く場合は、`row-audio-button.tsx` と同じ方式の薄いラッパ `RowBookmarkButton` を介す: `<span className="contents">` で包み、onClick で `preventDefault()`＋`stopPropagation()`、onKeyDown では `stopPropagation()` のみ（ボタン自身の Enter/Space 発火を潰さないため preventDefault は付けない）。

採用理由: 4 箇所で同一の見た目・挙動（決定 3 の楽観的更新を含む）を保証でき、行内クリック伝播抑止も実績あるパターン（RowAudioButton）をそのまま踏襲できる。src/components/ 配置は「横断共有は src/components/、ルート専用は各ルートの \_components/」の既存規約どおり。

却下した代替案: 各画面での個別実装（4 箇所で挙動・スタイルが乖離するリスクがあり、楽観的更新のロールバック処理を重複実装することになる）。

### 決定 2: 設置箇所ごとの配置

- **単語一覧の行**（WordView / OccurrenceView 共通の WordRow）: 見出し行右端の `ml-auto` ボタン群（MY バッジ・RowAudioButton の並び）に `RowBookmarkButton` を追加する。
- **テスト結果一覧の行**（result-list.tsx）: 見出し行右端の `ml-auto` 群（削除済みバッジ・RowAudioButton の並び）に追加する。単語削除済みの行（wordId 参照先なし）には表示しない。
- **単語詳細ページ**（words/[id]）: ScreenHeader の `actions` スロットに、編集・削除ボタンの並びで `BookmarkButton` を置く。`WordDetailView` は表示専用コンポーネントのまま変更しない。
- **quiz の単語詳細ダイアログ**（word-detail-dialog.tsx）: ダイアログのヘッダ部に `BookmarkButton` を置く。出題中（InfoIcon 経由）・結果一覧の行タップ経由のどちらで開いても同じ位置に出る。

採用理由: いずれも既存のアクション設置スロット（ml-auto 群・ScreenHeader actions）に相乗りでき、新しいレイアウト要素を作らない。WordDetailView を表示専用に保つことで、詳細ページとダイアログの双方から同じ表示部品を使い続けられる。

却下した代替案: WordDetailView 本体へのボタン埋め込み（表示専用という現在の責務を崩し、設置側ごとに操作可否を出し分ける props が増える）。

### 決定 3: 反映方式は楽観的更新（冪等 set の server action とセット）

タップで即座に ON/OFF を反転表示し、server action の失敗時のみ元に戻してエラー toast を出す。成功時は toast を出さない（アイコンの反転自体が確認になる）。`router.refresh()` は呼ばない。server action は「トグル」ではなく**目標状態を受け取る冪等な set**（ON にする / OFF にする）とし、連打しても最後の意図に収束させる（シグネチャ・層配置の詳細は 05 で決める）。

派生仕様: 単語一覧の「ブックマークのみ」フィルタ（決定 5）表示中に行のブックマークを OFF にしても、その行は即座には消えない（再読込・再遷移で消える）。誤タップをその場で取り消せる挙動として意図したものとする。

採用理由: ブックマークは高頻度・低リスクのトグル操作であり、即時反映が UX 上重要。router.refresh 方式では 1 トグルごとにページ全体を server 再取得するため一覧での連打が重い。また quiz 結果一覧はクライアント状態機械（quiz-flow）由来の画面で router.refresh が効かず、どのみち局所状態更新が必要になる——楽観的更新なら 4 導線を単一実装で貫ける。

却下した代替案: 既存踏襲の useTransition＋server action＋成功 toast＋router.refresh（既存パターンとの統一性はあるが、上記のとおり一覧で重く、quiz 結果一覧には適用できず結局 2 実装に割れる）。リポジトリ初の楽観的更新パターン導入である点は認識のうえで採用。

### 決定 4: ブックマーク状態の取得経路

- **単語一覧**: `WordListItem` / `WordOccurrenceListItem`（src/lib/words-list.ts）に `bookmarked: boolean` を追加する。`wordListSelect` に閲覧ユーザー userId でスコープした Bookmark の存在確認 select を足し、`toWordListItem` で boolean に整形する（取得関数は userId を既に受けている）。
- **quiz 結果一覧**: ResultRow はクイズ実行中のクライアント状態由来で DB 一覧取得を通らないため、結果表示時に wordId 一覧を渡して状態を一括取得する server action を追加し、結果はクライアント側の状態マップ（quiz-flow / ResultList）で管理する。行のトグルはこのマップを楽観的更新する。
- **単語詳細ダイアログ**: `getWordDetailForDialog` の戻り値に `bookmarked` を並置して返す（表示専用の `WordDetail` 型には混ぜない）。ダイアログ内でのトグルは `onBookmarkChange` コールバックで親（結果一覧の状態マップ）へ同期する。出題中などマップを持たない呼び出し元ではコールバックなしでも成立する。

採用理由: 一覧は既存の select 集約点（wordListSelect / toWordListItem）への 1 フィールド追加で済む。結果一覧は表示時一括取得にすることで、クイズ中のダイアログ操作による変更も結果表示時点の最新状態から始められる。ダイアログ→親のコールバック同期により、ダイアログで外した直後の行表示が食い違わない。

却下した代替案: ①出題データ（QuizSource）にブックマーク状態を同梱（クイズ中にダイアログで付け外しすると結果表示時に古くなる）。②結果行ごとに個別取得（N 回のラウンドトリップ）。

### 決定 5: 単語一覧「ブックマークのみ」フィルタは toolbar トグル＋ URL param

単語一覧の toolbar に Bookmark アイコンのトグルボタンを追加し、URL searchParams `bookmarked=1` で表現する。OFF（デフォルト）ではパラメータを URL から削除する（既存の「デフォルト値は URL に載せない」規約に従う）。WordView / OccurrenceView 両モードで有効とし、server 側の一覧取得関数（listWordsForUser / listWordsByOccurrence）に閲覧ユーザーのブックマーク存在条件を追加する。

採用理由: 既存フィルタ（view / q / sort / match）と同じ searchParams パターンに乗るため、URL 共有・リロード耐性・server component での絞り込みがそのまま成立する。

却下した代替案: クライアント側での行フィルタ（ページネーションや件数表示と食い違う）。専用一覧画面（01 で却下済み）。

### 決定 6: 開始フォーム — 「指定なし」常時表示・未指定時は範囲 disabled・プレビュー連動

- **チェックボックス「ブックマークのみ」**を出題範囲ブロック内、番号範囲 Input の後に置く（`checked`＋`onCheckedChange` の既存 Checkbox パターン）。
- **掲載箇所 Select の先頭に「指定なし」項目を常時表示**する。「ブックマークのみ」OFF で「指定なし」のままの場合は開始不可とし、従来の未選択と同じ扱いでプレビュー欄（aria-live）に案内を表示する（idle 文言を「掲載箇所を選択してください」から、ブックマークのみ ON なら指定なしで全件テストできる旨を含む文言に更新する）。
- **掲載箇所が未指定（指定なし）の間は番号範囲 Input を disabled** にし、送信時の rangeFrom / rangeTo は未指定（undefined）として送る。入力テキスト自体は保持し、掲載箇所を選び直せばそのまま復活する。これにより「掲載箇所未選択＋範囲指定」をスキーマが拒否する組（03 確定）が UI から送信されることはない。
- **プレビュー連動**: プレビューを取得するのは「掲載箇所が指定あり、または bookmarkedOnly=true」のとき（＝開始しうる入力のとき）とし、どちらでもなければ idle 案内を表示する。`getQuizPreview` の引数と debounce 用 requestKey に `bookmarkedOnly` を追加する（300ms debounce・鮮度判定の既存方式踏襲）。除外内訳表示（ExcludedNote）は `noNumber` が null のとき（掲載箇所未選択時）その項目を省略する。対象 0 件はプレビュー 0 件表示＋開始ボタン無効の既存流儀のままとし、追加の案内表示は設けない。
- **canStart** を「(occurrenceId が指定あり または bookmarkedOnly=true) ∧ format 選択済み ∧ preview.targetCount > 0 ∧ timeout 整合」に更新する。

採用理由: 「指定なし」常時表示は、チェック状態によって選択肢が増減せず挙動が予測しやすく、チェック OFF への変更時に選択を強制リセットする必要もない。範囲 Input の disabled＋送信除外は、既存の条件レンダー / disabled パターンに沿いつつ、入力値を破壊せずスキーマ違反の組を封じる。

却下した代替案: ①「指定なし」項目をチェック ON のときだけ表示（OFF に戻したとき選択の強制リセットが必要で挙動が複雑）。②Select 横のクリアボタン（部品が 1 つ増え、未選択状態の表現が placeholder 頼みになる）。③未指定時に範囲テキストをクリア（掲載箇所を選び直したときに再入力の手間が生じる）。

### 決定 7: デフォルト設定画面にも同チェックボックスを追加、SetNull 残存は UI 側で無害化

設定画面のフォーム（quiz-defaults-form.tsx）にも「ブックマークのみ」チェックボックスを追加する（QuizDefaultSetting の `bookmarkedOnly Boolean?` は 03 で確定済み。開始画面の「デフォルトとして保存」対象に含める点も 03 のとおり）。Occurrence 削除の SetNull で「occurrenceId null＋range 残存」のデフォルト設定を読み込んだ場合は、値のクリアや保存側の修正はせず、決定 6 の「未指定時は範囲 Input disabled＋送信から除外」でそのまま無害化する（掲載箇所を選び直せば残存 range が復活し再利用できる）。

採用理由: 開始フォームと設定画面は同構成の複製という既存の関係を保つ。SetNull 残存への対処を読み込み時のデータ加工ではなく表示・送信規則に寄せることで、デフォルト設定の読み込みロジック（既存の null 落とし二重防御）に手を入れずに済む。

却下した代替案: 読み込み時に occurrenceId null なら range もクリアして返す（保存済みの値を暗黙に破壊し、掲載箇所を選び直したときに復元できない）。

### 決定 8: drill の出題条件ラベルは全件・AND 両方に「ブックマークのみ」を表記

drill 一覧の行（ActiveDrillRow、実効範囲ベース）と完了画面の元テストラベル（sourceTestLabelOf、元テストの指定範囲ベース）の両方を次のとおりにする:

- 掲載箇所なし（ブックマーク全件モード）の drill: 「ブックマークのみ」（範囲数値なし）
- 掲載箇所あり＋ sourceBookmarkedOnly=true の drill: 「{掲載箇所} No.100〜200（ブックマークのみ）」
- 完了画面ラベルの既存「（範囲指定なし）」分岐（元テストが範囲未指定）との組み合わせは「{掲載箇所}（範囲指定なし・ブックマークのみ）」のように併記する（drill 一覧の行は掲載箇所ありなら常に実効範囲の数値を持つため、この分岐は完了画面側のみ）
- ブックマーク条件なしの drill は現行表記のまま

採用理由: 条件の異なる drill（同じ掲載箇所・範囲でブックマーク有無だけ違う等）が一覧に並んだとき区別できる。表記は開始フォームのチェックボックス文言「ブックマークのみ」と揃える。

却下した代替案: 全件モードのみ表記変更し AND モードは注記なし（ラベルは短いが、同一範囲でブックマーク有無の異なる drill を見分けられない）。

### 決定 9: アイコンは lucide BookmarkIcon、ON は塗りつぶし、aria-pressed で状態提示

lucide-react の `BookmarkIcon` を使う（`Icon` サフィックス import の既存慣習に従う。リポジトリ内で Bookmark 系アイコンは未使用のため新規導入）。ON 状態は fill 塗りつぶし＋強調色、OFF 状態はアウトライン表示とし、アイコンの見た目だけで状態が判別できるようにする。アクセシビリティは `aria-pressed={bookmarked}`＋`aria-label="ブックマーク"`（AudioPlayButton の aria-pressed 慣習に整合）。

採用理由: 単一アイコンの fill 切替は ON/OFF の対応が直感的で、ボタン位置も変わらない。aria-pressed はトグルボタンの状態提示として既存部品と一貫する。

却下した代替案: ON を `BookmarkCheckIcon` 等の別アイコンに切り替える（形状が変わり、同じボタンのトグルであることが伝わりにくい）。
