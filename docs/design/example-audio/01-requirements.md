## 議論・決定

本トピックの決定は、設計セッション開始時にユーザーから事前指示として与えられた確認済み事項を記録したもの（2026-08-03）。

### 決定 1: 読み上げ対象は例文の英文（`Example.text`）のみとする

例文の和訳（`Example.meaning`）は読み上げない。

採用理由: 既存の `speakEnglish` は `en-US` 固定で、日本語の読み上げには言語の出し分け（voice 選択・端末ごとの差異）を伴う別設計が要る。例文読み上げの目的（英語の音で例文を定着させる）は英文だけで満たせる。

却下した代替案: 英文に続けて和訳も読む / 和訳用の読み上げ手段を別途用意する → 言語の出し分け設計が必要になり、issue #170 のスコープを超える。和訳の読み上げが欲しくなった時点で別トピックとして扱う。

### 決定 2: 対象は全例文種別（TARGET / PHRASE / MINIMAL / SENTENCE）

読み上げと音源登録は例文種別で絞らない。ただし画面ごとの露出は決定 5 のとおり異なる。

採用理由: `Example` は種別によって構造が変わらず（英文 `text` を必ず持つ）、種別で読み上げ可否を分ける根拠がない。どの種別も「英語の音で覚えたい」という要求は同じ。

却下した代替案: TG例文だけを対象にする → 単語テストで使うのは TG例文だけだが、単語詳細では成句・MP例文・例文も同じ英文として並ぶ。ここだけ読み上げられないのは説明のつかない差になる。

### 決定 3: 例文にも発音音源（mp3）を登録でき、未登録のときだけ TTS にフォールバックする

見出し語・関連語と同じ「音源優先・無ければ端末内蔵の自動音声」（ADR-0046）を踏襲する。

採用理由: 自動音声の品質は端末依存で、語より長い例文ほど不自然さが出やすい。同じ画面で見出し語だけ音源・例文だけ自動音声という品質差を残さない。

却下した代替案: TTS のみとし音源を持たない → 実装は軽いが、既存の音源優先方針と食い違い、後から音源を足すときにデータモデル変更が再度必要になる。

### 決定 4: 例文に発音記号は持たせない

採用理由: 発音記号は語単位の表記であり、文・句に付ける慣習がない。読み上げにも使わない（読み上げは音源 or 英文からの TTS）。

却下した代替案: `Example` に `pronunciation` を追加する → 入力コストが増えるだけで使い道がない。

### 決定 5: 対象画面は単語詳細と単語テスト（TG 形式）

- 単語詳細: 全種別の例文行から読み上げできる
- 単語テスト: TG例文のみ（TG 形式の出題素材が TG例文のため）

読み上げボタンのラベルは既存どおり「発音」。音源あり／自動音声の描き分け（ADR-0076）をそのまま効かせる。

採用理由: 例文を音で確認したい場面は「詳細を見ているとき」と「テストで例文を読むとき」に集中する。他の画面（単語一覧など）は例文の全文を出しておらず、読み上げの置き場がない。

却下した代替案: 単語一覧・編集フォームにも置く → 一覧は例文を表示しないため対象がなく、編集フォームは入力中のテキストが対象になり音源との対応が曖昧になる。

### 決定 6: 単語テストの TG 形式ではボタンを増やさず、対象を見出し語から TG例文へ差し替える

いま見出し語を鳴らしているボタンが、TG 形式では TG例文を鳴らす。

採用理由: TG 形式で問われている主体は例文であり、鳴らしたいのも例文。ボタンを増やさなければ既存のレイアウト・操作手順が変わらない。

却下した代替案: 見出し語用と例文用のボタンを併置する → 同じ「発音」ラベルのボタンが 2 つ並び、どちらが何を鳴らすか判別できない（ユーザーが明示的に却下）。

### 決定 7: 例文音源の一括取り込みは行わない

`db:import-audio` の対象は見出し語・関連語のままとし、例文用の一括取り込み経路は作らない。登録は 1 件ずつの手動アップロードのみ。

採用理由: `db:import-audio` は掲載番号（＝単語単位）でファイルと DB を突合する設計で、例文単位で突合できるソースが手元にない。

却下した代替案: 例文用の一括取り込みスクリプトを新設する → 突合キーになる音源ソースが存在しないため、作っても入力が無い。ソースが手に入った時点で改めて検討する。

### 決定 8: スコープの線引き

やること:

- 例文の英文の読み上げ（音源優先・未登録時 TTS フォールバック）
- 例文への音源の登録・削除
- TTS 読み上げ時のテキスト正規化に括弧規則を追加する（規則の詳細は [04](04-speech-normalization.md)）
- 単語詳細（全種別）と単語テスト TG 形式での UI 反映

やらないこと:

- 例文の和訳の読み上げ（決定 1）
- 例文への発音記号の追加（決定 4）
- 例文音源の一括取り込み（決定 7）
- 単語一覧・編集フォームでの読み上げ（決定 5）

採用理由: 「英文を音で確認できる」ことに絞れば、既存の音源・TTS の仕組みを保持先の追加だけで再利用でき、変更範囲がデータモデル 1 カラム＋既存経路の追随に収まる。

却下した代替案: 例文まわりの改善（和訳読み上げ・発音記号・一括登録）をまとめて 1 機能にする → 言語出し分け・ソース整備という別種の課題が混ざり、着手できる部分まで止まる。
