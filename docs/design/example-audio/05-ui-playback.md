# 05. UI・再生挙動

状態: **確定**（2026-08-04）

## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 読み上げ対象は例文の英文（`Example.text`）のみで、和訳は読み上げない（01 確定）。
- 例文にも発音音源（mp3）を登録でき、未登録のときだけ TTS にフォールバックする（01 確定）。
- 対象画面は単語詳細（全例文種別）と単語テストの TG 形式（TG例文のみ）。ボタンのラベルは既存どおり「発音」で、音源あり／自動音声の描き分け（ADR-0076）を効かせる（01 確定）。
- 単語テスト TG 形式ではボタンを増やさず、いま見出し語を鳴らしているボタンの対象を TG例文へ差し替える（01 確定）。
- 一括プリフェッチは「見出し語・関連語の音源」と「例文の音源」を分けてダウンロードできるようにし、manifest はグループ別に URL と件数を返す（02 確定）。
- Cache Storage は 1 つのまま維持し、prune の判定は両グループの和集合に対して行う（02 確定）。
- system 所有の共通例文の音源は system としてログインしたときのみ操作でき、一般ユーザーは自分が追加した例文にのみ登録できる（03 確定）。共通単語の例文はしばらく音源未登録のままになるため、TTS フォールバックが常用経路になる。
- 音源の登録 UI は単語編集フォームの例文カード内に置き、そこで鳴らせるのは登録済み mp3 の「試聴」のみで TTS フォールバックは効かせない（03 確定）。
- 読み上げ正規化の括弧規則は `toSpokenText` の 1 箇所に足し、見出し語・関連語を含む読み上げ全経路に効かせる。表示（本文の見え方）は変わらない（04 確定）。
- 表示側 `TgExampleText` の `TG_TEXT_PATTERN` に全角括弧を追加してハイライト対象を正規化と揃える（04 確定）。TG 例文の見た目に関わる唯一の変更。

## 前提（既存実装）

- `AudioPlayButton`（`src/components/audio-play-button.tsx`）の props は `{ src, label, ttsText?, reserveSpaceWhenEmpty? }`。`hasAudio = Boolean(src)`、`showTts = !hasAudio && 設定ON && ttsText あり && ブラウザ対応`。**どちらも false なら `null` を返して何も描画しない**（`reserveSpaceWhenEmpty` 指定時のみ不可視プレースホルダ）。サイズは `size="xs"` 固定で props に無い。
- 単語詳細の意味カード・関連語カードは、カード上部の**メタ行**（`metaRowClassName = "flex flex-wrap items-center gap-2 empty:hidden"`）に品詞バッジ・発音記号・発音ボタンを横並びで置く。行を出すかどうかは props で判定せず、全要素が空のときだけ `empty:hidden` で畳む契約。例文カード（`ExampleCard`）にはこのメタ行が無い。
- クイズの `promptView` は 4 種（`headword` / `ja-plain` / `tg-text` / `tg-meaning`）。TG 形式は 4 つ（`CHOICE_TG` / `SELF_JUDGE_TG` が `tg-text`、`CHOICE_TG_JA_EN` / `SELF_JUDGE_TG_JA_EN` が `tg-meaning`）。
- クイズで鳴るのは常に `QuestionBase.pronunciationAudioUrl`（= 単語の最初の Meaning の音源）と `ttsText = question.headword`。TG 形式でも同じで、例文の音源という概念は payload に無い。
- 自動再生は 2 経路。出題時 `useEffect`（`isJaToEnFormat` なら早期 return。解答漏れ防止）と、日→英系の `handleAnswerReveal`（`autoplayAnswerAudioJaEn` 設定）。プリロード（現在問＋次問）は早期 return より前で必ず走る。
- 設定画面 `audio-prefetch-section.tsx` は 1 セクションに「対象 n 件 ／ 端末に保存済み m 件」＋進捗バー＋「ダウンロード」/「中止」＋「端末から削除」（確認ダイアログ）を持つ。

## 議論・決定

### 決定 1: 単語詳細の例文カード上部にメタ行を新設し、そこに発音ボタンを置く

`ExampleCard`（`src/components/word-detail-view.tsx`）に意味カード・関連語カードと同じ `metaRowClassName` の行を追加し、`AudioPlayButton` を 1 つ置く。全例文種別（TARGET / PHRASE / MINIMAL / SENTENCE）で同じ扱いにする。

```tsx
<div className={metaRowClassName}>
  <AudioPlayButton src={example.pronunciationAudioUrl} label="発音" ttsText={example.text} />
</div>
```

- `ttsText` は例文の英文（`Example.text`）。和訳は渡さない（01 確定）。装飾記法・括弧・プレースホルダの除去は `toSpokenText` が行う（04 確定）ので、ここでは生テキストをそのまま渡す。
- ラベルは既存どおり「発音」固定。音源あり＝マイクアイコン、自動音声＝再生アイコンの描き分け（ADR-0076）は `AudioPlayButton` の内部実装なので自動的に効く。
- 見出し語・関連語のボタンは変更しない。

採用理由: 3 種のカードでボタンの位置が揃い、視線の移動先が一定になる。メタ行は `empty:hidden` 付きなので、音源も TTS も無い例文では行ごと畳まれて余白が残らない（既存の意味カードが品詞・発音記号を持たないときと同じ挙動）。例文カードだけ別位置にすると、同じ画面内で「カードの種類によってボタンを探す場所が変わる」ことになる。

却下した代替案:
- **英文の直後に置く**: どのテキストが鳴るかは最も明確だが、和訳・補足説明が下に続くためボタンがカードの中間に浮き、他 2 種のカードと位置が揃わない。
- **英文と同じ行の右端に置く**: 行数は増えないが、例文は複数行に折り返されるためボタンの垂直位置が安定せず、長い例文では英文の表示幅を削る。

### 決定 2: 音源も自動音声も使えないときはボタンごと非表示にする（プレースホルダで場所を確保しない）

例文カードでは `reserveSpaceWhenEmpty` を渡さない。`AudioPlayButton` は `null` を返し、決定 1 のメタ行は `empty:hidden` で畳まれる。

採用理由: 単語詳細の既存 2 種（意味・関連語）も `reserveSpaceWhenEmpty` を渡していない。プレースホルダで幅を確保するのは一覧・結果一覧のように**列の幅を揃える必要がある文脈**（`RowAudioButton`）だけで、縦積みのカードには当てはまらない。共通例文は当面ほとんどが音源未登録（03 確定）なので、TTS 設定を OFF にしているユーザーではプレースホルダを出すと空の行が例文の数だけ並ぶことになる。畳む挙動は実質的にも正しい。

却下した代替案:
- **disabled のボタンを出す**: `AudioPlayButton` に disabled 状態は存在せず、新設すると「押せないボタンが並ぶ」画面になる。鳴らせない理由（音源未登録／TTS OFF）をボタン上では説明できない。

### 決定 3: TG 形式では発音ボタンの鳴らす対象を TG例文に差し替える（4 箇所すべて）

TG 4 形式で、いま見出し語を鳴らしているボタンの `src` と `ttsText` を **TG例文の音源 URL と英文**に差し替える。ボタンの数・位置・ラベルは変えない（01 確定）。差し替え対象:

| 箇所 | 対象 format | 現状 | 差し替え後 |
| --- | --- | --- | --- |
| `quiz-flow.tsx` の `tg-text` 見出し下のボタン | `CHOICE_TG` / `SELF_JUDGE_TG` | 見出し語の音源 / headword | TG例文の音源 / 例文の英文 |
| `question-choice.tsx` の正解選択肢のボタン | `CHOICE_TG_JA_EN` | 同上 | 同上 |
| `revealed-headword-card.tsx` のボタン | `SELF_JUDGE_TG_JA_EN` | 同上 | 同上 |
| `result-list.tsx` の行内ボタン | TG 4 形式の行 | 同上 | 同上 |

TG 以外の形式（`headword` / `ja-plain` の promptView）は一切変更しない。

`revealed-headword-card.tsx` だけは差し替えが prop 追加を伴う。`RevealedHeadwordCard` は `question` を受け取らず `ttsText={headword}` を内部で組み立てているため、`ttsText` を prop として受け取る形にし、呼び出し元 3 本（`question-self-judge-tg-ja-en` / `question-self-judge-ja-en` / `question-spelling`）が追随する（非 TG の 2 本も同じ prop を明示的に渡すことになる）。

**TG例文の音源が未登録のときは見出し語の音源へフォールバックしない**。音源が無ければ TTS（例文の英文を読み上げ）に落ち、TTS も無効なら決定 2 と同じくボタンが消える。

採用理由: 画面に見えている英文と、耳から入る音を一致させる。差し替え対象の 4 箇所はいずれも「TG例文の英文が表示されている（または解答として現れた）状態」で、そこで見出し語が鳴るのは食い違いになる。見出し語だけ聞きたい場合は解答後の「単語詳細」から辿れる。

却下した代替案:
- **TG例文の音源が無ければ見出し語の音源にフォールバックする**: 関連語が `linkedWord.meanings[0].pronunciationAudioUrl` にフォールバックしているのは「同じ綴りの語なので発音が同じ」という根拠があるからで、例文と見出し語は別のテキストであり同じ根拠が立たない。「ボタンを押すたびに例文だったり単語だったりする」挙動になる。
- **TG 形式では発音ボタンを 2 つ（見出し語・例文）出す**: 01 でボタンを増やさないと確定済み。選択肢行・結果一覧の行内は横幅の余裕が無い。

### 決定 4: 「鳴らす対象」は payload 側で音源 URL と読み上げテキストの 1 組に決め、UI 側では形式分岐しない

`questionBaseOf` の段階で「その問題の発音ボタンが鳴らすもの」を決め、`QuestionBase` に音源 URL と読み上げテキストの組として載せる。TG 4 形式では TG例文の値、それ以外の形式では従来どおり見出し語の値を入れる。UI 側（`quiz-flow.tsx` / `question-choice.tsx` / `revealed-headword-card.tsx` / `result-list.tsx`）は `format` を見た分岐を持たず、渡された組をそのまま `AudioPlayButton` に流す。結果一覧の行データ（`ResultRow`）も、現在 `pronunciationAudioUrl` / `headword` を `question` からコピーしているのと同じ形で、この組をコピーする。フィールド名・型の詳細は 06 で決める。

採用理由: 差し替え箇所が 4 つあり、形式分岐を UI 側に置くと 4 箇所すべてで TG 判定を書くことになる。新しい出題形式や新しい表示箇所を足したときに分岐の追加を忘れると「見えている英文と違うものが鳴る」形で静かに壊れる。ADR-0078 が読み上げ正規化を `toSpokenText` の一本道に集約したのと同じ理由で、判断を 1 箇所に寄せる。

却下した代替案:
- **`QuestionBase` に例文用フィールドを追加し、UI 側で `isTgExampleFormat(format)` により選ぶ**: payload はフィールド 1 つ分小さくなるが、上記の分岐 4 箇所と将来の漏れを抱える。
- **UI 側で既存の prompt / answer / choices から読み上げテキストを取り出す**（例文テキストは payload に既にあるため重複を避ける）: 取り出し方が形式ごとに違い（`prompt` / `choices[correctIndex]` / `answer`）、結局 4 種の分岐になる。重複するのは 1 問あたり数十バイトで、TG 形式のときだけ。

### 決定 5: 自動再生・プリロードも TG例文に揃える

出題時の `useEffect` と `handleAnswerReveal`、および `preloadAudio` の対象 URL を、決定 4 の「鳴らす対象」に統一する。結果として:

- `CHOICE_TG` / `SELF_JUDGE_TG`（英→日）: 出題時に TG例文の音源が自動再生される（未登録かつ TTS ON なら例文の英文を読み上げ）。
- `CHOICE_TG_JA_EN` / `SELF_JUDGE_TG_JA_EN`（日→英）: 出題時は従来どおり無音（`isJaToEnFormat` の早期 return を維持）。解答表示の瞬間に TG例文の音源が鳴る。
- プリロード（現在問＋次問）の対象 URL も TG例文の音源になる。日→英でもプリロードは早期 return より前で走る既存構造は変えない。

採用理由: 手動ボタンと自動再生が同じものを鳴らす。同じ画面で「自動では単語・ボタンでは例文」と食い違うと、聞こえた音がどちらか分からなくなる。日→英での早期 return は「発音＝解答（英文）を漏らす」抑止であり、鳴らす対象が例文になっても目的は変わらない（例文の英文こそが解答なので、むしろ抑止の必要性は高まる）。

却下した代替案:
- **自動再生だけ見出し語のまま残す**: 単語を短く聞けるテンポの利点はあるが、手動ボタンとの食い違いを常時抱える。

### 決定 6: ダミー選択肢には音源・読み上げを持たせない

TG 四択（日→英）のダミー選択肢は他単語の TG例文テキストになるが、既存方針どおり発音ボタンは正解選択肢にのみ出す。ダミー用の音源 URL は payload に載せない。

採用理由: 既存の `showCorrectAudio`（確定後の正解選択肢のみ）をそのまま踏襲する。ダミーは「選ばせないための選択肢」であり、読み上げを提供する学習上の意味がない。全選択肢に載せると payload が選択肢数倍に膨らむ。

却下した代替案:
- **確定後は全選択肢に発音ボタンを出す**: 誤答した選択肢の英文も聞けるが、ダミーは他単語由来なので「その単語の学習」から外れる。既存の見出し語形式でも提供していない。

### 決定 7: 設定画面は 1 セクション内に 2 行を並べ、「端末から削除」は共通 1 つのまま

`audio-prefetch-section.tsx` の見出し「発音音源のダウンロード」と説明文は 1 つのまま維持し、中に 2 行を置く。

```
発音音源のダウンロード
  （説明文：Wi-Fi 推奨・容量目安）

  見出し語・関連語   対象 n 件 ／ 端末に保存済み n' 件      [ダウンロード]
  例文               対象 m 件 ／ 端末に保存済み m' 件      [ダウンロード]

  [端末から削除]（確認ダイアログ → 両グループまとめて削除）
```

- 進捗バーと「中止」ボタンは実行中の行にのみ表示し、実行中はもう一方の「ダウンロード」も無効化する（同時実行はしない）。
- 「端末から削除」は従来どおり 1 つで、Cache Storage の音源を全件削除する。
- prune（manifest から消えた URL の掃除）は両グループの和集合に対して行う（02 確定）。片方だけダウンロードしたときも、もう一方のキャッシュを消さない。

採用理由: Cache Storage は 1 つのまま（02 確定）という実体に UI を合わせる。グループを分ける目的は「例文だけ後から入れる／通信量を分けて選べる」ことであり、削除にその需要はない（容量を空けたいなら全部消せばよい）。セクションを増やさないので設定画面の縦が伸びず、説明文・容量目安の文言も 1 箇所のまま保てる。

却下した代替案:
- **セクションを 2 つに割る**: グループごとの状態は読みやすいが、説明文・進捗バー・削除ダイアログが 2 重になり、「どちらの削除を押したのか」の取り違えリスクが生まれる。
- **削除もグループ別にする**: 例文だけ容量を空ける選択肢は作れるが、削除ダイアログとグループ別 prune の実装が増える。必要になってから足せる（片方向の拡張なので後戻りしない）。
