# 01. 要求・適用範囲

状態: **確定**（2026-08-15）

## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 訳語の表示制御は形式ごとに別設定を持たせず、1 つの共通設定に統合する（ユーザー合意、設計開始時）。

## 検討事項リスト

- [x] どの形式のどの表示に効かせるか（日→英 3 形式の問題文／四択（英→日）の選択肢／多義語選択の選択肢／自己判定（英→日）の解答表示／結果一覧の各列）→ 決定 1
- [x] 「先頭の訳語」の定義（最初の Meaning の先頭 MeaningText。品詞は含めない）を全適用先で共通にしてよいか → 決定 2
- [x] OFF のときの表示（従来どおり「; 」連結）を維持するか → 決定 2
- [x] 共通設定の既定値（既存の四択（英→日）は null = ON）→ 決定 3
- [x] 解答側の先頭訳語を強調するか → 決定 4
- [x] 先頭の訳語だけでは答えが一意に定まらない問題文を許容するか → 決定 5
- [x] スコープ外（単語詳細・一覧など、訳語が出る他の画面）→ 決定 1・決定 4

## 議論・決定

### 決定 1: 共通設定「先頭の訳語のみ表示」は出題データの生成時に反映し、四択（英→日）の選択肢と日本語→英語 3 形式の問題文にだけ効かせる

適用する表示（生成時に反映する）:

- 四択（英語→日本語）の選択肢（既存の `choiceFirstMeaningTextOnly` の適用先。挙動は変えない）
- 日本語→英語 3 形式（四択 `CHOICE_JA_EN`・自己判定 `SELF_JUDGE_JA_EN`・スペル確認 `SPELLING`）の問題文（今回の追加分。現在は常に「; 」連結）

結果一覧は生成済みデータをそのまま再表示するため、上の 2 つは結果一覧の該当列（四択（英→日）の正解列と「自分の回答」列、日本語→英語 3 形式の問題文列）にも同じ内容で出る。結果一覧のためだけの分岐は設けない。

適用しない表示:

- 多義語選択（英語→日本語）の選択肢
- 自己判定（英語→日本語 `SELF_JUDGE`）の解答表示と、結果一覧のその正解列（設定を反映しない生成データから表示時に組み立てる箇所）
- TG 例文形式 4 種（`CHOICE_TG`・`CHOICE_TG_JA_EN`・`SELF_JUDGE_TG`・`SELF_JUDGE_TG_JA_EN`）。問題文・解答の素材が TG 例文の英文と意味であり、訳語（MeaningText）を表示しない
- 訳語が出る他の画面（テスト中に開ける単語詳細ダイアログ、単語詳細ページ、単語一覧）

採用理由: 設定の目的は「答えを思い出す手がかりを 1 つに絞る」こと。手がかりを出す側（問題文・選択肢）と、答え合わせで覚える材料を出す側（解答表示）は目的が逆で、後者は情報を減らさない方がよい。多義語選択は「最初の Meaning の訳語をすべて選ぶ」ことが正解条件のため、先頭の訳語だけを表示すると選ぶべき正解が常に 1 つになり、複数選択という形式の眼目が失われる。

却下した代替案:

- 訳語が表示される全箇所に一律で効かせる: 多義語選択の形式が変質し、解答表示まで先頭 1 つに減って復習の材料を失う。
- 多義語選択だけ別扱いの例外フラグを設ける: 設定を 1 つに統合する方針（前提）に反し、成立しない組み合わせを設定で作れてしまう。
- 結果一覧だけ常に全訳語を出す: 出題時と結果一覧で同じ問題の見え方が変わり、見直しの手がかりにならない。表示側に生成データと別経路の分岐を増やすことにもなる。

### 決定 2: 「先頭の訳語」の定義は既存と同じ、OFF の表示も従来どおり

ON のとき表示するのは「最初の Meaning（sortOrder 先頭）の先頭 MeaningText 1 つ」（品詞は含めない。既存 `firstMeaningHeadText` と同じ）。OFF のときは最初の Meaning の MeaningText を「; 」で連結する（既存 `firstMeaningText`）。この定義は決定 1 の適用先すべてで共通とする。

採用理由: 四択（英→日）で既に使われている定義をそのまま広げる方が、設定 1 つで挙動が一意に説明できる。2 つ目以降の Meaning（別品詞）は「別の意味」であり、先頭の訳語を絞る話とは別軸。

却下した代替案: ON でも全 Meaning の先頭訳語を並べる（品詞ごとに 1 つずつ）: 手がかりを 1 つに絞る目的を満たさず、既存の四択（英→日）の挙動とも食い違う。

### 決定 3: 既定値は ON（未設定＝先頭の訳語のみ）を維持する

デフォルト設定（`QuizDefaultSetting`）の未設定（null）は ON として扱う。既存ユーザーが明示的に保存した ON / OFF はそのまま共通設定の値として引き継ぐ（値の変換はしない）。

この決定の射程はデフォルト設定の保存値まで。進行中の drill に保存済みの値（形式に関係なく保存されており、日本語→英語の drill にも値が入っている）をどう扱うかは 02 で決める。

採用理由: 既存の四択（英→日）の既定を変えずに済み、日本語→英語の問題文も既定で短く表示される（今回の要望に沿う）。全訳語を見たい場合は開始フォームで OFF にできる。

却下した代替案: 未設定＝OFF に変える: 既存の四択（英→日）の既定挙動が黙って変わる（設定画面で OFF にした覚えのないユーザーの表示が変わる）。

### 決定 4: 自己判定（英→日）の解答側だけ、先頭の訳語をアプリが常時赤字にする

対象は自己判定（英語→日本語 `SELF_JUDGE`）の解答表示（全 Meaning を品詞ごとに並べるブロック）と、結果一覧のその形式の正解列。赤くするのは先頭 Meaning の先頭 MeaningText 1 つ（決定 2 と同じ「先頭の訳語」）。共通設定の ON / OFF に連動せず常時適用する。

対象外: 多義語選択の選択肢・正解列、四択（英→日）の選択肢と結果一覧の正解列・「自分の回答」列（決定 1 で設定により内容が変わる列であり、強調を重ねると設定の効果が読み取りにくくなる）、日本語→英語の問題文（設定 ON なら表示自体が先頭の訳語 1 つになる）、TG 例文形式（`SELF_JUDGE_TG` の解答は TG 例文の意味で、先頭の訳語という概念がない）、訳語が出る他の画面。

装飾記法（`==赤==` などのユーザー入力。ADR-0077）との重ね方は既存方針に従う: 自動の赤字をベース体裁として置き、ユーザー記法をその上に重ねて競合するプロパティは後勝ちとする（`src/components/placeholder-text.tsx` の合成順）。現行のマーク集合では赤の指定同士が重なっても見た目は変わらない（自動赤字の色を装飾記法の赤と同じにした場合。色は 03 で決めるため、別の色にするならこの記述も更新する）。

この決定は ADR-0083 の「訳語には色を付けない」と「訳語が出る全画面で同じ体裁にする」を今回の範囲（自己判定（英→日）の解答側のみ）で覆す。同 ADR の「訳語の描画は `MeaningText` に集約する」は覆さない（赤字もその描画経路に載せる）。ADR への反映は「ADR 引き継ぎ候補」で扱う。

採用理由: 自己判定（英→日）の解答表示は全 Meaning を並べるため、どれが代表的な訳語かが一目で分からない。表示を減らさずに視点を誘導できる強調が要求に合う。結果一覧の正解列も同じ形式の答え合わせなので、強調の有無が画面間でぶれないよう揃える。設定と連動させないのは、設定 OFF（全訳語表示）のときこそ強調の必要が大きいため。

却下した代替案:

- 装飾記法（`==…==`）をデータに書いて表現する: 既に可能だが、全単語のデータへ手を入れる必要があり、訳語を並べ替えると赤字の位置がずれる。
- 共通設定と連動させる（ON のときだけ赤字）: ON のとき出題側は先頭 1 つしか出ないため、強調が最も要る OFF のときに効かないという逆の挙動になる。
- 多義語選択の選択肢も赤字にする: 選択肢のうち先頭訳語だけが赤いと正解のヒントになり、形式の難度を変えてしまう。
- 訳語が出る全画面で赤字にして ADR-0083 の「全画面で同じ体裁」を保つ: 単語詳細・一覧は一覧性が目的で、代表的な訳語を指し示す必要がない。覆す範囲は今回必要な解答側に限る方が小さい。

### 決定 5: 先頭の訳語だけでは答えが一意に定まらない問題文は許容する

設定 ON では、先頭の訳語が同じ別単語が同じテストに含まれると、四択（日→英）で正解と等価に見える選択肢が並ぶ・スペル確認で別解を入力して不正解になる、といったことが起こりうる（自己判定（日→英）は自己申告採点のため採点上の影響はない）。これを設定の性質として許容し、避けたいユーザーは開始フォームで OFF にする。

採用理由: 訳語は本来 1 対 1 対応ではなく、「; 」連結の現状でも同じ訳語群を持つ単語では起こりうる（ON で頻度が上がるだけ）。設定の目的（手がかりを絞る）と両立しない完全な一意性保証は、出題対象の除外や訳語の付け替えを伴い、機能の規模に見合わない。

却下した代替案: 先頭の訳語が衝突する単語を出題対象から外す: 出題数が設定によって暗黙に減り、範囲指定の意味が崩れる。

なお、四択（日→英）のダミー選択肢については、先頭の訳語が正解と衝突する単語をダミーから外す緩和策が生成ロジックの範囲で取りうる（既存の四択（英→日）が重複排除キーを設定に連動させているのと同じ考え方）。採否は 02 で決める。

## 02 への制約

- 共通設定は出題データの生成時に問題文・選択肢へ反映する（決定 1・2）。結果一覧はその再表示なので、結果一覧向けの分岐は作らない。
- 決定 4 の赤字は生成データの内容を変えず、表示側の体裁として付ける。ただし結果一覧の正解列は現在「; 」連結済みの文字列で先頭の訳語を切り出せないため、渡し方の見直しは 02 で決める。
- デフォルト設定の既存保存値は変換せずそのまま引き継ぐ。進行中 drill に保存済みの値の扱いは 02 で決める（決定 3）。
- 四択（日→英）のダミー選択肢に対する緩和策の採否は 02 で決める（決定 5）。
