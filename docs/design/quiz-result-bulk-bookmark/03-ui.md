## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 一括ボタンは「間違えた問題だけ表示」チェック ON のときだけ提供し（チェック OFF ではボタンを出さない）、明示押下で実行する（自動登録なし）（01 確定）。
- 全モード共通（TEST / DRILL / DRILL_RETRY）で仕様・挙動を分けない（判定源が送信状態の変種で分かれる実装分岐は妨げない）（01 確定）。
- 対象単語 = チェック ON 時の表示行（`result !== "CORRECT"`）から削除済み行（判定源は送信応答: TEST / DRILL_RETRY は `skippedWordIds` = 保存されなかった wordId 群、DRILL は応答の残数一覧 `remaining` に行が無いこと）を除いたもの。既ブックマーク済みも含む（01 確定）。
- 一括操作は履歴送信の成功後（TEST / DRILL_RETRY の `success`・DRILL の `drill-success`）のみ。送信中・失敗時・対象 0 件時の見せ方は本トピックの検討事項で決める（01 確定）。
- 一括解除・Undo はスコープ外（誤操作時は既存の行トグルで個別解除）（01 確定）。
- 一括登録 action は `addBookmarks({ wordIds })`。成功時は `bookmarkedWordIds`（操作後に ON 状態の wordId 群）と `skippedWordIds`（削除済み・範囲外で弾かれた wordId 群）が返る。全件スキップ時も `ok: true`＋`bookmarkedWordIds` 空になり得る（02 確定）。
- エラーは `unauthorized | invalid | unknown`（`forbidden` なし）で日本語 message 付き。失敗は常に全体失敗（部分適用なし）で、操作は冪等のため再実行が安全（02 確定）。
- `revalidatePath` は呼ばれない（楽観的更新方針）。02 から本トピックへの制約: 対象 0 件では action を呼ばない UI にする（空配列は `invalid` に落ちる）（02 確定）。
