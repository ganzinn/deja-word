## 議論・決定

### 決定 1: 対象は単語ビューの検索のみ

単語一覧（`/words`）の単語ビューの検索を対象とする。掲載箇所ビューの検索、および登録フォーム内の関連語ピッカー（既存単語からリンク）のゼロ件時はスコープ外とする。

採用理由: ユーザー指示。「検索して無ければ登録する」の主動線は単語ビューであり、まずそこで完結させる。
却下した代替案: 掲載箇所ビュー・関連語ピッカーへの同時展開 — 空状態の実装が別箇所にあり追加コストがかかる割に主動線ではない。需要が出たら別対応として issue 化する。

### 決定 2: 発動条件は「有効な検索語あり、かつ可視範囲に検索語と完全一致する headword が無いとき」

構成要素の定義:

- **有効な検索語**: 検索キーワード正規化（ADR-0084 の `normalizeSearchKeyword`）を通した結果が空でないこと。正規化で空になる入力は、一覧が「キーワード指定なし」に倒れて全件表示になる既存挙動に合わせ、導線も出さない（従来どおりの表示）。
- **完全一致**: 正規化後キーワードと headword の等値比較（大文字小文字を区別しない）。検索の部分一致照合（キーワード側のみ正規化・大文字小文字を区別しない。ADR-0084）を等値比較に置き換えたものであり、照合規則は検索と一貫させる（01 から 03 への制約）。アクセント付き headword が正規化後キーワードと等値にならない非対称は、検索で見つからないのと同じ帰結として許容する。
- **比較対象**: 可視範囲（system＋自分の単語）の全体。ブックマーク絞り込み・ページングなど表示上の絞り込みには依存しない。

発動条件を満たすとき、検索結果の件数にかかわらず導線を表示する。部分一致のヒットがあっても表示する（例: 「から始まる」「を含む」の検索で「run」に「runner」だけがヒットした場合も「run」を登録できる）。

採用理由: ユーザー指示（ゼロ件時に限定しない）。「可視範囲に完全一致が無い」ことは「目当ての単語が未登録」とみなせる。判定を表示上の絞り込みに依存させないことで、既に存在する単語への登録導線（自分の単語なら一意制約 `@@unique([ownerId, headword])` によりエラーになる登録）を出さない。

許容する帰結:

- 完全一致の照合は大文字小文字を区別しないが、一意制約・重複警告は区別する。このズレにより、自分が「Run」を持つ状態で「run」を検索すると、「run」の登録自体は可能なのに導線は出ない。導線が出ないだけで登録経路（`/words/new` 手動）は残るため許容する。
- 発動条件は一致方法（から始まる／を含む／で終わる）に依存しない。そのため「を含む」「で終わる」でのブラウズ用途の検索（例: 「ing」で終わる語を眺める）でも、ヒット多数のまま導線が出続け、押せば「ing」のような断片語もそのまま登録できてしまう。登録には明示的な操作（導線を押してフォームを送信）が必要で、誤登録は既存の削除機能で回復できるため許容し、目立ちすぎない表示位置の工夫は 02 に委ねる。
- 完全一致判定は正規化後キーワードで行う一方、フォームへプリフィルする値は 02 で決める。trim 済み入力値を選ぶと、アクセント付き入力（例: 「thóught」）がそのまま headword として登録され、①判定に使った値と登録される headword が乖離して重複しうる（既存の一意制約・重複警告で防ぐ範囲として許容）、②アクセントなしキーワードの検索で引けない単語が生まれうる（ADR-0084 が非対称正規化の根拠とした「見出し語にアクセント記号付きは存在しない」前提を崩す新規経路になる）。②は 02 でプリフィル値を決める際の判断材料とする（正規化後キーワードを選べばどちらも生じない）。

却下した代替案:
- ゼロ件時のみ表示 — 部分一致だけがヒットするケース（「runner」あり「run」なし）で登録に進めず、要望を満たさない。
- 現在の絞り込み結果（ブックマーク絞り込み・表示中ページ）を判定対象にする — ブックマーク絞り込み中に、既存の完全一致単語が結果に現れないだけで導線が出てしまい、一意制約エラーになる登録へ誘導する。
- system 単語に完全一致があっても表示（私有コピー登録の導線を兼ねる）— system 単語との共存登録は許容仕様（ADR-0065）だが、完全一致がある時点で「見つからなかった」の前提が崩れる。私有コピーの作成は既存の `/words/new` 手動フローで足りる。

### 決定 3: スコープ外

- 検索仕様そのもの（照合規則・一致方法・並び順・ページング）は変更しない。
- 登録フォームは「検索語プリフィルと戻り先の受け口」を追加する以外、項目・入力仕様を変更しない。プリフィル値に対する重複警告の発火タイミング（初期表示時にチェックするか、既存の blur 発火のままか）は受け口の設計の一部として 02 で決める。
- 重複警告（headword-exists）の照合仕様（自分の単語のみ・大文字小文字を区別する完全一致）は変更しない。

採用理由: 要望は「見つからなかったら登録に進める導線」であり、検索・登録の既存仕様に手を入れる必要がない。スコープを導線と受け口に限定して変更面積を最小化する。
却下した代替案: 重複警告の照合を決定 2 の完全一致判定と統一する改修 — 関心が異なる既存仕様の変更でスコープ肥大になる。必要性が出たら issue 化する。
