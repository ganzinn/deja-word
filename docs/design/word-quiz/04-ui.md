## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 機能名は quiz（ルーティング・コンポーネント命名の基準）。
- 既存 UI は shadcn/ui ベース、画面は App Router（`src/app/` 配下）で構成。
- 画面フロー: テスト開始画面 → カウントダウン画面 → 出題画面（×N問） → テスト結果画面（一覧）→（任意で）定着モード drill（01 確定）。
- 開始画面で出題形式と範囲（Occurrence＋掲載番号）を指定する（01 確定）。
- カウントダウン画面は「3・2・1」の演出。その裏でテスト内容をクライアントへ全ロードし、間に合わなければカウント後もローディング表示で待機（01 確定）。
- 出題画面はテスト中サーバー通信なしで進行。ただし発音音源の取得のみ例外（01 確定・04 で例外追記）。
- 出題形式は英→日の3形式: 四択＋「わからない」（選択肢は最初の Meaning の MeaningText を「; 」連結表示） / 自己判定（タップで解答表示→「合っていた / 間違っていた / 思い浮かばなかった」の3択） / 多義語選択（MeaningText 単位・完全一致で正解、選択肢数ランダム、「わからない」あり）（01・03 確定）。
- 問題データはサーバーで全問生成し、カウントダウン中に一括取得する（03 確定）。
- 中断（ブラウザバック・リロード・離脱）は破棄。再開機構なし。drill はラウンド途中のみ破棄で、確定済みの残数は保持（01・06 確定）。
- 結果画面には自分の回答内容も表示する（四択＝選んだ選択肢、多義語選択＝選んだ意味の組、自己判定＝結果（正誤・わからなかった）のみ。直後の表示のみで履歴には残らない）（01 確定）。
- drill はラウンド制・日またぎ再開可。ラウンド結果画面で正誤・自分の回答・単語ごとの残数（「あと◯回」）を表示する（06 確定）。
- 範囲指定の対象は occurrenceNumber が付与された単語のみ（02 確定）。意味（MeaningText）未登録の単語も出題対象から除外（03 確定）。

## 議論・決定

### エントリポイント・ルーティング

- ダッシュボード（`src/app/dashboard/page.tsx`）のアクションボタン群に「単語テスト」を追加し、`/quiz` へ遷移する。MVP の導線はここのみ（単語一覧・詳細からの導線は将来拡張）。
- `/quiz` が開始画面。server component がデータ取得し、client コンポーネントに渡す（既存画面と同じパターン）。
- **カウントダウン → 出題 → 結果は `/quiz` 内のクライアント状態遷移**とし、URL 遷移しない。中断＝破棄・再開なし（01 確定）と整合し、途中状態の URL が共有・ブックマークされる余地もなくなる。
- drill のラウンド（カウントダウン → 出題 → ラウンド結果）も同じクライアントフローを mode 違いで再利用する。入口は「テスト結果画面からの開始」と「開始画面の進行中一覧からの再開」の2つ。
- **却下案**: 画面ごとにルートを分ける（`/quiz/play`、`/quiz/result` 等）。途中 URL への直アクセス・リロードがすべて「破棄して開始画面へ」になるだけでルートを分ける利点がなく、状態の受け渡しも複雑になるため却下。

### 開始画面（/quiz）

上から順に:

1. **Occurrence 選択** — shadcn Select で1つ選択。各項目に単語数を併記する。
2. **掲載番号範囲** — from / to の数値入力2つ。空欄は「制限なし」（片側のみの指定も可）。
3. **出題形式選択** — 3形式（四択 / 自己判定 / 多義語選択）のラジオ相当のトグルカード。カテゴリ見出し「英語→日本語」を付けてグループ表示する（2026-06-13 加算。将来の「日本語→英語」形式は2つ目のグループとして追加する）。
4. **制限時間** — チェックボックス「1 問ごとに制限時間を設定する」＋ON のときのみ秒数入力（1〜60 秒。ON にした初期値は 5 秒）。OFF（デフォルト）は制限なし（2026-06-13 加算）。
5. **対象件数プレビュー** — `対象 ◯語` を表示。
6. **開始ボタン** — 対象0件、選択中の形式が不成立、または制限時間 ON で秒数が未入力のときは無効。

- プレビューは Occurrence・範囲の変更時にサーバーへ問い合わせて取得する（Server Action、debounce。単語一覧の検索と同じ感覚）。
- **除外件数の注記**（02・03 引き継ぎ）: プレビューと同時に「掲載番号なしの単語 ◯語・意味未登録の単語 ◯語は対象外」を注記として表示する。対象に乗らない理由をユーザーが開始前に把握できるようにする。除外0件のときは注記自体を出さない。
- **形式の成立制御**（03 引き継ぎ）: プレビュー応答に**形式ごとの成立可否**を含め、不成立の形式（例: ダミー候補が0件で四択が組めない）は選択不可＋理由を注記する。成立判定は 03 のダミー生成ロジック（同一 Occurrence 優先→全登録単語、正解と重複する訳語は除外）に従いサーバー側で行う。プレビュー API の形は 05 で確定する。
  - 形式の選択後に範囲変更で選択中の形式が不成立になった場合は、選択を自動で解除・変更せず、不成立の注記を表示して開始ボタンを無効にする（ユーザーの選択を勝手に書き換えない）。
- 画面下部に「**進行中の定着モード**」一覧を表示する（元テストの範囲・残単語数・最終実施日と「再開」ボタン）。進行中 drill がなければセクションごと非表示。
  - 各行に**削除ボタン**を置く（確認ダイアログ付き。06 決定 7 起因の加算）。削除しても解答履歴（QuizAnswer）は残る。
  - **却下案**: ダッシュボードに進行中 drill 一覧を置く。quiz 関連の導線が分散し、ダッシュボードが quiz のデータ取得に依存するため却下。quiz の入口（開始画面）に集約する。
- **初期値はデフォルト設定から読み込む**（2026-06-13 加算）: page.tsx がユーザーのデフォルト設定（後述の /settings/quiz-defaults）を取得し、4 項目（掲載箇所・範囲・形式・制限時間）の初期値として開始フォームに渡す。
  - デフォルトの掲載箇所が選択肢にない場合（削除済み・可視範囲外）は未選択に落とす。
  - 初期の出題形式がプレビューで不成立だった場合は、自動解除しない既存方針のまま（不成立の注記＋開始ボタン無効）。デフォルト由来でもユーザー選択と同じ扱いにする。

### デフォルト設定画面（/settings/quiz-defaults。2026-06-13 加算）

開始画面の設定項目をユーザーごとのデフォルトとして保存する画面。設定メニュー（/settings）に「単語テスト」項目を追加して遷移する。データモデルは [02](02-data-model.md) の `QuizDefaultSetting`。

- 構成は開始画面と同じ 4 項目（Occurrence 選択・掲載番号範囲・出題形式トグルカード・制限時間。2026-06-13 に制限時間を加算）＋「保存」「クリア」ボタン。**すべて任意**（部分的なデフォルト可。02 の全項目 nullable と整合）。
- 出題形式は再クリックで選択解除できる（任意項目のため未設定へ戻す手段が必要。開始画面は必須選択なので解除なし）。「クリア」は保存済みデフォルトを行ごと削除して全項目未設定に戻す。
- **対象件数プレビュー・形式成立可否はこの画面には出さない**。成立可否は単語データの変化で保存後いつでも変わるため保存時点の検証に意味が薄く、開始画面のプレビューが毎回再検証して開始をゲートする。
- **UI は開始画面と共通コンポーネント化しない**（保存フォームと開始ゲートで関心が違うため複製）。形式のカテゴリ見出し・ラベル・説明の純データ（FORMAT_GROUPS）のみ共有し文言ドリフトを防ぐ。
- **却下案**: 開始画面に「現在の内容をデフォルトとして保存」ボタンを置く。保存の入口が分散し開始画面が複雑になるため、設定画面に集約する（要件確定 2026-06-13）。

### カウントダウン画面

- 全画面オーバーレイで「3・2・1」を表示。裏で**問題データを一括取得し、取得完了後ただちに第1問の音声をプリロード**する（発音音源の URL は問題データに含めるため、データ取得が先行する。03 に追記済み）。
- カウント終了時に未ロードなら「準備中…」のローディング表示で待機（01 確定どおり）。
- 取得失敗時はエラーメッセージ＋「開始画面に戻る」ボタンを表示する。リトライは開始からやり直し（中断＝破棄と同じ扱いでシンプルに保つ）。

### 出題画面（共通構成）

- 上部: プログレスバー＋「n / N」の進捗表示。
- 中央: 見出し語を大きく表示。横に発音再生ボタン（既存 `AudioPlayButton` を利用）。
- その下に形式ごとの解答 UI を出し分ける。
- **制限時間あり（payload の timeoutSeconds が非 null）のときは、解答 UI の最上部に残り時間バー＋残り秒数を表示する**（2026-06-13 加算）。問題進捗バーと同構造・別色（amber 系、残りわずかで destructive）。バーは問題ごとにリセット（key リマウント）され、回答確定（自己判定は「解答を表示」）で停止・凍結する。
  - **時間切れになったら回答した状態と同じ状態にする**: 結果は TIMEOUT として記録（間違い扱い）。四択・多義語選択は選択肢 disabled＋正解の緑表示＋「次へ」（誤答の赤表示はなし。未確定の選択は採点しない）。自己判定は自動で解答を表示し、判定 3 ボタンの代わりに「次へ」のみ。バー横に「時間切れ」を表示する。
  - タイマーは実時間の期限方式（バックグラウンドタブでも期限はずれない）。TEST / DRILL とも payload の timeoutSeconds だけを見る（出どころは [05](05-architecture.md)）。
- **解答後は即時フィードバック**を表示する: 正誤（緑/赤）＋正解内容をその場で見せ、「次へ」ボタンで次問へ進む。
  - **採用理由**: 答え合わせを最後にまとめるより1問ごとに記憶を修正できるほうが学習効果が高く、自己判定形式はもともと解答表示を挟むため3形式の体験も揃う。
  - **却下案**: 即時表示なし（解答で即次問へ、正誤は結果一覧のみ）。テンポは出るが上記理由で却下。○×のみ短時間表示する折衷案も、正解内容まで見せる価値を優先して却下。

### 出題での音声利用

- **出題画面の表示時に発音音源を自動再生する**（最初の Meaning の発音音源。未登録なら何もせず再生ボタンも非表示＝`AudioPlayButton` の既存挙動）。再生ボタンで何度でも再再生できる。
- **音声の先読み**: カウントダウン中に第1問の音声を、各問題の表示中に次問の音声をプリロードし、再生遅延を感じさせない。即時フィードバック表示中もプリロードは継続する。
- 音声取得は「テスト中はサーバー通信なし」（01 確定）の**例外**とする（01 に追記済み）。取得に失敗しても出題の進行には影響させない（自動再生をスキップし、ボタン押下時に再取得を試みる）。
- **意味音源（読み上げ）は quiz では使わない**（MVP）。自己判定の解答表示（全 Meaning）にも再生ボタンは置かない。01 に追記した通信なしの例外も発音音源に限定する。将来拡張で必要になれば例外の範囲とあわせて見直す。
- ブラウザの自動再生制限について: クイズ開始のクリックが操作起点になるため通常は再生が許可される。ブロックされた環境では自動再生せず手動ボタンにフォールバックする。
- **却下案**: MVP では音声なし（通信なし原則の厳守）／カウントダウン中に全問の音声を一括プリロード。前者は登録済み音源を活かせず、後者はロード時間・データ量が問題数に比例して膨らむため却下。先読み＋失敗時スキップで原則の意図（通信断でもテストが止まらない）は保てる。

### 形式ごとの解答 UI

- **四択**: 選択肢ボタンを縦に並べ、末尾にスタイル違いの「わからない」。タップで即確定し、正解の選択肢を緑・選んだ誤答を赤でハイライトして即時フィードバックとする。
- **自己判定**: 「解答を表示」ボタン → **全 Meaning を一覧表示**（品詞・MeaningText。単語詳細の Meaning 表示を簡略化した形。03 引き継ぎ）→「合っていた / 間違っていた / 思い浮かばなかった」の3ボタン。選択したら即「次へ」相当で進む（解答は表示済みのため追加のフィードバック画面は挟まない）。
- **多義語選択**: MeaningText 単位のトグル選択（複数選択可）＋「回答する」確定ボタン＋「わからない」。確定後、正解集合を緑・誤って選んだものを赤で表示して即時フィードバックとする。

### 中断＝破棄の具体挙動

- テスト中（カウントダウン開始〜結果の履歴送信完了前）は、**ブラウザバックをガードし、リロード・タブ閉じには beforeunload で確認**を出す。「途中の結果は破棄されます」を確認のうえ離脱したら破棄する。
- このガードは **drill のラウンド中（カウントダウン開始〜ラウンド結果の履歴送信完了前）にも同様に適用**する。ラウンド途中の離脱はそのラウンド分のみ破棄され、確定済みの残数は保持される（06 確定と整合）。
- **採用理由**: 全問解答後の誤操作で結果ごと消えるのを防ぐ。破棄自体は 01 確定のままで、確認を1枚挟むだけ。
- **却下案**: 確認なしで即破棄。ガード実装は省けるが、誤操作で全問やり直しになるコストが大きく却下。

### 結果一覧画面（テスト）

- 上部サマリ: 正解数 / 全問数（正答率）。
- 一覧: 単語ごとに「見出し語・正誤アイコン・正解（最初の Meaning の『; 』連結）・自分の回答」を表示。自分の回答は形式別（01 確定どおり）: 四択＝選んだ選択肢 / 多義語選択＝選んだ意味の組 / 自己判定＝結果（正誤・わからなかった）のみ。時間切れは時計アイコン（amber）＋「自分の回答: 時間切れ」を表示する（2026-06-13 加算）。一覧の各行に発音ボタンは置かない（シンプル優先）。
- **単語タップで、単語詳細画面（`/words/[id]`）と同等の内容をフルスクリーンダイアログで表示**する。閉じると元の結果画面に戻る。結果はクライアント状態のため、ページ遷移ではなくダイアログを重ねる方式とする。
  - 既存の単語詳細の表示部を共有コンポーネント化し、`/words/[id]` ページとこのダイアログの両方から使う。
  - **ダイアログは表示専用**とし、編集への導線は置かない（編集ページへ遷移すると結果画面のクライアント状態が失われるため）。
  - 詳細データはダイアログを開いたときに取得する（結果画面はテスト終了後なので「テスト中通信なし」とは矛盾しない）。取得 API の形は 05 で確定する。
- **履歴送信**: 結果画面の表示時に一括送信する。**失敗時は画面上部にアラート＋「再送」ボタン**を表示し、送信が成功するまで drill への導線を無効化する（drill 生成は履歴の確定が前提のため）。
- 導線: 「定着モードをはじめる」（drill 生成 → ラウンド1のカウントダウンへ）/「開始画面に戻る」。

### drill ラウンド結果画面

- テスト結果一覧と同構成（単語タップの詳細ダイアログ含む）。加えて単語ごとに**残数バッジ「あと◯回」**を表示し、残数0になった単語は「卒業」バッジを表示する（06 確定の表示要件を満たす）。
- **履歴送信もテスト結果と同じく結果画面の表示時に一括送信**する（06 確定: 履歴登録と残数更新は同一トランザクション）。**失敗時はアラート＋「再送」ボタン**を表示し、送信が成功するまで「次のラウンドへ」を無効化する（残数未更新のまま次ラウンドを生成すると不整合になるため）。
- 残数バッジ・卒業バッジは**送信成功のレスポンスに含まれる確定残数に基づいて表示**する（クライアント側の見込み計算で先出ししない）。送信失敗中は残数表示を保留する。
- 導線: 未卒業の単語が残っていれば「次のラウンドへ」（カウントダウンから再開）/「終了」（開始画面へ。確定済みの残数は保持される）。
- 全単語が卒業したら完了メッセージを表示し、「次のラウンドへ」は出さない。

### 既存画面への影響

- **MVP では既存画面（単語一覧・詳細）への解答履歴表示は見送る**。quiz による既存画面の変更はダッシュボードへのボタン追加のみ。履歴の表示（定着度など）は将来拡張とし、データは QuizAnswer に蓄積されているため後から追加できる。
