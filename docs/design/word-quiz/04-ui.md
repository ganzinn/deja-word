## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 機能名は quiz（ルーティング・コンポーネント命名の基準）。
- 既存 UI は shadcn/ui ベース、画面は App Router（`src/app/` 配下）で構成。
- 画面フロー: テスト開始画面 → カウントダウン画面 → 出題画面（×N問） → テスト結果画面（一覧）→（任意で）定着モード drill（01 確定）。
- 開始画面で出題形式と範囲（Occurrence＋掲載番号）を指定する（01 確定）。
- カウントダウン画面は「3・2・1」の演出。その裏でテスト内容をクライアントへ全ロードし、間に合わなければカウント後もローディング表示で待機（01 確定）。
- 出題画面はテスト中サーバー通信なしで進行。ただし発音音源の取得のみ例外（01 確定・04 で例外追記）。
- 出題形式は英→日の3形式: 四択＋「わからない」（選択肢は最初の Meaning の MeaningText を「; 」連結表示） / 自己判定（タップで解答表示→「合っていた / 間違っていた / 思い浮かばなかった」の3択） / 多義語選択（最初の Meaning の MeaningText 単位・完全一致で正解、選択肢数ランダム、「わからない」あり）（01・03 確定）。
- 問題データはサーバーで全問生成し、カウントダウン中に一括取得する（03 確定）。
- 中断（ブラウザバック・リロード・離脱）は破棄。再開機構なし。drill はラウンド途中のみ破棄で、確定済みの残数は保持（01・06 確定）。
- 結果画面には自分の回答内容も表示する（四択＝選んだ選択肢、多義語選択＝選んだ意味の組、自己判定＝結果（正誤・わからなかった）のみ。直後の表示のみで履歴には残らない）（01 確定）。
- drill はラウンド制・日またぎ再開可。ラウンド結果画面で正誤・自分の回答・単語ごとの残数（「あと◯回」）を表示する（06 確定）。
- 範囲指定の対象は occurrenceNumber が付与された単語のみ（02 確定）。意味（MeaningText）未登録の単語も出題対象から除外（03 確定）。

## 議論・決定

### エントリポイント・ルーティング

- ダッシュボード（`src/app/dashboard/page.tsx`）のアクションボタン群に「単語テスト」を追加し、`/quiz` へ遷移する。MVP の導線はここのみ（単語一覧・詳細からの導線は将来拡張）。
- `/quiz` が開始画面。server component がデータ取得し、client コンポーネントに渡す（既存画面と同じパターン）。
- **カウントダウン → 出題 → 結果は `/quiz` 内のクライアント状態遷移**とし、URL 遷移しない。中断＝破棄・再開なし（01 確定）と整合し、途中状態の URL が共有・ブックマークされる余地もなくなる。
- drill のラウンド（カウントダウン → 出題 → ラウンド結果）も同じクライアントフローを mode 違いで再利用する。入口は「テスト結果画面からの開始」と「開始画面の進行中一覧からの再開」の2つ。
- **却下案**: 画面ごとにルートを分ける（`/quiz/play`、`/quiz/result` 等）。途中 URL への直アクセス・リロードがすべて「破棄して開始画面へ」になるだけでルートを分ける利点がなく、状態の受け渡しも複雑になるため却下。

### 開始画面（/quiz）

上から順に:

1. **Occurrence 選択** — shadcn Select で1つ選択。各項目に単語数を併記する。
2. **掲載番号範囲** — from / to の数値入力2つ。空欄は「制限なし」（片側のみの指定も可）。
3. **出題形式選択** — shadcn Select（ドロップダウン）で1つ選択。カテゴリ見出し「英語→日本語」はリスト内の見出し（SelectGroup/SelectLabel）として含める。リスト項目はラベルのみとし、選択中の形式の説明だけトリガー直下に表示する。全形式を選択可とし、形式の成立可否は事前判定しない（2026-06-21 改訂＝05 決定 8 改訂。プレビューを件数のみに軽量化したため、不成立は開始時にカウントダウン画面でエラー表示する。改訂前は不成立の形式をグレーアウト＋理由表示していた）（2026-06-14 改訂。出題形式が今後増えても画面を縦に伸ばさずシンプルに保つためカードからドロップダウンへ変更。将来の「日本語→英語」形式は2つ目の SelectGroup として追加する）。
4. **制限時間** — チェックボックス「1 問ごとに制限時間を設定する」＋ON のときのみ秒数入力（1〜60 秒。ON にした初期値は 5 秒）。OFF（デフォルト）は制限なし（2026-06-13 加算）。**出題形式を選ぶと、その形式の保存済みデフォルト制限時間が自動入力される**（後続改訂。その場で上書き可。デフォルト未保存の形式は OFF）。
   - **「選択肢に最初の訳語だけを表示する」チェックボックス**（2026-06-24 加算。**デフォルト ON**） — **出題形式が四択（英語→日本語）のときのみ表示**。ON で選択肢を先頭の訳語のみにする（OFF＝従来どおり「; 」連結。03 参照）。初期値はデフォルト設定の `choiceFirstMeaningTextOnly`（未設定は ON）。デフォルト保存トグル ON で開始すると他の開始画面項目とともにデフォルトへ上書きされる。
5. **対象件数プレビュー** — `対象 ◯語` を表示。
6. **「この設定をデフォルト設定とする」トグル**（2026-06-20 加算） — ON で開始すると、上の掲載箇所・掲載番号範囲・出題形式・制限時間・「最初の訳語だけを表示する」をデフォルトに保存する。初期状態は設定画面のメタ設定（`QuizDefaultSetting.saveOnStart`）由来（後述）。
7. **開始ボタン** — 対象0件、制限時間 ON で秒数が未入力のときは無効（2026-06-21 改訂で「選択中の形式が不成立」は条件から除外。成立可否は開始時に判定し、不成立はカウントダウン画面でエラー表示）。

> **定着までの回数（残数設定）は開始画面では設定しない**（2026-06-26 改訂）。テストを終えてから定着モードの挙動として決める内容のため、テスト結果一覧画面（drill 直前の 1 回）へ移した（後述「結果一覧画面（テスト）」）。デフォルト値の設定は引き続き設定画面（/settings/quiz-defaults）で行う。

- プレビューは Occurrence・範囲の変更時にサーバーへ問い合わせて取得する（Server Action、debounce。単語一覧の検索と同じ感覚）。
- **除外件数の注記**（02・03 引き継ぎ）: プレビューと同時に「掲載番号なしの単語 ◯語・意味未登録の単語 ◯語は対象外」を注記として表示する。対象に乗らない理由をユーザーが開始前に把握できるようにする。除外0件のときは注記自体を出さない。
- **形式の成立制御**（03 引き継ぎ、2026-06-21 改訂＝05 決定 8 改訂）: プレビュー応答は対象件数・除外内訳のみで、形式ごとの成立可否は含めない。成立判定（03 のダミー生成ロジック＝同一 Occurrence 優先→全登録単語、正解と重複する訳語は除外）は**テスト開始時にサーバー側で行い**、不成立（例: ダミー候補が0件で四択が組めない）はカウントダウン画面でエラーメッセージ＋戻るで示す。
  - 改訂前は、プレビュー応答に形式ごとの成立可否を含め、不成立の形式を選択不可＋理由注記とし、範囲変更で選択中形式が不成立になった場合は開始ボタンを無効化していた。掲載箇所選択ごとの全コーパス読込コストを避けるため、件数のみの軽量プレビュー＋開始時検証へ移行した。
- 画面下部に「**進行中の定着モード**」一覧を表示する（元テストの範囲・出題形式・制限時間・残単語数・最終実施日と「再開」ボタン）。進行中 drill がなければセクションごと非表示。
  - **出題形式・制限時間の表示**（2026-06-20 加算）: 同じ範囲でも形式違いの drill を持ち得るため、範囲行の下に補助行として形式（`英語→日本語・四択` のように向き併記。FORMAT_GROUPS 流用）と制限時間（`制限 N 秒` / `制限なし`）を表示し、再開対象を区別できるようにする。
  - 各行に**削除ボタン**を置く（確認ダイアログ付き。06 決定 7 起因の加算）。削除しても解答履歴（QuizAnswer）は残る。
  - **却下案**: ダッシュボードに進行中 drill 一覧を置く。quiz 関連の導線が分散し、ダッシュボードが quiz のデータ取得に依存するため却下。quiz の入口（開始画面）に集約する。
- **初期値はデフォルト設定から読み込む**（2026-06-13 加算）: page.tsx がユーザーのデフォルト設定（後述の /settings/quiz-defaults）を取得し、掲載箇所・範囲・形式の初期値として開始フォームに渡す。制限時間は形式別デフォルト（`timeoutByFormat`）から導出する（後続改訂）。
  - デフォルトの掲載箇所が選択肢にない場合（削除済み・可視範囲外）は未選択に落とす。
  - 初期の出題形式がプレビューで不成立だった場合は、自動解除しない既存方針のまま（不成立の注記＋開始ボタン無効）。デフォルト由来でもユーザー選択と同じ扱いにする。
  - **制限時間は選択中の形式に追従する**（後続改訂）: 初期表示は初期形式の `timeoutByFormat` 値（形式未選択なら OFF）。形式を切り替えるたびに切替先の保存値を制限時間入力へ反映する（手編集した値より保存値を優先＝「形式を選んだらその形式の秒数が入る」を一貫させる）。
  - **未保存ユーザーには推奨デフォルトを反映する**（2026-06-22 加算）: デフォルト設定のレコードが一度も保存されていない場合（`getQuizDefaultsForUser` が `null`）、page.tsx は `DEFAULT_QUIZ_SETTINGS`（`src/lib/quiz/default-settings.ts`。format=四択・CHOICE/CHOICE_JA_EN=5 秒・SELF_JUDGE/SELF_JUDGE_JA_EN=3 秒など）を初期値として渡す。保存後に明示的に未設定へ戻した状態は非 null で返るため差し替わらない（本人の選択を尊重）。フォールバックはレコード丸ごと `null` のときだけで、フィールド単位のマージはしない。ユーザー作成時の seed は行わない。
- **開始画面の設定をデフォルトに保存できる**（2026-06-20 加算。当初却下案の見直し、下記）: 「この設定をデフォルト設定とする」トグルを ON のまま開始すると、開始画面の入力でデフォルトを**部分上書き**してからテストを開始する（`saveStartSettingsAsDefaults` を非ブロッキングで発火。失敗してもテストは進む）。上書きは開始画面にある項目のみ（occurrence / range / format ＋選択中形式の制限時間・四択先頭訳語のみ表示）で、他形式の制限時間・カウントダウン/発音/効果音・定着までの回数・メタ設定自体は温存する。
  - トグルの**初期状態**は設定画面のメタ設定 `saveOnStart` 由来。トグルを切り替えてもメタ設定には**書き戻さない**（一方向。メタ設定は初期状態を決めるだけ）。

### デフォルト設定画面（/settings/quiz-defaults。2026-06-13 加算）

開始画面の設定項目をユーザーごとのデフォルトとして保存する画面。設定メニュー（/settings）に「単語テスト」項目を追加して遷移する。データモデルは [02](02-data-model.md) の `QuizDefaultSetting` ＋ `QuizDefaultTimeout`（形式別の制限時間）。

- 構成は Occurrence 選択・掲載番号範囲・出題形式（制限時間を内包）＋四択（英→日）選択肢表示・カウントダウン表示・発音・効果音の各チェックボックス＋定着までの回数（3 値の数値入力）＋開始画面設定のデフォルト保存メタ設定チェックボックス（いずれも後述）＋「保存」「デフォルト設定に戻す」ボタン。**すべて任意**（部分的なデフォルト可。02 の全項目 nullable と整合）。
- **制限時間は出題形式カードの中で設定する**（後続改訂で統合）: 形式（四択 / 自己判定 / 多義語選択）ごとに 1 枚のカードを置き、上段はカードタップでデフォルト初期形式を選択/解除、下段にその形式の「制限時間を設定する」チェックボックス＋ON 時のみ秒数入力を持たせる。独立した「制限時間」セクションは廃止。各形式は独立に ON/OFF・秒数を持ち、OFF は制限なし（02 の「行なし＝制限なし」と整合）。形式ラベルは FORMAT_GROUPS を流用。
  - カード内のチェックボックス・数値入力は選択用ボタンの内側に置かず兄弟要素にする（ネスト不可・クリック競合の回避）。デフォルト形式選択（`format`）と各形式の制限時間（`timeoutByFormat`）は独立した state。
  - 開始画面の制限時間は単一入力（選択中形式に追従）で UI 構造が異なる。共通コンポーネント化はせず純データ（形式ラベル）のみ共有する。
- 出題形式は再クリックで選択解除できる（任意項目のため未設定へ戻す手段が必要。開始画面は必須選択なので解除なし）。
- **「デフォルト設定に戻す」ボタン**（2026-06-22 改訂。旧「クリア」を置換）: フォームの各項目を推奨デフォルト `DEFAULT_QUIZ_SETTINGS` に復元する（保存はしない。ユーザーが確認して「保存」で確定）。旧「クリア」（全項目未設定へ戻す＝行削除）から、推奨値を埋める挙動へ変更。未保存ユーザーの初回表示もこの推奨デフォルトと一致する（前掲の開始画面と同方針）。なお全項目を手動で未設定にして保存することは引き続き可能で、その状態は尊重される。
- **対象件数プレビュー・形式成立可否はこの画面には出さない**。成立可否は単語データの変化で保存後いつでも変わるため保存時点の検証に意味が薄く、開始画面のプレビューが毎回再検証して開始をゲートする。
- **UI は開始画面と共通コンポーネント化しない**（保存フォームと開始ゲートで関心が違うため複製）。形式のカテゴリ見出し・ラベル・説明の純データ（FORMAT_GROUPS）のみ共有し文言ドリフトを防ぐ。
- **開始画面の設定をデフォルトに保存するメタ設定**（2026-06-20 加算）: チェックボックス「テスト開始画面で設定した内容をデフォルト設定とする」（`QuizDefaultSetting.saveOnStart`。デフォルト OFF＝未設定時オフ）。**開始画面トグルの初期状態だけを決める**メタ設定で、上書き処理自体の挙動には影響しない。開始画面でトグルを切り替えてもこの値は変わらない（一方向）。
- **却下案の見直し**（2026-06-20）: 当初は「開始画面に保存導線を置く案」を *保存の入口が分散し開始画面が複雑になる* として却下し設定画面に集約していた（要件確定 2026-06-13）。その後、開始画面で調整した内容をそのままデフォルトにしたい要望を受け、**常設ボタンではなく、メタ設定で初期 ON を制御する明示トグル**の形で開始画面に再導入した。デフォルト編集の主たる入口は引き続き設定画面（全項目・全形式の制限時間・挙動設定）であり、開始画面トグルは「開始画面にある項目だけの部分上書き」に限定することで、入口分散による複雑化を抑える。
- **四択（英→日）選択肢表示**（2026-06-24 加算）: チェックボックス「選択肢に最初の訳語だけを表示する」（`QuizDefaultSetting.choiceFirstMeaningTextOnly`。**デフォルト ON**＝null は先頭の訳語のみ。false で「; 」連結）。四択（英→日）専用の設定で、03 のとおり選択肢生成時に効く。開始画面の「初期値」も兼ねる項目のため、こちらは開始画面（四択選択時のみ）にも同じチェックボックスを出す（発音・効果音・カウントダウンと違い、表示が生成結果に影響するため開始時に選べるようにした）。
- **カウントダウン表示**（2026-06-13 加算）: チェックボックス「テスト開始時にカウントダウン（3・2・1）を表示する」（デフォルト OFF＝未設定時は非表示）。開始フォームの「初期値」ではなくテストの「挙動設定」のため、開始画面には設定 UI を出さない（変更はこの画面のみ）。OFF 時の挙動はカウントダウン画面の項を参照。
- **定着までの回数**（2026-06-26 加算）: 「間違えた問題 / うろ覚えの問題 / 正解した問題」の開始残数を 3 つの数値入力（各 1〜9）で設定する（`QuizDefaultSetting.resetRemaining` / `vagueRemaining` / `initialCorrectRemaining`。各 null = アプリ既定 3 / 2 / 1）。テスト結果画面（drill 直前）の 3 入力の**初期値**となる項目で、空欄で保存すると null（＝既定）になる。「デフォルト設定に戻す」で 3 / 2 / 1 に復元。

### カウントダウン画面

- 全画面オーバーレイで「3・2・1」を表示。裏で**問題データを一括取得し、取得完了後ただちに第1問の音声をプリロード**する（発音音源の URL は問題データに含めるため、データ取得が先行する。03 に追記済み）。
- カウント終了時に未ロードなら「準備中…」のローディング表示で待機（01 確定どおり）。
- 取得失敗時はエラーメッセージ＋「開始画面に戻る」ボタンを表示する。リトライは開始からやり直し（中断＝破棄と同じ扱いでシンプルに保つ）。
- **カウントダウン演出は表示/非表示を切り替えられる**（2026-06-13 加算。設定はデフォルト設定画面のみ、`QuizDefaultSetting.showCountdown`。null = 非表示＝デフォルト）: 非表示時はカウントを最初から終了済みとして扱い、データ取得が完了しだい即出題へ遷移する。準備中は「準備中…」のローディング表示。エラー時の扱いは表示時と同じ。drill のラウンド開始・再開のカウントダウンにも一律適用する（演出を消したいユーザーは drill でも消えるのが自然）。

### 出題画面（共通構成）

- 上部: プログレスバー＋「n / N」の進捗表示。
- 中央: 見出し語を大きく表示。横に発音再生ボタン（既存 `AudioPlayButton` を利用）。
- その下に形式ごとの解答 UI を出し分ける。
- **制限時間あり（payload の timeoutSeconds が非 null）のときは、解答 UI の最上部に残り時間バー＋残り秒数を表示する**（2026-06-13 加算）。問題進捗バーと同構造・別色（amber 系、残りわずかで destructive）。バーは問題ごとにリセット（key リマウント）され、回答確定（自己判定は「解答を表示」）で停止・凍結する。
  - **時間切れになったら回答した状態と同じ状態にする**: 結果は TIMEOUT として記録（間違い扱い）。四択・多義語選択は選択肢 disabled＋正解の緑表示＋「次へ」（誤答の赤表示はなし。未確定の選択は採点しない）。自己判定は自動で解答を表示し、判定 3 ボタンの代わりに「次へ」のみ。バー横に「時間切れ」を表示する。
  - タイマーは実時間の期限方式（バックグラウンドタブでも期限はずれない）。TEST / DRILL とも payload の timeoutSeconds だけを見る（出どころは [05](05-architecture.md)）。
- **解答後は即時フィードバック**を表示する: 正誤（緑/赤）＋正解内容をその場で見せ、「次へ」ボタンで次問へ進む。
  - **採用理由**: 答え合わせを最後にまとめるより1問ごとに記憶を修正できるほうが学習効果が高く、自己判定形式はもともと解答表示を挟むため3形式の体験も揃う。
  - **却下案**: 即時表示なし（解答で即次問へ、正誤は結果一覧のみ）。テンポは出るが上記理由で却下。○×のみ短時間表示する折衷案も、正解内容まで見せる価値を優先して却下。
  - **自己判定の本人申告は中央 ○/× フラッシュ・効果音を出さない**（2026-06-24 加算）: 自己判定形式（英→日・日→英）で「合っていた / 間違っていた」を押した正誤（CORRECT/INCORRECT）は、解答が表示済みで本人が正誤を把握しているため演出が冗長。中央フラッシュ（`AnswerFeedbackOverlay`）と効果音（`playAnswerSound`）を抑止する。**時間切れ(TIMEOUT)は本人の判定ではないため従来どおり ×・不正解音を出す**。四択・多義語選択など他形式は従来どおり。`QuizFlow.handleReveal` が集中点で `isSelfJudgeFormat` で分岐する。

### 出題での音声利用

- **出題画面の表示時に発音音源を自動再生する**（最初の Meaning の発音音源。未登録なら何もせず再生ボタンも非表示＝`AudioPlayButton` の既存挙動）。再生ボタンで何度でも再再生できる。
- **音声の先読み**: カウントダウン中に第1問の音声を、各問題の表示中に次問の音声をプリロードし、再生遅延を感じさせない。即時フィードバック表示中もプリロードは継続する。
- 音声取得は「テスト中はサーバー通信なし」（01 確定）の**例外**とする（01 に追記済み）。取得に失敗しても出題の進行には影響させない（自動再生をスキップし、ボタン押下時に再取得を試みる）。
- **意味音源（読み上げ）は quiz では使わない**（MVP）。自己判定の解答表示（全 Meaning）にも再生ボタンは置かない。01 に追記した通信なしの例外も発音音源に限定する。将来拡張で必要になれば例外の範囲とあわせて見直す。
- ブラウザの自動再生制限について: クイズ開始のクリックが操作起点になるため通常は再生が許可される。ブロックされた環境では自動再生せず手動ボタンにフォールバックする。
- **却下案**: MVP では音声なし（通信なし原則の厳守）／カウントダウン中に全問の音声を一括プリロード。前者は登録済み音源を活かせず、後者はロード時間・データ量が問題数に比例して膨らむため却下。先読み＋失敗時スキップで原則の意図（通信断でもテストが止まらない）は保てる。

### 形式ごとの解答 UI

- **四択**: 選択肢ボタンを縦に並べ、末尾にスタイル違いの「わからない」。タップで即確定し、正解の選択肢を緑・選んだ誤答を赤でハイライトして即時フィードバックとする。
- **自己判定**: 「解答を表示」ボタン → **全 Meaning を一覧表示**（品詞・MeaningText。単語詳細の Meaning 表示を簡略化した形。03 引き継ぎ）→「合っていた / 間違っていた / 思い浮かばなかった」の3ボタン。選択したら即「次へ」相当で進む（解答は表示済みのため追加のフィードバック画面は挟まない）。本人申告の正誤は中央 ○/× フラッシュ・効果音を出さない（上記「解答後は即時フィードバック」参照）。
- **多義語選択**: MeaningText 単位のトグル選択（複数選択可）＋「回答する」確定ボタン＋「わからない」。正解集合は最初の Meaning の MeaningText（03 改訂 2026-06-20）。確定後、正解集合を緑・誤って選んだものを赤で表示して即時フィードバックとする。

### 中断＝破棄の具体挙動

- テスト中（カウントダウン開始〜結果の履歴送信完了前）は、**ブラウザバックをガードし、リロード・タブ閉じには beforeunload で確認**を出す。「途中の結果は破棄されます」を確認のうえ離脱したら破棄する。
- このガードは **drill のラウンド中（カウントダウン開始〜ラウンド結果の履歴送信完了前）にも同様に適用**する。ラウンド途中の離脱はそのラウンド分のみ破棄され、確定済みの残数は保持される（06 確定と整合）。
- **採用理由**: 全問解答後の誤操作で結果ごと消えるのを防ぐ。破棄自体は 01 確定のままで、確認を1枚挟むだけ。
- **却下案**: 確認なしで即破棄。ガード実装は省けるが、誤操作で全問やり直しになるコストが大きく却下。

### 結果一覧画面（テスト）

- 上部サマリ: 正解数 / 全問数（正答率）。
- 一覧: 単語ごとに「見出し語・正誤アイコン・正解（最初の Meaning の『; 』連結）・自分の回答」を表示。自分の回答は形式別（01 確定どおり）: 四択＝選んだ選択肢 / 多義語選択＝選んだ意味の組 / 自己判定＝結果（正誤・わからなかった）のみ。時間切れは時計アイコン（amber）＋「自分の回答: 時間切れ」を表示する（2026-06-13 加算）。一覧の各行に発音ボタンは置かない（シンプル優先）。
- **「間違えた問題だけ表示」フィルタ**（2026-06-24 加算）: 一覧上部にチェックボックスを置き、ON で `CORRECT` 以外の行（不正解・わからなかった・時間切れ）だけを一覧に表示する**表示専用フィルタ**。上部サマリ（正解数・正答率）は常に全問ベースで、フィルタの影響を受けない。初期状態は OFF（全問表示）。全問正解時に ON にすると「間違えた問題はありません。」を表示する。drill ラウンド結果画面（後述）にも同じフィルタを出す。定着対象の選別トグル「正解した問題も定着モードで出題する」（06 決定 9）とは独立で、こちらは表示にのみ作用する。
- **単語タップで、単語詳細画面（`/words/[id]`）と同等の内容をフルスクリーンダイアログで表示**する。閉じると元の結果画面に戻る。結果はクライアント状態のため、ページ遷移ではなくダイアログを重ねる方式とする。
  - 既存の単語詳細の表示部を共有コンポーネント化し、`/words/[id]` ページとこのダイアログの両方から使う。
  - **ダイアログは表示専用**とし、編集への導線は置かない（編集ページへ遷移すると結果画面のクライアント状態が失われるため）。
  - 詳細データはダイアログを開いたときに取得する（結果画面はテスト終了後なので「テスト中通信なし」とは矛盾しない）。取得 API の形は 05 で確定する。
- **定着までの回数**（2026-06-26 加算。当初は開始画面にあったが結果画面へ移設） — 「間違えた問題 / うろ覚えの問題 / 正解した問題」それぞれの開始残数を 3 つの数値入力（各 1〜9）で指定する。定着モードで各単語を何回連続正解すれば定着とするか（間違えるたびにこの回数に戻る）。**定着モードに入る直前のこの結果画面でだけ設定でき**、各テスト開始ごとにデフォルトへ戻る（永続化しない。「正解した問題も定着モードで出題する」トグルと同じ扱い）。初期値はデフォルト設定（`resetRemaining` / `vagueRemaining` / `initialCorrectRemaining`。未設定はアプリ既定 3 / 2 / 1）。`startDrill` 経由で `Drill` 行へ保存して全ラウンドに引き継ぐ（06 決定 1）。範囲外/空欄のときは「定着モードをはじめる」を無効化する。
  - **「間違えた問題 / うろ覚えの問題」の 2 値は常に表示**し、**「正解した問題」の回数は「正解した問題も定着モードで出題する」トグル ON のときだけ表示・設定可能**にする（2026-06-26 加算）。トグルの設定カード内に内包し、ON で展開する。OFF では正解語を定着モードに投入しないため回数は無関係（非表示・開始可否の判定からも除外。内部的には既定値 1 を送る）。
- **履歴送信**: 結果画面の表示時に一括送信する。**失敗時は画面上部にアラート＋「再送」ボタン**を表示し、送信が成功するまで drill への導線を無効化する（drill 生成は履歴の確定が前提のため）。
- 導線: 「定着モードをはじめる」（drill 生成 → ラウンド1のカウントダウンへ）/「同じ範囲でもう一度テストする」/「開始画面に戻る」。
- **「同じ範囲でもう一度テストする」**（2026-07-03 加算）: 同じ開始入力（掲載箇所・掲載番号範囲・出題形式・制限時間）で**新しい通常テストを開始**する（既存のテスト開始経路 `startQuiz` の再利用。履歴も TEST のまま）。厳密な「同じ問題」ではなく同じ範囲の再実行のため、テスト後に範囲内の単語が増減していれば再テストに反映される（drill retry の「同じ問題で〜」と文言を分けているのはこのため）。履歴送信の成功まで無効。開始画面トグル由来のデフォルト上書き（`saveStartSettingsAsDefaults`）は発火しない（デフォルト上書きは開始画面からの開始のみ）。

### drill ラウンド結果画面

- 残数バッジ・卒業バッジは**送信成功のレスポンスに含まれる確定残数に基づいて表示**する（クライアント側の見込み計算で先出ししない）。送信失敗中は残数表示を保留する。

- **「同じ範囲でもう一度テストする」ボタン**（2026-07-03 加算。06 決定 11）: **完了（全卒業）時のみ**、完了メッセージの直下に primary で表示する。元テストと同じ範囲（`Drill.sourceRangeFrom / sourceRangeTo`。null = 範囲指定なし）・出題形式・制限時間で**新しい通常テスト（TEST）**を開始し、定着を確認する。開始入力は `startDrillRound` 応答の `sourceTest` 由来（再開経路でも機能する）。ラウンド送信の成功まで無効。未完了のラウンド結果には出さない。**ボタン直上に「{掲載箇所名} No.{from}〜{to}・対象 {n}語」を表示**（同日加算。掲載箇所名＋範囲は進行中一覧と同表記、件数は `getQuizPreview` のライブ値。取得中は「対象件数を確認中…」、失敗時は範囲のみ）。

### 既存画面への影響

- **MVP では既存画面（単語一覧・詳細）への解答履歴表示は見送る**。quiz による既存画面の変更はダッシュボードへのボタン追加のみ。履歴の表示（定着度など）は将来拡張とし、データは QuizAnswer に蓄積されているため後から追加できる。
