# 06. 定着モード（drill）

状態: **確定**（2026-06-12。データ影響論点・ラウンド仕様は同日先行確定。2026-07-03 「同じ問題で再テスト」（drill retry）を決定 10 として加算改訂）

## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 定着モードの英語名は drill（コード上の命名の基準）。
- テスト結果画面から drill へ遷移する（01 で確定済みの導線）。
- drill は「間違えた問題を中心とした再テスト」を繰り返して定着させるモード。
- 通常テストは クライアント完結（テスト中サーバー通信なし）・終了時一括送信・中断＝破棄。
- 出題形式は英→日の3形式（四択 / 自己判定 / 多義語選択）。
- 結果画面には自分の回答内容も表示する（直後のみ、履歴には残さない）（01 確定）。

## 用語

- **ラウンド** — drill 内の1周（未卒業の単語を全て出題し、結果画面で区切る単位）。ユーザー説明上の「セッション」だが、テストセッション・ブラウザセッションとの混同を避けるためドキュメント・コードでは「ラウンド」と呼ぶ。

## 議論・決定

### 決定 1: ラウンド仕様と残数（カウントダウン）モデル（確定 2026-06-12 / 残数設定可 2026-06-26）

「N 回連続正解で卒業」を、**卒業までの残数**で管理する。残数の開始値・リセット値（誤答 / うろ覚え /
正答の 3 値）は**テスト開始時にユーザーが設定できる**（既定 誤答=3 / うろ覚え=2 / 正答=1、各 1〜9。
2026-06-26 追加）。以下の「3 / 2 / 1」は既定値であり、設定で変更される。

- 元テストで**間違えた**単語: 残数 **resetRemaining（既定 3）** から開始
- 元テストで**うろ覚え（VAGUE）**だった単語: 残数 **vagueRemaining（既定 2）** から開始（正解と不正解の中間。2026-06-26 追加）。
  **「正解も出題する」トグルに関係なく必ず投入する**（正解後にうろ覚えへ降格した＝復習したい意思表示のため）
- 元テストで**正解した**単語: 残数 **initialCorrectRemaining（既定 1）** から開始（drill 初回ラウンドにも出題され、設定回数正解すれば卒業）。
  ただし**正解組を投入するのは「正解も出題する」を ON にしたときのみ**。既定では投入しない（決定 9）
- 正解で残数 −1、**うろ覚え（VAGUE）で vagueRemaining にリセット**、**間違えたら（「わからない」・時間切れ TIMEOUT 含む）resetRemaining にリセット**（TIMEOUT は 2026-06-13 加算、VAGUE は 2026-06-26 加算）
- 残数 0 = 卒業。以降のラウンドには出題されない

**残数 3 値の永続化と引き継ぎ（2026-06-26）**: 3 値はテスト結果一覧画面（result-list。定着モードに入る
直前の 1 回だけ設定可。各テスト開始でデフォルトへ戻る）で設定し、デフォルト値は単語テスト設定
（`/settings/quiz-defaults`）で設定する。`startDrill` 経由で `Drill` 行（`resetRemaining` / `vagueRemaining` /
`initialCorrectRemaining`）に保存して**全ラウンドで引き継ぐ**（format / timeoutSeconds と同じパターン。決定 4）。
初期残数（`initialRemaining`）だけでなくラウンド遷移（`nextRemaining`）も drill ごとの保存値を使うため、
間違え直したときのリセット値も設定値に従う。設定既定は `QuizDefaultSetting`（各 null = アプリ既定）。
3 値は各独立に 1〜9 で受け付け、順序（正答 ≤ うろ覚え ≤ 誤答）は強制しない（`remaining===0` への
減算のみで卒業判定するため逆転設定でも破綻しない）。`DrillWord.remaining` の取りうる上限は 9 に拡大。

> うろ覚え（VAGUE）の入口: 自己判定は「思い浮かばなかった」（旧 GAVE_UP）を廃し「うろ覚え」ボタンへ置換。四択・多義語選択・スペル確認は**正解で答えた後**に「うろ覚えだった」降格ボタンを出す。`GAVE_UP` は四択等の回答前「わからない」用として存続する。

各ラウンドでは未卒業（残数 > 0）の単語を**全て**出題する。卒業者が増えるほどラウンドの出題数は減っていく。ラウンドの区切りごとに結果画面を表示し、正誤・自分の回答・単語ごとの残数（「あと◯回」）を確認できる。

- **却下案**: 積み上げ式カウント（連続正解数を 0→3 へ数え上げる）。元テスト正解組の開始値の説明（1回しか正解していないのに 2 から開始）が複雑になるため、残数方式を採用（ユーザー提案）。

### 決定 2: 永続化 — 日をまたいで続きから（確定 2026-06-12）

単語ごとの残数をサーバーに保存し（DrillWord）、後日続きのラウンドから再開できる。

- **drill は元テストごとに独立**して生成し、複数並存できる。同じ範囲でテストをやり直せば別の drill になる。
  - 却下案: ユーザー全体で1つの定着待ちプール — 異なる本・範囲の単語が混ざり「さっきのテストの復習」という体験から離れるため。
  - 却下案: Occurrence ごとに1プール — マージ時の残数の扱いなどエッジケースが増えるため。
- **生成タイミングは結果画面で「定着モードへ」を押したとき**。押さなければ何も残らない。
  - 却下案: テスト完了時の自動生成 — 使われないプールがたまり、生成・置き換えルールが複雑化するため。
- 全単語卒業で drill 完了（Drill.completedAt を設定）。

### 決定 3: 解答履歴と送信タイミング（確定 2026-06-12）

- drill 中の解答も解答履歴（QuizAnswer）に残し、**mode 列（TEST / DRILL）で通常テストと区別する**。単語ごとの履歴を追う際に drill の繰り返し分を見分けられるようにするため（当初「区別なし」としたが要望により変更）。Drill 行への FK 参照は持たない — Drill 行が消えても履歴の区別が失われないようにするため。
- **履歴送信は各ラウンド終了時**（結果画面表示のタイミングでそのラウンド分を一括送信し、同一トランザクションで残数を更新）。ラウンド途中の離脱はそのラウンド分のみ破棄され、確定済みの残数は保持される。
  - 却下案: drill 全体終了時の一括送信 — 途中離脱で全ラウンド分の履歴が消えるため。

スキーマの具体形は [02-data-model.md](02-data-model.md) を参照。

### 決定 4: 出題形式は元テストを引き継ぐ（確定 2026-06-12）

drill の全ラウンドを元テストと同じ出題形式で行う。

- `Drill.format`（QuizFormat、非 null）を加算する（→ 02 改訂）。format の流れ:
  - `startDrill`（drill 生成）がクライアントから format をトップレベルで 1 回だけ受け取り（zod enum 検証）、`Drill.format` に保存する。サーバーにはテストセッション状態がなく元テストの形式を導出できないため、ここだけはクライアント申告（TEST の履歴送信と同じ理由）。
  - `startDrillRound` / `submitDrillRound` から format 引数を削除する（→ 05 改訂）。ラウンドの問題生成と QuizAnswer.format の付与は、サーバーが `Drill.format` から導出する。
  - `QuizAnswer.format` は従来どおり保持する。QuizAnswer は Drill への FK を持たない（決定 3）ため、Drill が消えても履歴単独で形式が分かる状態を保つ。
- **採用理由**: drill は「さっきのテストの復習」体験であり、同じ形式の繰り返しが自然。ラウンド間に形式選択 UI が不要になりテンポを保てる。format の受け取り経路が drill 生成時の 1 回に閉じ、ラウンドごとのクライアント申告（Drill と食い違う形式で履歴が混ざる余地）も消える。
- **却下案**: ラウンドごとに選べる — 柔軟だがラウンド間に選択 UI が挟まりテンポが落ちる。
- **却下案**: デフォルト継承＋ラウンド開始時に変更可 — UI・スキーマ両方の対応が必要で MVP には重い。形式を変えて再挑戦したければ「同じ範囲で新しいテストを開始」で代替できる。
- **制限時間（timeoutSeconds）も同じパターンで引き継ぐ**（2026-06-13 加算）: `Drill.timeoutSeconds Int?`（null = 制限なし）を加算し（→ 02 改訂）、`startDrill` で元テスト開始時の設定を 1 回だけ受け取って保存、各ラウンドの payload にはサーバーが `Drill.timeoutSeconds` から載せる（→ 05 改訂）。「さっきのテストの復習」体験として同条件の繰り返しが自然であることも format と同じ。

### 決定 5: ラウンド間で出題順・選択肢は毎回変える（確定 2026-06-12）

ラウンドごとに出題順序・四択のダミー・選択肢の並びは変わる（固定しない）。

- 05 で確定済みの「各ラウンド開始時にサーバー再生成（シード永続化なし）」の自然な挙動を、そのまま仕様として確定する。追加実装なし。
- **採用理由**: 選択肢の位置やダミーの顔ぶれで覚えてしまう「位置記憶」を防ぎ、定着確認の精度が上がる。
- **却下案**: 出題順・選択肢の固定 — シード（または生成結果）の永続化が必要で 02・03 に加算が及ぶ割に、固定することの学習上の利点がない。

### 決定 6: 終了条件と導線の詳細（確定 2026-06-12）

- **ラウンド結果画面の導線**（04 確定の再掲＋完了処理の補完）:
  - 未卒業の単語が残っている場合: 「次のラウンドへ」（カウントダウン → 出題で継続）と「終了」（quiz 開始画面へ戻る）。残数はラウンド送信で確定済みのため、どの時点で終了しても損失はない。
  - 全単語卒業: 完了メッセージを表示し「次のラウンドへ」は出さない。`completedAt` は `submitDrillRound` の同一トランザクション内で、全 remaining=0 を判定したサーバーが設定する（05 決定 4 のフローに含まれる）。完了した drill は進行中一覧（completedAt IS NULL が条件）から消える。
- **再開**: quiz 開始画面の「進行中の定着モード」一覧（04 確定）の「再開」→ カウントダウン → 次ラウンド。初回・再開とも `startDrillRound` の単一経路（05 確定）。
- 元テスト全問正解でも drill は開始できる（全単語が残数 1 から始まり、1 ラウンド全問正解で完了）。導線を出し分ける特例は設けない。

### 決定 7: 進行中 drill の削除導線（確定 2026-06-12）

quiz 開始画面の進行中一覧の各行に削除ボタン（確認ダイアログ付き）を置く（→ 04 改訂）。

- `deleteDrill` Server Action（8 本目）と UseCase `drill-delete.ts`（`deleteDrillForUser`）を加算する（→ 05 改訂）。`ownerId: userId` で照合のうえ Drill を物理削除する（DrillWord は Cascade で消える）。
- QuizAnswer は Drill への FK を持たない（決定 3）ため、削除しても解答履歴は無傷で残る。
- **採用理由**: 未完了の drill を放置すると一覧に残り続けるため、完了させる以外に消す手段がないと一覧が劣化する。追加コストは Action 1 本＋確認ダイアログと小さい。
- **却下案**: MVP 見送り — 実装は最小になるが、放置 drill が溜まる UX 問題をユーザー側で解決できない。

### 決定 8: 通常テストとの共有範囲（確定 2026-06-12）

04・05 で確定済みの構成を drill 視点で総括する（整理であり、新規の変更はない）:

- **完全共有**: カウントダウン → 出題 → 即時フィードバックのクライアントフロー（`quiz-flow.tsx` の状態機械を mode 違いで再利用。04 確定）、形式別の出題 UI、単語詳細ダイアログ、離脱ガード。
- **共有＋mode 差分**: 結果画面（`result-list.tsx`）。テスト＝drill 導線＋履歴一括送信、drill＝残数・卒業バッジ＋「次のラウンドへ」/「終了」＋ラウンド送信（04 確定）。
- **drill では使わない**: 開始画面（start-form）。drill に範囲・形式の選択はなく（範囲は生成時に確定、形式は決定 4 で継承）、入口は「テスト結果画面からの開始」と「進行中一覧からの再開」の 2 つのみ（04 確定）。
- **サーバー側**: 問題生成は同一の生成ロジック（03 確定）を `quiz-generate.ts` / `drill-round-generate.ts` の両 UseCase から呼ぶ。履歴保存 handler（insertQuizAnswers）も共有し、mode はサーバーが経路で決める（05 確定）。

### 決定 9: 既定は誤答のみ・正答はオプトインで投入（確定 2026-06-24）

「正解したのに定着モードで出題される」のはレアケースという観点から、drill の既定の投入対象を
**誤答単語のみ**に改める。正解単語も投入したい場合は明示的にオプトインする。

- **テスト結果画面**（通常テスト直後の最初の結果画面のみ）に「正解した問題も定着モードで出題する」
  トグルを置く。**既定は OFF（＝誤答のみ）**。ON のとき従来どおり正答も投入する（残数 1。決定 1）。
- トグルの**初期 ON/OFF は単語テスト設定で変更可能**（`QuizDefaultSetting.drillIncludeCorrect`、`null = OFF`）。
  設定の既定は OFF。トグルはテスト開始ごとに設定既定へリセットする。
- トグルは TEST モードの結果画面だけに表示し、定着モード（DRILL）のラウンド結果画面には出さない。
- **全問正解 ＋ OFF** では投入対象が 0 件になるため、「定着モードをはじめる」を無効化し
  「全問正解のため、定着させる単語はありません。」を表示する（決定 6 の「全問正解でも開始可」は
  ON のときに限る、と読み替える）。
- 投入対象を生成時点で絞るだけのため `Drill` 列は追加しない（ラウンド継承は不要）。`createDrillForUser`
  が誤答のみへフィルタし、rangeFrom / rangeTo も投入対象から算出する。

### 決定 10: 同じ問題で再テスト（drill retry）（確定 2026-07-03）

drill の**ラウンド結果画面**（全卒業の完了画面を含む）から、直前のラウンドと同じ単語セットで
**残数に一切影響しない再テスト**を挟めるようにする。「もう一度自分を試したいが、正解して残数が
減る（＝進んでしまう）のは避けたい」練習用の導線。

- **入口**: DRILL ラウンド結果画面の「同じ問題でもう一度テストする」ボタン（ラウンド送信の成功後のみ有効）。
  TEST 結果画面には出さない。
- **出題範囲は直前のラウンドに出題された単語のみ**。そのラウンドで卒業した（remaining が 0 になった）
  単語は含み、それ以前に卒業済みでそのラウンドに出題されなかった単語は含まない。
- **wordIds はクライアント申告**: ラウンド送信後は残数が更新済みで、ラウンドのメンバーシップは
  永続化していないため、サーバーには「直前のラウンドの出題セット」を導出する手段がない。
  `startDrill` が元テスト結果をクライアントから受ける既存の信頼モデル（05 決定 2）と同型。
  サーバーは `Drill.ownerId` を照合し、wordIds を当該 drill の `DrillWord` と交差して検証する
  （改ざんしても本人の drill 内の単語で練習できるだけで実害なし）。
- **出題順・選択肢は毎回サーバー再生成**（決定 5 と同じ。シード永続化なし）。形式・制限時間・
  四択の選択肢表示は `Drill` から導出する（決定 4 と同じ）。
- **残数（DrillWord.remaining）・roundCount・completedAt には一切影響しない**。正解しても減らず、
  間違えてもリセットしない。CAS も不要（送信は TEST と同じ single-flight のみ。再送重複は MVP 許容）。
- **解答履歴は `mode = DRILL_RETRY` で残す**（→ 02 改訂）。QuizAnswer の単語別履歴で「残数に効いた
  解答」と「練習の解答」を見分けられるようにする。
- **繰り返し可能**。再テスト結果画面からも同じセットでもう一度再テストできる。
- **再テスト結果画面の導線**: 「次のラウンドへ」（drill 未完了時のみ。残数は再テストの影響を受けない）
  ／「同じ問題でもう一度テストする」／「終了」。残数バッジは表示しない（残数は不変で、送信応答にも
  含まれないため。古い値の表示は進捗と誤読されるので出さない）。
- **却下案**: ラウンドメンバーシップの永続化（列・テーブル加算） — クライアントが結果画面に
  保持している情報をサーバーに二重化するだけで、軽い機能に対しスキーマ加算が過剰。
- **却下案**: `mode = DRILL` の流用 — 残数に効いた解答と練習の解答が履歴上区別できなくなる。
- **却下案**: 再テストも残数に影響させる（正解ノーカウント・誤答のみリセット等の折衷含む） —
  「ノーリスクで試したい」という機能の目的に反し、残数モデル（決定 1）の説明も複雑になる。
