## 議論・決定

### 決定 1: 対象は 3 経路。いずれも「直前に見ていた一覧の並び・絞り込み」にナビを一致させる

1. **単語ビュー → 単語詳細ページ**: 前後ナビを新設する。一覧の並び順（`sort` = recent / headword）・検索（`q` / `match`）・ブックマーク絞り込み（`bookmarked`）を詳細へ引き継ぎ、その集合・順序の隣へ移動する
2. **掲載箇所ビュー → 単語詳細ページ**: 既存ナビのコンテキストに `bookmarked` を追加する（`occ` / `q` / `match` / `from` / `to` / `order` は引き継ぎ済みで、昇順/降順も既に一覧と一致して動作している）
3. **テスト結果一覧 → 単語詳細ダイアログ**: 結果一覧に並んでいる順（= 出題順）で前後移動する。現行の「掲載箇所全体を掲載番号昇順で辿る」挙動は廃止する

採用理由: ユーザー要望そのもの。「前へ/次へは一覧に並んでいる順」という原則を 3 経路すべてで一貫させる。

却下した代替案: 単語ビューのみ対応（当初案）— ユーザーヒアリングで掲載箇所ビューのブックマーク絞り込み欠落とテスト結果ダイアログも対象に含めると確定したため拡張した。

### 決定 2: 「間違えた問題だけ表示」で絞り込み中は、表示中の行だけを辿る

結果一覧のフィルタが ON のとき、ダイアログの前へ/次へは表示されている行（間違えた問題）だけを順に移動し、非表示の行は飛ばす。

採用理由: 見えている一覧とナビの移動先が常に一致し、「一覧に並んでいる順」の期待を裏切らない。単語一覧側の「絞り込みを保ったまま隣へ移動」と同じ思想。

却下した代替案: 常に全行を辿る — フィルタで隠した行へ移動すると、一覧に見えていない単語が突然現れて期待と食い違う。

### 決定 3: 全件ブックマークモードのテストでも前後ナビを出す

採用理由: 結果一覧順ナビは掲載箇所（`occurrenceId`）に依存しないため、全件ブックマークモードだけナビ無しにする技術的理由が消える。全モードで挙動が揃う。

却下した代替案: 現状維持（出さない）— 制約が消えた後も非対称を残すことになり、説明できない差異になる。

### 決定 4: スコープ外

- 一覧のソート機能自体の追加・変更（並び順の種類は現状のまま）
- 関連語をたどった先のダイアログ（スタック 2 件目以降）のナビ非表示の解除
- ナビ順序と無関係な既存挙動の変更（例: 掲載箇所ビュー詳細の「戻る」が 1 ページ目固定である点）

採用理由: 要望は「並び順・絞り込みへの追随」のみ。作業中に見つかった別の改善はスコープ肥大防止のため issue 化して扱う（AGENTS.md の方針）。
