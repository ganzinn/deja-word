# 04. UI・遷移・アーキテクチャ・テスト戦略

状態: **確定**（2026-08-07）

## 前提（確定事項の再掲）

このトピックが依存する決定。覆す場合はハブ（README.md）と決定元の両方を更新すること。

- 対象 3 経路: 単語ビュー由来の詳細ページに前後ナビ新設、掲載箇所コンテキストに bookmarked 追加、テスト結果ダイアログは結果一覧順ナビ（01 確定）。
- スコープ外: 一覧ソート機能の追加・変更、関連語スタック先のナビ非表示の解除（01 確定）。
- 単語ビューコンテキストは `view=word` を判別子に `sort` / `q` / `match` / `bookmarked` を詳細 URL に載せる。`occ` があれば掲載箇所コンテキストが優先、デフォルト値は省略（02 確定）。
- コンテキスト型は kind 付き union `WordDetailNavContext` に一般化し、掲載箇所コンテキストに `bookmarked` を追加する（02 確定）。
- 単語ビュー用隣接クエリ `findAdjacentWordsInWordView` を新設する。戻り値は prev / next の id のみで掲載番号を含めず、単語ビューコンテキストでは詳細画面に掲載番号を表示しない（02 確定）。
- current が絞り込み集合から外れたら前後ナビ非表示（既存踏襲）（02 確定）。
- 戻り・編集リンクはコンテキストから再構築し、`page` は持ち回らない（02 確定）。
- ダイアログの前後ナビ順序は「開いた時点の表示行」のクライアントスナップショット（wordId 配列）。`onOpenDialog` の引数で渡し、quiz-flow が `dialogNavOrder` として保持、スタック深さ 1 のときのみダイアログへ渡す（03 確定）。
- ダイアログのナビ表示条件は `navOrder` 非 null のみで `occurrenceId` に依存しない（全件ブックマークモードでもナビを出す）。隣接が同期的に決まるため、応答待ちのナビ状態（両ボタン disabled・初回はナビ行非描画）は廃止（03 確定）。
- `getAdjacentWordsForDialog` / `findAdjacentWordsByOccurrenceNumber` と隣接応答系 state（`navResponse` / `navCache` / `resolveNavView` / `resolveCurrentNav`）は廃止・置き換え（03 確定）。
- ダイアログの `#N` は詳細応答の掲載箇所一覧から導出する（全件ブックマークモードは `#N` なし・ナビあり）（03 確定）。
- 削除済み単語の行はナビからスキップせず、エラービューでもナビ継続可能（03 確定）。
- ダイアログの先読みは `navOrder` 前後 1 件の詳細のみ（隣接先読みは廃止）。ADR-0086 該当記述の改訂は本トピックのドキュメント更新論点で扱う（03 確定）。

## 議論・決定

### 決定 1: ページ側の前後ナビは既存コンポーネントを流用する（新規 UI なし）

単語ビュー由来の詳細ページの前後ナビは、既存の `WordNavArea`（遷移ロジック）＋ `AdjacentWordNav`（ナビ行の見た目・スワイプ）＋ `WordContentTransition`（淡色化＋方向スライド）をそのまま使う。

- いずれも href ベースで掲載箇所に依存しないため、02 の union 対応済み `buildWordDetailHref(id, ctx)` で組んだ 3 つの href（current / prev / next）を渡すだけでよい
- `words/[id]/page.tsx` は `ctx.kind` で隣接クエリ（`findAdjacentWordsByOccurrence` / `findAdjacentWordsInWordView`）を出し分け、ナビ表示条件を「ctx 非 null かつ隣接結果非 null」に一般化する。`#N` は掲載箇所コンテキストのときのみ `WordDetailView` へ渡す（単語ビューでは null。ADR-0087 の「単語ビューから開いた詳細には出ない」記述と整合）
- `<Link prefetch={true}>` による前後 1 件の先読み、淡色化＋スライド、横フリックは既存機構がそのまま効く（ADR-0085 / 0086 / 0087 の挙動を追加実装なしで満たす）

採用理由: 見た目・操作を既存の掲載箇所ナビと完全に揃えるという要求に対し、同一コンポーネントの流用が最短かつ乖離の余地がない。
却下した代替案: 単語ビュー用に別コンポーネントを作る（同一見た目の重複実装になり、片方だけ直す事故の温床）。

### 決定 2: ダイアログのナビ行は `AdjacentWordNav` と共通化しない（直書きを維持）

`word-detail-dialog.tsx` のナビ行は、現状どおり `AdjacentWordNav` を import せず同じ見た目（同一クラス構成の `<nav>` + `buttonVariants` 相当）を直書きのまま維持する。03 の変更（navOrder ベースの同期導出）もこの直書き部分の書き換えとして行う。

採用理由: ページは `<Link href>` ＋ `router.push`（サーバナビ・prefetch は Link 経由）、ダイアログは `<Button onClick>` ＋クライアント state 置換（prefetch は Server Action キャッシュ）で、遷移の性質・無効条件・先読み経路がすべて異なる。見た目が似ていても変更理由が別であり、共通化は凝集度を下げる（ファイル分割・共通化は行数でなく変更理由で判断する方針）。見た目の一致はクラス共有で担保されている。
却下した代替案: `AdjacentWordNav` に href モードと onClick モードの両対応を持たせる（props とレンダリングが分岐だらけになり、どちらの変更でも両方のテスト確認が要る密結合になる）。

### 決定 3: 遷移フィードバック・先読みは既存 ADR の枠内とし、ADR-0086 の隣接先読み記述を改訂する

- ページ側（単語ビュー由来）: 決定 1 のとおり既存機構で ADR-0085 / 0086 / 0087 の挙動が成立する。追加の決定はない
- ダイアログ側: 03 決定 6（先読みは navOrder 前後 1 件の詳細のみ）により、ADR-0086 の決定 3 のうち「ダイアログは詳細＋隣接ナビの Server Action を前後 1 件先読み」の隣接ナビ部分が実態と合わなくなる。決定 6 で起票する ADR（結果ダイアログのクライアント配列ナビ化）に置き換えを明記し、ADR-0086 本文には置き換え先 ADR への改訂注記を 1 行追記する
- 遷移中フィードバック（前の単語を残して淡色化 → 到着時スライド）・`prefers-reduced-motion` 対応・連続送りの追い越し許容は、両経路とも ADR-0086 のまま変更しない

採用理由: 変わるのは「隣接情報の入手経路」だけで、体感仕様（フィードバック・先読みの目的と範囲）は既存 ADR のままだから。ADR の改訂は新 ADR からの置き換え明記＋旧本文への注記という最小手当てにする。
却下した代替案: ADR-0086 本文を直接書き換える（決定の履歴が追えなくなる。0085 → 0086 が追補で積まれている家風とも合わない）。

### 決定 4: テスト戦略

- **`search-params.unit.test.ts`**: `parseOccurrenceContext` / `buildWordDetailHref` / `buildWordEditHref` の describe を union 対応で書き換える。必須ケース: 判別順（`occ` 優先 → `view=word` → null）、単語ビューコンテキストのパース（`sort` / `bookmarked` の正規化、デフォルト値の扱い）、href 生成のデフォルト省略（`view=word` は常時付与・`sort=recent` 等は省略）、掲載箇所コンテキストの `bookmarked` パースと省略。既存の occ 系ケースは新パーサのケースとして引き継ぐ
- **`words-list.integration.test.ts`**: `findAdjacentWordsInWordView` の describe を新設する。必須ケース: recent 順の prev/next と端、**`createdAt` 同値時の id tiebreak**（同値データを明示的に作る）、headword 順、`q` / `match` 絞り込み、`bookmarkedOnly`、集合外 current は null、scope（own + system 混在・他ユーザー除外）。`findAdjacentWordsByOccurrence` には `bookmarkedOnly` のケースを追加する。`findAdjacentWordsByOccurrenceNumber` の describe は削除する
- **`word-detail-dialog-state.unit.test.ts`**: 隣接応答系（`resolveCurrentNav` / `resolveNavView`）のテストを、navOrder ベースの同期導出関数のテストに置き換える。必須ケース: 現在 wordId の index 解決と端の disabled、navOrder null（出題中・関連語スタック先）で非表示、`#N` の詳細応答からの導出（`dialogOccurrenceId` null・一致なし・番号なしは非表示）。`resolvePrefetchTargets` は「詳細のみ・navOrder 前後 1 件・表示中詳細 settle 後」の仕様で書き直す
- **`quiz-flow.tsx` / `result-list.tsx`**: 従来どおり `.tsx` はテスト対象外の方針を維持する（include は `.ts` のみ）。順序スナップショットの構築は `visibleRows.map(...)` の自明な導出であり、専用の抽出・テストは行わない
- **E2E**: 実装チケットの完了条件として e2e-verify スキルで 3 経路（単語ビュー由来ページナビ・掲載箇所 bookmarked 込みナビ・結果ダイアログの表示行順ナビ）を動作確認する

採用理由: 既存テストの配置・粒度（パーサ = unit、隣接クエリ = integration、ダイアログ state = 純関数 unit）をそのまま踏襲し、新規はタプル比較の境界（同値 tiebreak）と判別順という壊れやすい点に集中させる。
却下した代替案: quiz-flow の順序受け渡しを純関数抽出してまで unit テストする（自明な map で、抽出コストに見合う検証内容がない）。

### 決定 5: `docs/features/` は 2 ファイルを改訂し、スクリーンショットは再撮影・追加しない

- **`word-management.md`**（現 L94-100 の段落）: 「掲載箇所ビューから開いた詳細では」を主語にした段落を再構成する。前後ナビ（並び・絞り込みを保った移動、フリック、淡色化＋スライド、先読み）は単語ビュー・掲載箇所ビューの両由来で使える説明にし、見出し語右の掲載番号 `#N` は掲載箇所ビュー由来のみと明記する。ブックマーク絞り込みも保たれることに触れる
- **`word-quiz.md`**（現 L58-62）: 「掲載箇所から出題したテストでは…掲載番号順に隣の単語」を改訂する。前後移動は結果一覧の並び順（「間違えた問題だけ表示」中はその表示順）で、全件ブックマークモードのテストでも使えること、`#N` は掲載箇所から出題した場合のみ付くことを書く
- **スクリーンショット**: 再撮影・新規追加なし。既存の `word-detail.png` は掲載箇所コンテキスト無しで撮影されており前後ナビが写っておらず（ADR-0087 で確認済み）、`quiz-result.png` もダイアログを開いていない。ナビ行の見た目自体は変わらないため、新たに写すべき画面差分がない

採用理由: ユーザー向け挙動の変更点（ナビの適用範囲・順序の意味）は本文で正確に伝わり、画像に写る差分が存在しない。
却下した代替案: ダイアログを開いた状態のスクリーンショットを新規追加する（撮影セクションの新設が必要になる割に、見た目は既存ナビと同一で情報量が増えない。必要になったら別途 issue 化する）。

### 決定 6: ADR を 2 本起票し、naming-book に用語を追加する

- **ADR ①「単語詳細の前後ナビを一覧コンテキストに追随させる（`view=word` URL コンテキスト）」**: 02 の決定（`view=word` 判別子、kind 付き union、`bookmarked` 補完、単語ビュー隣接クエリ、集合外時の非表示、`page` 非持ち回り）を採用理由・却下案ごと転記する
- **ADR ②「テスト結果ダイアログの前後ナビを結果一覧順のクライアント配列に変更する」**: 03 の決定（順序ソース = 表示行スナップショット、隣接 action・`findAdjacentWordsByOccurrenceNumber` 廃止、削除行スキップなし、先読みは詳細のみ）を転記し、ADR-0086 決定 3 の隣接先読み部分を置き換えることを明記する（→ 決定 3）
- 番号は起票時点の最新 + 1 を採る（現時点の最新は 0087 のため 0088・0089 見込み）。起票タイミングは各実装 PR と同時
- **naming-book**: §1-9（横断・アーキテクチャ語）に「前後ナビ」（英語名: `AdjacentWordNav` / adjacent word nav。詳細ページとテスト結果ダイアログの 2 箇所、順序はコンテキスト由来）と「単語ビュー / 掲載箇所ビュー」（英語名: `view=word` / `view=occurrence`。一覧の 2 表示モードで、詳細 URL のコンテキスト判別子にも使う）のエントリを追加する

採用理由: 設計ドキュメント（`docs/design/`）は実装完了後に削除していく運用のため、長期に参照される決定は ADR へ残す必要がある。経路ごとに決定の性質（URL 設計 vs クライアント state 設計）が異なり、既存 ADR の細粒度（0085〜0087 が各 1 論点）とも揃うため 2 本に分ける。naming-book は「前後ナビ」の見出しエントリが現状無く、本機能で語彙が確定するため追加する。
却下した代替案: ADR を 1 本に統合する（2 経路の決定が混ざり、片方だけ覆すときの参照性が悪い。既存 ADR の粒度とも不揃い）。ADR を起票せず設計ドキュメントを残す（design docs は削除運用のため長期記録の受け皿にならない）。
